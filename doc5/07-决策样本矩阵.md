# 07｜可执行的正反例与版本验收矩阵

本页是目标判定表，不是已执行结果。所有自动提取样本都先构造同 scope、同窗口的 user/user L0 事件；另加跨 scope 与 assistant/tool 伪来源负例。`quote` 均为用户事件连续原文；特别标明的例外除外。新作业版本为 `extract_v3/admit_v2`。`active` 只表示 Rust 准入目标，后续搜索是否命中另看召回探针。

## C. 版本、召回与账目

- schema 3 副本升级 schema 4：旧 job 的 `prompt_version` 与所有旧列不变，`admission_version=admit_v1`；新 job 为 `extract_v3/admit_v2`。用同一个 A01 候选分别执行历史 v1 与新 v2 分派，观察 v1 保持旧判定、v2 active；未知 admission version 立即 dead，不调用模型。
- “以后回答请用中文”与 A08 同时 active：无关查询只应注入指令；相关“VSCode 暗色主题”应含偏好；“护眼颜色”零词法时可记录未命中，不能把可能相同的答案记为记忆生效。
- 同一用户 Agent A 写入、Agent B 查询可见；另一用户的相同文本不得被 A/B 看到。correct 后旧 superseded 普通查询不见，forget 后同一旧证据重试不得复活。模型输入、候选行、memory_evidence 的 ID/span 应能追到原始 user L0。
