# 04｜`memory_remember` 的保存意图边界

> **【用户产品决定，2026-09-25 深夜——本文 §1–§4 的内容条件护栏已全部解除】**
> 「直写内容护栏全部解除，这是我规定的；后续如果有需要我再统一写护栏进行防范。」
> 自本决定起：`memory_remember` 不再做内容类别判定（SECRET/SENSITIVE/THIRD_PARTY/TEMPORAL 四类门）、
> 不再要求相邻保存指令、不再限制单命题（doc5/09 决策 B 一并撤销）；Agent 可主动写入任何内容。
> 保留的仅是协议级校验：scope、最新用户证据、quote 逐字 span、幂等去重、审计与遗忘抑制。
> 实施记录见 `../doc-handoff/12-直写护栏解除.md`（commit 见该文档）。本文以下内容保留为历史规则描述。

## 1. 源码事实与问题

`memory-store-sqlite/src/memories.rs::remember` 目前验证 token scope、同 host/session 最新 user/user 证据、quote 连续 span，随后建 active；DSH 的 `memory_remember` 可以由 Agent 自主调用。这个调用只证明“Agent 请求写入某条用户原文”，**不能单独证明用户要求保存**。日常观察中用户只说“我喜欢用暗色主题写代码”，模型就主动调用了工具。doc5 对自动提取设 held 时，必须同步检查这条直写路径，否则健康、第三人和时间事实仍可能绕过自动准入。

## 2. 两类直写

- 普通稳定自述、偏好和长期指令：保留既有 latest user evidence + quote + scope 约束；不因 doc5 引入额外确认步骤。保留 remember 的既有幂等、审计和忘记抑制。
- 命中 `SECRET` 的密码、token、API key 等凭据：即使用户说“请记住”也不得 active，返回 409 `STATE_CONFLICT`；不回显凭据值。该分类优先于保存指令检查。
- 命中 `TEMPORAL` 的未来/短期状态：即使有保存指令，本版也不能成为无期限 active，因为当前 `remember` 将 `valid_until` 写 NULL。返回 409 `STATE_CONFLICT`，提示该类时间内容尚不支持永久保存；不要静默转成长期记忆。以后若做期限或事件生命周期，单独修协议和审计。此项是**独立否决条件**，不能因同一 quote 还属于第三人信息而被允许。
- 命中 `admit_v2` 的 `SENSITIVE`（不含凭据）或 `THIRD_PARTY` 内容：只有同一条**最新**用户消息中的保存指令与目标 quote 直接相邻，才允许 `memory_remember` active。接受的窄形式为消息去首尾空白后以“请记住”“记住”“请帮我记住”或 `Remember` 开始，允许其后一个 `:`/`：` 与空白，随后内容必须恰为待保存 quote（可带句末标点）。例如“请记住：我对花生过敏” + quote“我对花生过敏”可保存；“请记住我喜欢蓝色。另外我对花生过敏” + quote“我对花生过敏”不可保存。大小写折叠只用于英文指令；保存的 quote 不改写。

这三类判断必须对 quote 内容独立执行，不信任工具传入的 `kind`；例如把过敏内容填成 `instruction` 仍需直接保存指令，把密码填成 `preference` 仍要拒绝。若一条 quote 同时命中多个类别，`SECRET` 和 `TEMPORAL` 任一命中都拒绝。

对高风险直写，若不满足条件，返回现有 HTTP 错误 envelope 的 `STATE_CONFLICT`；消息只说明所需用户保存意图或时间限制，不回显敏感正文或其他 scope 信息。核对顺序必须先做 scope/latest user evidence/quote 校验，后看内容类别与保存指令；不能用错误差异泄露其他用户的事件。**不新建候选、不伪称 held**：现有 `memory_candidates` 需要 job 外键，直写拒绝就如实拒绝。若用户随后给出合格的新保存指令，应以新用户事件及新 quote 重新请求。现有历史 active 不被这条新规则自动删除。

## 3. 工具与用户可理解的反馈

DSH 工具只透传内核结构化错误；不得由适配器自行判定敏感或生成用户意图。Agent 可以告诉用户“这类内容需要你直接说请记住”，但不能代用户补造该指令或调用另一个隐藏写入口。若 Rust 返回时间内容不支持永久保存，Agent 不应声称已记住。不得把高风险写入失败记录为 `memory_remember` 成功或已激活。

## 4. 保留的授权边界

服务端仍以 Bearer token 限定 `(tenant,user)`；不接受请求体声明的用户身份。直接保存不是手动 promote；本版不提供管理员把 held 候选转 active 的命令。忘记仍写 `suppressed_sources`，旧证据重放不得复活。
