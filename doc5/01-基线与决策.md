# 01｜基线、证据与正式决定

## 1. 当前源码事实

基线 `main@a2edb62`，schema 3。`memory-extract/src/lib.rs` 的当前新作业 Prompt 为 `extract_v2`；`admit(c,events)` 是 v1/v2 作业共用函数。`memory-store-sqlite/src/jobs.rs::save_candidate` 将 active 候选写成 `source_class=user_explicit`，held 候选写成 `model_inferred`；候选与作业通过 `job_id` 关联。`memory-store-sqlite/src/memories.rs::remember` 只核验当前 scope/会话的最新 user/user 事件、连续 quote、幂等与抑制源，不核验用户是否说了“请记住”。`compose_context` 给 active instruction 至多两个独立名额，其他 kind 必须由查询命中。

阅读证据：`doc-handoff/06-日常对话观察.md` 会话 1—8；`doc-handoff/08-收口复验记录.md`；`doc4/05-候选与召回的决策边界.md`；`doc/13-算法与模型契约.md` §4—6。样本说明“有具体失败路径”，不提供总体召回率或误收率。

字段含义要保持诚实：现有 `source_class=user_explicit` 表示内容可逐字定位到用户直接陈述，**不等于用户明确要求持久保存**；`memory_remember` 的 Agent 工具调用也不等于用户本人执行了一次写入。实施 doc5 时在 README/诊断说明中写清这一点，不用旧字段名推断授权。

## 2. 已决定的产品规则

1. **候选原子性**：一个候选只能承载一个可独立纠错、遗忘、过期的命题；quote 是该命题的最短可定位连续原文。模型不得拼接多事件、改写用户话或把两件事塞进一条 active。
2. **自动准入范围**：只扩展到有限的、关于用户本人的稳定自述。职业/居住/主要技术或长期习惯等需满足 [03](03-准入与版本.md) 的明确句式和排除条件。不能因为 `kind=fact`、逐字匹配或模型 confidence 高就自动 active。
3. **先 held 的信息**：第三人事实、健康/过敏等敏感个人信息、未来节点、一次性或明显会变化的状态、归属不明的半句话、含两个命题的宽 quote。凭据类也不得 active；保留原 L0，候选诊断不得输出其正文。held 默认不参与 search/compose。
4. **显式保存不由工具调用本身证明**：`memory_remember` 处理健康/第三人内容时必须在同一条最新用户消息中找到与目标 quote 直接相邻的保存指令；凭据禁止 active，时间性内容在有效期机制确定前不得无限期 active。[04](04-显式保存路径.md) 给出闭合规则。
5. **召回维持有界相关性**：instruction 独立名额继续有效；fact/preference 不添加最新若干条的常驻名额，不在零相关证据时盲注入。改召回算法须先满足 [05](05-召回与离线评价.md) 的可区分探针与预算约束。
6. **历史可解释**：新作业用 `extract_v3` + `admit_v2`；旧作业保持原 Prompt + `admit_v1`。迁移只加元数据、不重跑、不回填 active、不重写旧 candidate。旧版本未知时显式失败。

## 3. 例子与边界

| 原话或候选 | 决策 | 原因 |
|---|---|---|
| “我在杭州做后端开发” | 新版自动 active，可为 fact | 第一人称稳定职业自述；需最短 quote、逐字来源、无排除项 |
| “我主要写 Rust” | 新版自动 active，可为 fact | 第一人称主要技术/长期工作方式；不靠技术词名单猜测 |
| “我在杭州做后端开发，平时主要写 Rust” | 整句 held；可拆出的首条独立判断 | 两个命题；“平时主要写 Rust”独立 quote 缺主语，不能凭模型补“我” |
| “我喜欢用暗色主题写代码” | 沿既有显式偏好路径 active | 明确用户自述、单命题 |
| “我们家小孩今年九月上小学一年级” | held | 第三人 + 未来节点；不能无期限当作当前事实 |
| “我对花生过敏” | 自动提取 held | 健康信息；模型提取不等于保存授权 |
| “老笔记本电池坏了，插电才能用” | held | 对象/归属和持续期限不明确、状态易变化 |
| “下班喜欢骑车放松” | held；若用户说“我下班喜欢骑车放松”可按偏好规则判断 | 缺明确第一人称，不以会话推断补主语 |

表中 `active` 是实施后目标结果，**不是当前代码已具备的能力**。对每条含义有歧义的候选，选择 held，并保留 reason 与原文供复核。

稳定职业、居住与主要实践也可能随时间变化；本版不凭模型猜有效期。若用户后来变更，继续使用现有 `/correct` 或 `/forget`。在得到新证据而未纠错之前，旧 active 可能过时，这是本版明确保留的质量限制，不能写成“系统会自动更新画像”。

## 4. 暂缓事项

不做自动 promote、第三人或健康事实的模型推断放行、默认过期日计算、跨事件语义合并、LLM 自动去重、embedding、任意偏好常驻、真实模型批量评测。继续使用现有 correct/forget；遗忘后旧证据重放不得复活。候选全批原子提交仍属 `doc-handoff/08` 已知限制，只有发现实际丢失/重复路径才另立任务。
