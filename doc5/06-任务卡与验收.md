# 06｜施工任务卡、依赖与交付标准

只写规则的本轮不修改实现。下列卡供后续 Harness 连续实施；每卡先读 `AGENTS.md`、`doc-handoff/08`、本目录和当前源码。每卡检查根 HEAD/status，不凭本文件里的旧行号猜实现。唯一代码目录为 `agent-memory/`，三个上游和官方 DSH clone 只读。只暂存明确路径，禁止 `git add .`。

## D5-0：收口遗留的两个契约偏差

**范围**：按 `doc-handoff/08 §3.2` 修 worker 侧 `WINDOW_TOO_LARGE/UNKNOWN_PROMPT_VERSION` 确定性错误立即 dead（本次 attempt 只增加一次）；skip audit `actor_kind='admin_cli'` 并修错误注释。补相应确定性用例。不要把修复与产品准入规则混成一个提交。**完成证据**：单次失败即 dead/不调模型；audit 行 actor 符合 `doc4/03`；已存在作业不被重写。

## D5-1：版本与迁移 0004

**负责**：新增 `agent-memory/migrations/0004_admission_version.sql`；`memory-contract/src/lib.rs` 的 schema/版本常量；`memory-store-sqlite/src/lib.rs` 迁移；`jobs.rs` 的读取与诊断 DTO；必要的 `memory-server` 作业详情字段。不得回改 0001—0003。**实现**：历史 job 默认 `admit_v1`；此卡期间新建 job 仍写 `extract_v2/admit_v1`，不能提前启用尚未实现的 v3/v2；旧候选和记忆不改。**完成证据**：schema 3 副本升级到 4，旧作业所有旧字段不变且新列为 v1；空库直装；重复打开不重跑；当前新作业仍可正常处理。未知 admission version 的立即 dead 由 D5-3 的完整 worker 分派验收。注意 `Store::open` 自动迁移，演练先做原库只读一致性快照再打开副本；本卡不碰 dana/realtest 原库。

## D5-2：`extract_v3` 与单命题候选

**负责**：`memory-extract/src/lib.rs` 的新 Prompt 与分派、候选粒度判定；`memory-server/src/worker.rs` 的 Prompt 路由；`doc/13 §4—5` 的增量说明。**实现**：保留 v1/v2 Prompt 原文；v3 明确一候选一命题、最短连续 quote、现行 JSON schema 和空数组语义；宽 quote/无主语/口语前缀按 [02](02-候选粒度与提取.md) held，不能把模型输出强行拆成新文本。**完成证据**：固定响应两项可分别关联同一事件；整句候选 held；无主语片段 held；跨消息拼接 rejected；schema 多字段按既有 BAD_JSON 行为处理。

## D5-3：版本化准入与 Store 提交

**负责**：`memory-extract/src/lib.rs` 的 `admit_v1/admit_v2`；`memory-store-sqlite/src/jobs.rs::save_candidate` 的版本化查库步骤、reason 与 provenance；`memory-server/src/worker.rs` 的 job.admission_version 分派。**实现**：旧规则冻结；新规则按 [03](03-准入与版本.md) 固定顺序。v3 Prompt 与 v2 准入都就绪后，**此卡末尾才切换**所有新作业（普通/超限/checkpoint）的默认版本为 `extract_v3/admit_v2`；版本默认值切换与分派必须在同一提交可运行。新 active 的 revision/audit 可查到策略版本。任何已忘来源继续拒绝，已 active 同 hash 仅加证据。**完成证据**：[07](07-决策样本矩阵.md) 自动提取行逐条成立；同样候选在旧 job 仍给旧结果，新 job 给新结果；同 scope 和跨 scope、冲突/忘记用例成立；未知 admission version 立即 dead；新 reason 可由候选只读 CLI 查询。

## D5-4：直写路径的高风险窄门

**负责**：`memory-store-sqlite/src/memories.rs::remember` 与 HTTP 错误映射、必要的 DSH 工具错误显示；不让 TypeScript 裁决来源或语义。**实现**：按 [04](04-显式保存路径.md) 在最新用户事件原文内检查保存指令与 quote 紧邻；凭据永不 active，健康/第三人需直接保存指令，时间性内容暂拒永久存储。普通偏好沿现有行为。**完成证据**：同一高风险 quote 的“用户陈述 + Agent 自发调工具”被 409 拒绝，“请记住：<同一 quote>”可允许的类别才 active；服务端错误不回显正文；合法后续新事件能保存；跨用户/旧事件仍按原错误隐藏。不得用模型自报“用户确认”替代用户原文。

## D5-5：召回探针与质量归因

**负责**：离线探针数据、结果记录和必要的本机脚本；本卡不改 `compose_context` 或检索排序。**完成证据**：[05](05-召回与离线评价.md) 所列该注入/正确沉默/盲区/跨 scope/遗忘/预算样本有预期与实际 ID；把已知零词法盲区写为未解决，不把无模型的探针写成回答质量验证。

## D5-6：交付与状态更新

**负责**：`agent-memory/README.md`、`AGENTS.md` 当前阶段入口、`doc-handoff/` 新交付记录、实际更改过的 `doc/13` 和 `doc5/`。列出迁移、版本对照、已核档位和未验证项。运行 `git status --short`、`git diff --check`；只暂存本项目明确文件。真实用户库 schema 4 的升级须独立部署决定，不能因临时库通过就声称已升级。

## 检查原则与状态格式

实施卡需要有针对性的 Rust 单测与临时 SQLite/HTTP 行为检查；D5-4 是授权边界，必须有否定用例。按改动运行 `cargo test --workspace`；若改 DSH 再做 `tsc`/适配器检查。停止在足以覆盖具体风险的检查，不做外部模型或无目的重复测试。每卡交接：基线 HEAD、改动文件、迁移、规则变化、执行命令与原始结果、失败/未验证、Git 状态与提交 ID。

不要顺手执行 dana/realtest 的 schema 3/4 真实升级、`rebuild-index`、held promote 或真实模型调用。`doc-handoff/08` 中 dana 旧库 `index_dirty=1` 与 `Store::open` 自动迁移是部署决策的输入，不是质量卡可以隐式修掉的状态。
