# 05 Rust 模型调用、作业来源与可信准入

本文件只处理现有 `memoryd` 自动提取通道的确定缺口，不重设计记忆类别。来源参考继续用 [三项目源码对照](../doc/02-上游源码对照.md)：L0 先存、L1 异步候选、证据链和派生索引。v1 的 [算法契约](../doc/13-算法与模型契约.md) 中候选准入规则保持有效。

## 1. 已实现与未实现的分界

[worker.rs](../agent-memory/crates/memory-server/src/worker.rs) 已有单 worker、flush 作业、固定响应走通的候选解析和入库路径；[memory-extract](../agent-memory/crates/memory-extract/src/lib.rs) 已要求候选引用窗口内的真实 `user/user` 事件、逐字连续 quote 和窄规则。历史报告中的 23 个测试与本机 curl 属已有交付记录，本次没有复跑。

当前真实模型客户端是手写 `TcpStream`：只接 `http://`，用 `SocketAddr` 解析 host:port，读取文本后按 HTTP 头尾切分，未处理 HTTPS、DNS 主机、chunked/压缩响应与响应大小界限。因此“支持 OpenAI 兼容端点”只能理解为部分本地 HTTP 实现，不能写成常见远程端点已可用。

## 2. v2 模型客户端契约

替换 `worker.rs::http_post_json`，使用能够处理 HTTPS/TLS、DNS、超时、HTTP 状态、正文大小限制和标准响应编码的维护中 Rust HTTP 客户端。需要新增 crate 时只引入这一条模型调用路径所需的依赖；crates.io 若仍不可达，记录阻碍和可复现命令，不能继续用不完整的手写 HTTP 并声称远程端点可用。

固定输入和输出：

- `model_endpoint` 是完整的 Chat Completions URL；不自行猜路径或把 `/chat/completions` 重复拼接。启动时校验 URL scheme 为 http/https、主机与路径明确；HTTPS 是默认生产路径，本地 mock 可用 HTTP。
- 密钥仅从 `model_key_file` 读取。请求头发送 `Authorization: Bearer`；日志不显示 key、完整请求体、用户事件正文或原始模型响应。空 key 是否允许由配置显式决定，不能把空字符串当真实授权。
- 请求中明确 `model`、system/user 消息、`temperature=0`。响应解析只接受预期 `choices[0].message.content` 为字符串；超大响应、非 JSON、缺字段、非 2xx 和超时分别标记错误，均保留 L0 与作业状态。
- 网络调用不持有 SQLite `Mutex<Store>`；每次 claim、装入窗口、提交候选分别用短事务/锁段。取消或超时不可提交半条 active 记忆。
- 一次成功调用后读取可用的 `usage` 计数写入作业；提供者未给 usage 时保持 NULL，不估算成真实用量。

不安排多个模型之间的比较；只用一个用户已经配置的端点做一次短的真实连通与合法候选闭环。固定响应检查仍用于确定性规则，不替代真实端点连通。

## 3. Prompt 版本持久化

旧 [doc/13 第 4 节](../doc/13-算法与模型契约.md) 要求每个作业保存 `prompt_version`，但 [0001_init.sql](../agent-memory/migrations/0001_init.sql) 的 `extraction_jobs` 没有该列。现实现只在日志和 active 记忆 revision 的 `reason_code='extract_v1'` 中体现；held/rejected 或失败作业的版本不能仅靠持久表还原。

**v2 决策：增加 `0002_prompt_version.sql`，不修改已发布的 `0001`。** 迁移为 `extraction_jobs` 增加非空 `prompt_version`，现有 v1 作业默认 `extract_v1`。新 flush 在同一事务写入该列；worker 从作业行读取并选择已实现的 Prompt/准入版本，不再只引用当前编译常量。未知版本不得用“最新规则”处理旧作业，要显式失败并保留可诊断状态。同步更新 `memory-contract::SCHEMA_VERSION=2`、版本端点、迁移 checksum 和 README 的升级说明。旧库升级前先备份，验证已提交 v1 作业与候选仍可读。若实现中发现 SQLite 版本或迁移执行器约束与这一步不兼容，先记录具体失败并调整迁移方案，禁止回改 `0001`。

`prompt_version` 记录“生成该作业时的规则版本”，不能由模型输出填。后续更新 Prompt 必须新建版本并保留老版本处理未完成作业。模型名、调用量和错误码仍使用现有字段。

## 4. 可信门槛不扩张

`active` 只能由 Rust 判断：候选 source ID 在同 scope、本窗口且原事件为 `role=user/source_kind=user`；quote 是该条原文连续子串；长度、明确表达、语境与敏感闸门通过；重复 claim 只增证据，冲突放 held；forgotten 旧来源被 `suppressed_sources` 阻断。模型 confidence 不提供权限，工具或助手内容不能自称用户。

保留 `fact/preference/instruction/episode` 四类，保留 v1 的有限上下文、FTS5/中文二元字检索和 RRF；本轮不引入向量库、画像、自动概括或情感状态推断。现有显式 `remember` 与自动 `extract_v1` 的信任路径不同，修模型客户端时不得把手动工具改成“模型认为可信即 active”。

## 5. 验收与结果表述

必要检查只有：本地固定响应能让合法候选 active、坏 JSON 使作业按既有重试上限进入 dead 且 L0 不丢；一条真实 HTTPS/HTTP 配置的短调用返回作业 `succeeded`、正确来源的 candidate 与可检索记忆；模型断开后错误可见且服务仍可做手工 remember/search。若用户未提供可用端点，完成客户端实现并标明“真实模型连通未验证”，不能改写验收结论。
