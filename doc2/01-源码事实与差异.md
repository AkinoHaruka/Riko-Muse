# 01 官方 DSH 源码事实与 v1 差异

本文件锚定 `deepseek-harness` 的 `477b4f4` 和现有 `agent-memory` 的 `1748db3`。升级 DSH 时先复查这些路径；不能把旧 `riko-memory` checkout 的用法直接当作当前官方接口。

## 1. 官方宿主事实

| 事实 | 代码出处 | 对适配器的约束 |
|---|---|---|
| DSH 是 Cordis 插件树，通过 profile 和 patch 组合；应用由 `dsh` profile 启动 | [architecture](../deepseek-harness/docs/architecture.md)、[CLI README](../deepseek-harness/apps/cli/README.md)、[app-boot README](../deepseek-harness/packages/boot/app-boot/README.md) | 实现 `apply(ctx, config)` 插件入口；独立 profile/`--patch` 装载，不调用私有启动器 |
| 当前官方 checkout 没有 `packages/bundle/riko-memory` | 当前 `packages/` 文件清单 | v1 文档引用的旧插件只是历史参考；不得在新 clone 寻找或修改它 |
| `SessionEvent` 的 `seq` 是会话内连续序号，`time` 是 Unix 毫秒数 | [session/types.ts](../deepseek-harness/packages/core/session/src/types.ts) 的 `SessionEvent` | 适配器要把数字时间转换成带时区 RFC3339；不能把它按字符串或 `Date` 读取 |
| `user/message` 的 `data` 直接是 `UserMessage`；`assistant/message` 与 `tool/result` 的正文在 `data.message` | [session/types.ts](../deepseek-harness/packages/core/session/src/types.ts) 的 `SessionEventMap` | 四类事件分别映射；不能共用未经核实的 `data.message || data.content` 猜法 |
| `UserMessage.source` 必填；只有 `source.kind === 'user'` 是直接用户输入 | [llm/message.ts](../deepseek-harness/packages/llm/llm/src/message.ts)、[session/types.ts](../deepseek-harness/packages/core/session/src/types.ts) | 未知或其他来源不能默认标成 `source_kind=user`；插件注入不能回流为用户证据 |
| `session/event` 是提交后的同步、受保护的通知，监听器错误会被记录并隔离，不会撤销 DSH 原事件 | [session/index.ts](../deepseek-harness/packages/core/session/src/index.ts) 的事件文档和 `Session.append` | 本地 spool 成功与 DSH session 成功是两件事；要记录可观测的捕获失败和缺口 |
| `Session.append` 热路径不等待 I/O；官方 `sessionQuery` 提供异步 `readEvent/observeSession` | [session/index.ts](../deepseek-harness/packages/core/session/src/index.ts)、[session-query](../deepseek-harness/packages/session-query/session-query/src/index.ts) | 回调只做有界入队，异步落盘；对已知 session 的缺口用异步定点读取核对，不能承诺零丢失 |
| `agent/pre-step` 是 waterfall；必须调用 `next()`，返回 `enter` 的消息可追加；模型可见输入须进入 Session 日志 | [agent/runtime-types.ts](../deepseek-harness/packages/core/agent/src/runtime-types.ts)、[architecture](../deepseek-harness/docs/architecture.md) | 保留决策字段，来源用官方 `createUserMessage`；不能只修改未记录的 HTTP 请求 |
| `agent.id === agent.session.id` 是当前 Agent registry 约束 | [agent/index.ts](../deepseek-harness/packages/core/agent/src/index.ts) | `agent.id` 可作 DSH 来源标记，不能当可信用户 ID 或跨用户身份 |
| 工具使用 `defineTool`，必须声明 `output.schema` 与 `output.render`；`execute` 收到 `exec.agent` 和取消信号 | [adding-a-tool](../deepseek-harness/docs/cookbook/adding-a-tool.md)、[tools README](../deepseek-harness/packages/core/tools/README.md) | 现有自定义 `ToolHost` 数据结构不是可直接注册的 DSH ToolDefinition |
| 新代码不应调用被标为 deprecated 的 `Session.snapshotEvents/ownEvents/eventAt` 取历史 | [session/index.ts](../deepseek-harness/packages/core/session/src/index.ts)、[官方决定记录](../deepseek-harness/.agents/notes/implemented/architecture/2026-09-09-deprecate-synchronous-session-event-reads.md) | 事件 seq 与 evidence ID 由当前通知流和持久 spool 索引维护；缺失历史要用受支持的异步读取路径，不能新造同步全量扫描 |
| 当前源码未找到可在这些 Hook 中直接提供“经过认证的多用户 user ID”的契约 | 本次核对的 Agent/Session/Tool 接口 | v2 仍按一个 DSH 进程一个用户令牌部署；不能用 preset、session、Agent 或模型文本猜用户 |

## 2. 与当前代码逐项对照

| 编号 | 当前代码位置 | 读代码得到的状态 | 对交付的影响 |
|---|---|---|---|
| G-01 | [adapters/dsh/src/index.ts](../agent-memory/adapters/dsh/src/index.ts) | 只有 `createAdapter(config, glue)`；没有实际 DSH Cordis `apply` 装载入口 | profile 无法把适配器当完整插件装入 |
| G-02 | 同上 `readTokenFile` | `package.json` 是 ESM，运行时代码却调用裸 `require('node:fs')` | 在纯 ESM Node 环境会于插件启动时失败 |
| G-03 | [events.ts](../agent-memory/adapters/dsh/src/events.ts) `mapEvent` | 只接受字符串或 `Date` 时间；官方是数字毫秒 | 当前官方 DSH 的正文事件会被视为不支持 |
| G-04 | 同上 `mapEvent` | `user/message` 无 `source.kind` 时默认 `user`；`assistant/message` 和 `tool/result` 来源固定映射 | 来源缺失被提升为用户；应失败关闭或明确标成非用户 |
| G-05 | [index.ts](../agent-memory/adapters/dsh/src/index.ts)、[tools.ts](../agent-memory/adapters/dsh/src/tools.ts) | 事件和工具写入基本都使用 `unknown-agent` | 来源 Agent 信息丢失；不影响 scope，但不满足来源追踪 |
| G-06 | [events.ts](../agent-memory/adapters/dsh/src/events.ts) `observeSessionEvent` | 本地追加在异步 Promise 链中，回调先返回；写入没有 `fsync` | 不能声称“回调返回前已持久落 spool” |
| G-07 | 同上 `sendOp/replayPending` | HTTP 失败的记录留在文件里，但进程继续运行时没有明确的后台重试；flush 发送不检查前面事件已 ack | 内核短暂离线后可能直到重启才恢复；不完整窗口可能先排队 |
| G-08 | [tools.ts](../agent-memory/adapters/dsh/src/tools.ts) `evidenceFor` | 取“最后一个正文事件”序号，可能指向助手或工具；`exec.agent` 被当 Session 传给 `sessionId` | remember/correct/forget 可能错误绑定或一直失败 |
| G-09 | 同上 `memory_correct/forget` | `correct` 未传必需的 `old_quote`；两者把必需的 `expected_version` 做成可选 | 与 [服务端请求类型](../agent-memory/crates/memory-server/src/main.rs) 不兼容 |
| G-10 | [index.ts](../agent-memory/adapters/dsh/src/index.ts) | `captureEnabled` 控制工具注册，`injectionEnabled` 没有控制注入；启动强制请求 version | 配置语义错位；内核启动顺序不便于离线 spool |
| G-11 | [worker.rs](../agent-memory/crates/memory-server/src/worker.rs) `http_post_json` | 手写客户端仅接受 `http://`，地址用 `SocketAddr` 解析，响应按简单 HTTP 文本切分 | 常见 HTTPS/域名模型端点不能使用；真实模型闭环未验证 |
| G-12 | [doc/README.md](../doc/README.md)、[agent-memory/README.md](../agent-memory/README.md) | 一个仍写“尚未实现”，另一个将本机协议闭环表述为卡 0～5 已交付 | 状态报告需要分开说明实现、宿主接入和运行证据 |
| G-13 | [memory-store-sqlite/src/memories.rs](../agent-memory/crates/memory-store-sqlite/src/memories.rs) `forget_memory` | 校验了遗忘动词和旧 claim 内的 `target_quote`，却没有校验用户最新消息含该 `target_quote` | 带 ID 和泛称“忘记”可能遗忘未被用户明确指认的记忆；Rust 服务端必须补验 |

G-01 至 G-13 是从源码可直接定位的缺口，不等同于完整安全审计。v2 先修正这些明确问题，并用 [06 任务卡](06-施工任务卡与验收.md) 做最小验证。此处没有复跑旧报告所说的 23 个测试或 curl 样例。

## 3. 不变的内核边界

Rust 的 `ScopeKey` 由 token hash 查出；请求正文没有 `tenant_id/user_id`。[HTTP v1](../doc/12-HTTP协议v1.md) 和 [迁移蓝图](../doc/11-数据库v1迁移.md) 没有因为官方 DSH clone 而失效。v2 默认不改 HTTP 路径、不改已有字段含义、不改 `0001_init.sql`；确需持久字段时必须新增迁移，不回写已发布的 `0001`。

模型输出仍是候选。来源必须是同 scope、同窗口、`role=user`、`source_kind=user` 的原文证据，Rust 负责最终准入。这个规则与 DSH 适配器是否已装载无关。
