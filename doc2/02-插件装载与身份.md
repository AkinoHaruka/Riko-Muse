# 02 DSH 插件装载、生命周期与用户身份

目标：`agent-memory/adapters/dsh` 从“待宿主注入的通用 TypeScript 模块”成为能由官方 DSH profile 加载、停用和重载的 Cordis 插件。实施以官方 [architecture](../deepseek-harness/docs/architecture.md)、[app-boot](../deepseek-harness/packages/boot/app-boot/README.md) 和 [工具示例](../deepseek-harness/docs/cookbook/adding-a-tool.md) 为准。

## 1. 装载边界

**源码事实。** 官方 DSH 的应用启动方式是 `dsh --profile <name>`。profile 以 bundle、profile patch、home patch、命令行 `--patch` 逐层组合；`insert` 可插入绝对文件路径或包名。插件模块通常导出 `name`、`inject`、`Config` 和 `apply(ctx, config)`。注册是 Cordis effect，卸载时要释放监听器、工具和本地资源。源码路径：[architecture](../deepseek-harness/docs/architecture.md)、[CLI](../deepseek-harness/apps/cli/README.md)、[tool-bash](../deepseek-harness/packages/shell/tool-bash/src/index.ts)。

**v2 决策。** 先在 `agent-memory/adapters/dsh` 内实现一个独立可构建的 Host 插件入口；用独立 `memory-dev` profile 加 `--patch` 装载。首轮不改官方 DSH `packages/`、不把适配器并入 DSH 默认 base bundle，也不与旧记忆插件同时运行。profile 路径和补丁只供本机试运行；交付时再选持久安装形式。

### 入口职责

1. 定义并校验 `Config`，在加载时拒绝空令牌路径、相对 spool 路径、非法端口/URL、非 loopback 内核地址以及无效上限。`memoryUrl` 必须使用 `http://127.0.0.1` 或等价本机地址；禁止用户信息、查询串和路径片段参与基地址。
2. 用 ESM `import { readFileSync } from 'node:fs'` 读取令牌文件；不调用裸 `require`。Token 只保存在进程内，日志不输出 token、token hash、记忆正文或模型密钥。
3. 打开 spool 并恢复本地 receipt 索引，然后注册当前会话事件监听、`agent/pre-step` 和五个工具。每个注册的卸载行为由 Cordis effect 承担；不要用全局未释放的监听器或定时器。
4. 启动后台连通循环。daemon 离线时插件仍可捕获并落 spool，compose 跳过，写工具返回“内核暂不可用”；daemon 恢复后先检查 `/v1/version` 的 `protocol_version=1`，再按序发送。若返回不兼容版本，暂停出站请求并报明确错误，不能把不明协议当成功。
5. 插件卸载先停止接受新事件，等待正在执行的发送链最多 5 秒，保留未 ack spool；释放工具/Hook/定时器和文件句柄。`dispose` 必须由宿主 await 到真实收尾，不能只创建一个未等待的 `Promise.race`。

`captureEnabled` 只控制 L0 事件/flush 捕获；`injectionEnabled` 只控制 pre-step 自动注入。五个工具的启停若需配置，新增独立 `toolsEnabled`；不能让 `captureEnabled=false` 偶然关闭工具。写工具在捕获关闭时仍须检测当前用户证据是否存在，不能靠模型参数补齐证据。

## 2. DSH 身份与来源

Rust 服务端的真实用户 scope 仍由请求 Bearer token 决定，见 [v1 目标与边界](../doc/01-目标与边界.md) 和 [HTTP v1](../doc/12-HTTP协议v1.md)。适配器不在请求 JSON 中发送 `tenant_id`、`user_id`。此官方 checkout 的 Agent/Session/Tool 契约只提供 session-backed `agent.id` 和 `agent.session.id`；本次核对没有找到可证明“同一进程内当前操作属于哪名已认证人类用户”的 Hook。因此：

- 一个 DSH 进程配置一名用户的一份令牌；同进程的不同 Agent 使用同一令牌，默认共享记忆。
- 不同用户使用不同进程和不同令牌，可接同一个本地 Rust daemon。
- 多用户共用一个 DSH 进程不纳入本轮验收。以后只有拿到 DSH 可信身份接口和选择 token 的证明，才允许开放。
- `origin.agent_id` 用官方 `agent.id` 或等价会话来源标记。源码约束 `agent.id === agent.session.id`，所以它在这版 DSH 中是会话身份，不是假装稳定跨会话的“角色 ID”。来源标签不改变读权限。
- `host_id` 由每个适配器安装的非秘密稳定 ID 配置或首次生成并持久保存；同一安装重启保持不变，多安装不同。不可每次启动生成，否则幂等键变化；不可从 token hash 派生。

## 3. 配置与包接口

预期配置字段：

| 字段 | 语义 | 默认/校验 |
|---|---|---|
| `memoryUrl` | 内核基地址 | `http://127.0.0.1:8791`，loopback URL |
| `userTokenFile` | 当前单用户的令牌文件 | 必填，文件必须存在，当前用户可读 |
| `spoolDir` | 本机持久队列 | 必填绝对路径，不在上游仓库源码树 |
| `hostId` | 当前 DSH 安装的稳定来源 ID | 必填或首次持久生成；非空、最长 256 字符 |
| `composeTimeoutMs` | 上下文调用时限 | 默认 500 ms，正整数 |
| `writeTimeoutMs` | 单次 HTTP 写时限 | 默认 3000 ms，正整数 |
| `captureEnabled` | 事件捕获与 flush | 默认 true |
| `injectionEnabled` | pre-step 注入 | 默认 true |
| `toolsEnabled` | 注册五个工具 | 默认 true |
| `spoolLimitBytes` | 本地 spool 上限 | 默认 100 MiB，正整数 |

这些是 v2 插件字段；内核 HTTP v1 无需增加身份字段。宿主插件的 `package.json` 要声明 ESM、导出的编译产物、实际使用的 DSH peer 依赖及准确的 DSH 版本兼容范围。`tsconfig` 和源码 import 形式按当前官方 Node ESM 构建路径核对；不要只靠脱离 DSH 的 `tsc --noEmit` 宣称可装载。`HostGlue` 若保留，必须有本仓库内的官方 DSH 实现并从 `apply` 调用；不允许再把“glue 由目标装载层注入”写成已完成状态。

## 4. 最小装载证据

构建插件后，用独立 profile 的临时 `--patch` 加入插件行。先运行配置预览确认该行和完整 config，再启动 DSH。记录以下事实：

1. DSH 版本与 commit、插件包版本、profile 名、最终 patch 文件路径。
2. 插件加载日志和五个工具是否在有效工具目录中；卸载后工具消失。
3. DSH 对一条用户输入产生的实际 `session/event` 形状；不得把测试构造的对象冒充宿主事件。
4. 内核离线时 profile 仍能启动且事件落本地 spool；连接恢复后同键重放。
5. 配置中只出现 token 文件路径，不出现 token 值。

独立 profile 操作步骤见 [07 运行手册](07-独立Profile运行手册.md)。这份文档给的是实施契约，当前没有对官方 clone 执行插件装载。
