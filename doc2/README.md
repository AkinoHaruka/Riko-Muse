# Agent Memory v2 开发入口

状态：基于本地源码的下一阶段施工规范；文档已写，v2 代码尚未实施。基线日期：2026-09-25。

## 目标

把现有 Rust 内核和 DSH 适配器真正接入新克隆的官方 DeepSeek Harness，并收紧证据接收、工具绑定、spool 恢复与模型调用的实际运行边界。v2 结束的判据是：在独立 DSH profile 中，由真实 DSH 用户消息触发 Agent A 写入记忆，Agent B 能读到；纠错和遗忘工具可以从同一宿主会话正确提交；身份隔离和来源准入仍由 Rust 服务决定。

此目录针对当前实现的缺口，不重写 v1 的全部数据库和 HTTP 规范。`doc/` 保留产品目标、SQLite 模式、HTTP v1 字段和准入规则；`doc2/` 对 DSH 官方源码事实、接线与修复任务拥有优先权。两者冲突时先写明冲突和影响，不让实现者自己猜。

## 已固定的用户要求

1. Rust 是通用记忆内核，DSH 是第一个宿主。
2. 同一用户的不同 Agent 默认共享记忆；不同用户按服务端令牌 scope 隔离。
3. 首版从空库开始，不导入旧 Riko／Companion 记忆。
4. 可信记忆以可定位的用户证据和 Rust 准入为依据，沿用三项目调研与 v1 收紧后的规则。
5. 不安排模型选型海试或大规模 API 基准；只做完成实际接入所必需的检查。

## 完成状态用语

- “代码存在”：仓库有实现，不代表编译、装载或运行。
- “本机协议闭环”：直接调用 `memoryd` HTTP 得到结果，不代表 DSH Hook 调用成功。
- “DSH 宿主闭环”：独立 profile 中的真实 DSH session 产生证据、工具和注入，且能在 DSH 日志和 `memoryd` 状态中对上。
- “真实模型连通”：一条作业经配置的真实端点完成；不能由固定响应代替。
