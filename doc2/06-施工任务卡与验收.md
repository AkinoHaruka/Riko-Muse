# 06 v2 施工任务卡与最小验收

本任务表给后续实现模型直接执行。按卡提交和报告；每卡只触碰列出的新项目文件或文档。官方 `deepseek-harness/`、`EverOS/`、`hindsight/`、`tencentdb-agent-memory/` 均是只读输入。根仓库中的新 clone 当前是未跟踪目录，不能执行根目录的递归 `git add .`。每张卡先读所列来源再动代码，发现路径或接口改变时记录实际位置并更新对应 `doc2`，不能用旧 checkout 的类型补缺。

“完成”只表示该卡列明的代码与最小检查达到条件；最后一张卡之前不能称为“DSH 首接入已完成”。不要为省时跳过源代码中已经确认的形状差异，也不要为一个简单功能组织长时间模型海试。

## 卡 V2-0：锁定官方基线与最小插件入口

**先读：** [01](01-源码事实与差异.md)、[02](02-插件装载与身份.md)；官方 `docs/architecture.md`、`apps/cli/README.md`、`packages/shell/tool-bash/src/index.ts`、`packages/core/tools/README.md`。

**修改范围：** `agent-memory/adapters/dsh/package.json`、`tsconfig.json`、`src/index.ts`、`src/config.ts`，必要时新增本适配器内部的 `src/plugin.ts` 或文件；本卡不改 Rust 和官方 DSH clone。

**实现：** 提供 DSH 可加载的 Cordis `apply(ctx,config)`，把现有 `MemoryClient/EventPipeline/Spool` 连接到真实 `ctx.on` 和 `ctx.tools.register`；读取 token 改为 ESM import；验证 config；用 Cordis effect 管理监听器、工具和异步资源。daemon 离线时保留本地捕获模式，连通后先核 `protocol_version=1`。`captureEnabled`、`injectionEnabled`、`toolsEnabled` 分别控制自己的行为。构建产物必须从 Node ESM 可 import。

**完成证据：** 构建/类型检查通过；独立 profile 的配置预览出现一条 `agent-memory` 插件行；实际 profile 启动时插件可加载，停用后工具和监听器消失。仅 `tsc --noEmit` 通过不够。

## 卡 V2-1：官方事件形状与可靠 spool

**先读：** [03](03-事件映射与可靠性.md)；官方 `packages/core/session/src/types.ts`、`index.ts`、`packages/llm/llm/src/message.ts`。

**修改范围：** `agent-memory/adapters/dsh/src/events.ts`、`spool.ts`、`client.ts`、`index.ts`；不改内核 HTTP 协议。

**实现：** 数字毫秒时间转 RFC3339；`user/message` 从 `event.data` 取正文，assistant/tool 从 `event.data.message` 取；`user` 来源必须精确匹配；回调只入有界内存队列，异步写入者确认 spool 落盘后才发送；记录已观察 session 光标并通过官方异步 session-query 对已知缺口定点对账；持久 receipt 包含 `evidence_id`；同 session 先 event ack 后 flush；daemon 恢复时无需重启适配器即可重试；401、永久 400/409 与可重试错误分别处理；卸载真实等待并关资源。按安装持久 `hostId`，`agent_id` 用当前 DSH session-backed Agent ID。

**完成证据：** 一个官方形状 `time:number` 输入可落 L0；插件来源不能成为用户证据；daemon 短暂离线后当前进程重发成功；前序事件未 ack 时 flush 不发送；重启后旧 op 幂等且 evidence ID 可用；写盘失败产生可见缺口，不假称已接收；若独立 profile 装有 session-query，演示一次已知 session 的异步缺口对账。只需要一个短序列，不跑全量 DSH 会话数据。

## 卡 V2-2：五个真实 DSH 工具

**先读：** [04](04-工具与上下文.md)；官方 `docs/cookbook/adding-a-tool.md`、`packages/core/tools/src/schema.ts`、`packages/core/agent/src/runtime-types.ts`；本项目 `doc/12`。

**修改范围：** `agent-memory/adapters/dsh/src/tools.ts`、`events.ts`、`client.ts`；如需更改入口注册，同时改 `src/index.ts`。

**实现：** 用官方 `defineTool` 注册五个工具，准确声明参数/输出；从 `exec.agent.session` 和当前 `user/user` receipt 定位证据；读工具使用内核 scope，写工具需要真实 `origin`、`user_evidence_id`；`correct` 的 `old_quote/expected_version`、`forget` 的 `expected_version` 必填；HTTP 失败不能被包装成成功；传递 `exec.signal`。

**完成证据：** 在 DSH Tool registry 能看到五个工具；remember 使用当前用户证据成功；assistant/tool 事件之后仍绑定到最后一条真实用户证据；correct/forget 请求的 JSON 与 Rust Deserialize 结构一致；缺 evidence/版本时工具返回可处理错误，不提交写入。

## 卡 V2-3：有来源的上下文注入

**先读：** [04](04-工具与上下文.md)；官方 `packages/core/agent/src/runtime-types.ts`、`packages/core/agent-loop/src/agent.ts`、`packages/llm/llm/src/message.ts`。

**修改范围：** `agent-memory/adapters/dsh/src/recall.ts`、`index.ts`、`client.ts`。

**实现：** `await next()` 后只改 `enter` 决策；原始用户消息必须 `source.kind=user`；调用 `compose` 时使用 `args.signal` 和 500 ms 默认超时；用官方 `createUserMessage` 标成 plugin 来源，保持 `startsRequestSeries`；同一决策跳过重复注入；`injectionEnabled=false` 生效；离线和空结果原样返回。

**完成证据：** 同用户 Agent A 记忆在 Agent B 的真实 DSH 请求中出现，且能从 Session 日志重建；其他用户 token 的 Agent 不见；plugin 来源不会被事件线重新摄入为用户事实；停用注入后不再出现记忆块。

## 卡 V2-4：Rust 遗忘最终闸门

**先读：** [04 第 3 节](04-工具与上下文.md)；本项目 [HTTP v1 第 6 节](../doc/12-HTTP协议v1.md)；`memory-store-sqlite/src/memories.rs`。

**修改范围：** `agent-memory/crates/memory-store-sqlite/src/memories.rs` 和该 crate 的必要行为检查；只在有证据时改 `memory-server/src/main.rs` 的错误映射。

**实现：** `forget_memory` 在事务前要求最新用户证据正文同时含遗忘动词和非空 `target_quote` 连续片段，`target_quote` 还须定位到目标 memory claim；保留已 forgotten 的幂等确认、乐观锁和旧来源抑制。此检查属于 Rust 真正执行点，不能仅由 DSH 工具或 Prompt 实现。

**完成证据：** “忘记那个”+已知 ID 被拒绝；“忘记我喜欢 Rust”定位对应 claim 可通过；另一用户 ID 仍 404；相同请求幂等，旧证据重放不能复活。只做这一组边界检查。
