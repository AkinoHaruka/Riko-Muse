# 04 五个 DSH 工具与自动上下文

本文件同时约束 DSH 端和必要的 Rust 服务端检查。精确 HTTP 字段继续以 [doc/12](../doc/12-HTTP协议v1.md) 为准；官方工具定义与 waterfall 语义来自 [adding-a-tool](../deepseek-harness/docs/cookbook/adding-a-tool.md) 和 [agent/runtime-types.ts](../deepseek-harness/packages/core/agent/src/runtime-types.ts)。

## 1. 通用工具形状

每个工具通过官方 `defineTool({name,description,parameters,output,execute})` 构造并以 `ctx.tools.register` 注册。`output.schema`、`output.render` 与 `execute` 的真实值必须一致；不得直接把任意 `r.body` 当成已校验输出。`exec.agent` 提供当前运行的 Agent，`exec.agent.session` 提供宿主 Session，`exec.signal` 取消 HTTP 请求。注册随插件卸载自动失效；一条 DSH ToolDefinition 可见并不证明其 `execute` 已成功。

工具参数不能出现令牌、tenant/user ID 或“由模型填写的 evidence_id”。对 Rust 响应先按 HTTP 状态和 `error.code` 分类：用户可处理的状态给简短、明确的结果；基础设施/协议错误抛出并记录 `request_id`，不把失败响应当成成功记忆。模型可见的返回值要有界，不回显完整用户事件或 token。若实际工具的输出 schema 选择 JSON 对象或字符串，须在代码与快照里固定同一种；不能一会儿返回对象，一会儿返回 JSON 字符串。

## 2. 当前用户证据定位

`memory_remember/correct/forget` 共享一条流程：

1. 从 `exec.agent.session.id` 取得 Session ID，从 `exec.agent.id` 取得来源 Agent ID。当前官方 DSH 要求两者相同，但要显式使用正确对象，不能把 `Agent` 对象交给 `sessionId(session)`。
2. 从本适配器通过 `session/event` 维护的“该 session 最新 `source.kind=user` 消息”记录，取 `event.seq`、`message.id` 和完整原文。不能使用“最后一条正文事件”，因为随后可能出现 assistant/tool 事件。
3. 等待这条用户事件的内核 ingest receipt，取得对应 `evidence_id`；等待应受 `writeTimeoutMs` 和 `exec.signal` 限制。若还未 ack，返回“当前消息尚未入库，请重试”，不能改用旧用户事件。
4. 请求体发送 `origin={host_id,agent_id,session_id}`、`user_evidence_id` 和该工具允许的原文字段。Rust 再检查 scope、role/source_kind、最新用户事件及 quote；适配器的检查不是最终授权。
5. 收到 `STALE_USER_EVIDENCE`、`QUOTE_MISMATCH` 或 `VERSION_CONFLICT` 时，用当前状态让用户重述或重新查询；不得自动换成另一条证据或偷偷重试写操作。

这里的“最新用户消息”按每个 session 的 `user/user` 通知更新，不从 `deriveMessages()` 中反向猜 `event.seq`；`deriveMessages()` 是模型表面投影，可能包含插件上下文且没有把每条消息直接映射回内核 evidence ID。

## 3. 工具参数与服务端要求

| 工具 | 模型可填参数 | 适配器补入字段 | 成功边界 |
|---|---|---|---|
| `memory_search` | `query` 非空，`limit` 1–20，可选 `include_history` | Bearer token 仅在 HTTP header | 返回当前 scope 的受限摘要；历史查询需明确历史词 |
| `memory_get` | `id` | Bearer token | 仅当前 scope 可见 active 记忆，跨用户 ID 返回 404 |
| `memory_remember` | `quote`、`kind` | `origin`、最新 `user_evidence_id` | quote 必须是最近原始用户消息的连续片段；Rust 创建或同 claim 去重 |
| `memory_correct` | `id`、`expected_version`、`old_quote`、`replacement_quote` | `origin`、最新 `user_evidence_id` | 最新用户消息要同时含旧片段和新片段，旧片段还要匹配目标记忆；旧版 superseded，新版 active |
| `memory_forget` | `id`、`expected_version`、`target_quote` | `origin`、最新 `user_evidence_id` | 最新用户消息明确含遗忘动词和目标片段；后续 search/compose 立即不见，响应注明 L0 保留 |

`expected_version` 对 correct/forget 必填，来源于 search/get 返回的版本；没有版本时先查，不传 `undefined`。`memory_correct` 必须传 `old_quote`，不能只传新文本。`memory_forget` 的 `target_quote` 应取用户实际指认的连续原文；“忘记那个”没有明确片段时拒绝写入并提示用户重述，不能因为模型选了一个 ID 就删除。

**必须补的 Rust 检查：** [memories.rs 的 `forget_memory`](../agent-memory/crates/memory-store-sqlite/src/memories.rs) 当前只检查 `has_forget_cue(content)` 和 `target_quote` 在旧 claim 中，没有检查 `target_quote` 在 `content` 中。补上该检查，并保持已 forgotten 的幂等确认、`suppressed_sources` 和跨用户 404 行为。该判断必须放在真正执行遗忘的 Rust 路径，而非仅在工具描述、TypeScript 参数或 Prompt 中。

## 4. 自动上下文

注册官方 `agent/pre-step` waterfall 时先 `await next()`。若 `decision.kind !== 'enter'` 或 `signal.aborted`，原样返回。查询只从本次 `args.messages` 中选择最后一条 `source.kind === 'user'` 的原始用户消息；缺少明确 source 时不提升为用户。`compose` 请求带 `agent_id=String(args.agent.id)`、query、`max_items<=5`、`max_chars<=2000`，并与 `args.signal` 共同取消，超时默认 500 ms。

`compose` 返回空文本、超时、内核离线或 HTTP 错误时，返回原 decision，日志只记错误码和 request ID。成功时用官方 `createUserMessage` 生成带 `source.kind='plugin'`、稳定插件名的消息，返回 `{...decision,messages:[...decision.messages,memoryMessage]}`，保留 `startsRequestSeries` 等字段。若本次 decision 中已有相同插件来源消息，跳过重复注入。官方 AgentLoop 会把准入的用户角色消息记入 Session 日志；实际运行还需检查模型请求和日志都能看到该来源。

`injectionEnabled=false` 时不注册或明确跳过这个 Hook；`captureEnabled=false` 不应悄悄改变注入配置。Agent A 写入后 Agent B 自动注入可见的前提是同一个用户令牌；`agent_id` 只是来源/读取审计信息，不能用它过滤掉同用户其他 Agent 的记忆。

## 5. 最小宿主检查

在一个隔离 profile 中按顺序观察：

1. 用户对 Agent A 说“以后回答我用中文”，当前会话 `user/message` 有数字 `time` 且 `source.kind=user`，内核返回对应 `evidence_id`。
2. Agent A 调用 remember，写入成功；同用户 Agent B search/get/compose 可见；另一用户 token 用相同 ID 返回 404。
3. 用户说“把‘以后回答我用中文’改成‘以后回答我用英文’”，correct 提交新旧 quote、版本和当前 evidence；旧记忆不再自动注入，新记忆出现。
4. 用户明确说“忘记‘以后回答我用英文’”，forget 后 search/compose 不见；“忘记那个”被 Rust 拒绝。
5. 插件生成的 `source.kind=plugin` 消息不能经事件线变成 `user/user` 证据；同一 pre-step 不重复注入。

记录真实 DSH session ID、内核 request ID、memory ID 与状态，不保存 token 或完整私密正文。若没有模型凭据，可先在官方宿主的 keyless 测试装置中核对 Hook 和工具路径；“DSH 实际会话闭环”仍要等真实会话完成才能宣称。
