# 07 开发顺序、交付物与必要验证

本计划按可运行的纵向切片排序，避免先完成大堆抽象再发现 DSH 接口不匹配。每个切片有可演示产物；完成后才进入下一切片。用户明确希望减少测试阶段，因此不设置单独的长时间在线评测阶段，也不为每个实现细节写镜像式测试。关键的身份隔离、幂等和遗忘必须用简短、可重复的检查证明。

## 阶段 0：仓库与协议骨架

**产物**：独立 Rust workspace、许可证和第三方声明、Cargo lockfile、配置示例、`memory-server` 健康端点、版本端点、空数据库迁移、DSH 适配器包骨架。三个上游仓库保持只读，旧 DSH 插件保持不动。

**完成条件**：Rust 进程在 Windows 本机启动；`GET /v1/health` 返回协议版本与存储状态；无效用户令牌被拒绝；DSH 适配器能连到版本端点。这里不调用模型。

## 阶段 1：可信身份与 L0 证据

**产物**：每用户令牌、scope 类型、`evidence_events` 表、幂等 ingest API、DSH `session/event` 映射、事件来源标记、本地 spool 和最小审计。先记录用户消息与助手消息；工具结果按 [14](14-DSH适配器实施.md) 的事件映射处理。

**完成条件**：Agent A 和 Agent B 用同一用户令牌写入的事件归同一 scope；相同事件重放只存一份；同键不同内容报冲突；用户 B 的令牌或无令牌不能读写用户 A 的数据。检查使用本地构造事件，不调用模型。

## 阶段 2：用户显式记忆与跨 Agent 读取

**产物**：`memory_remember`、`memory_search`、`memory_get`，`memories/memory_evidence/revisions`，手动绑定最近用户消息证据，关键词检索与有界上下文。此时尚不需要自动提取；先完成真正的跨 Agent 闭环。

**完成条件**：用户向 Agent A 明确说“以后用中文回答”，Agent A 调用 remember 后，Agent B 能通过 search 和自动上下文看到；用户 B 不能看到；直接把助手编造的句子交给 remember 被拒绝。检查一次 DSH 本地闭环即可，不跑大量 API 样本。

## 阶段 3：自动 L1 提取

**产物**：窗口关闭、持久化作业、可配置模型客户端、结构化候选、来源校验、active/held 状态、有限重试和作业状态 API。默认只在会话结束提取一次；必要时才增加更细的边界识别。

**完成条件**：同一会话窗口的重复 flush 不重复提交；模型返回合法候选能引用真实用户事件；错误来源或推断候选不自动注入；模型不可用时原始证据和作业状态仍在。仅用一个已配置模型进行少量端到端调用，或使用固定响应检查校验规则；不开展模型选型海试。

## 阶段 4：纠错、遗忘和恢复

**产物**：`memory_correct`、`memory_forget`、版本冲突处理、历史修订、suppression 规则、索引重建命令、重启后作业恢复。普通遗忘不等于删除原始会话，返回值明确提示。

**完成条件**：纠错后下一次上下文不再包含旧值；遗忘后下一次搜索和注入都不可见；后台任务重跑不能从同一旧证据复活已遗忘记忆；重启后已提交 L0 与未完成任务仍存在。使用短路径检查，不要求全量基准。

## 阶段 5：交付与操作文档

**产物**：安装说明、DSH profile 配置、升级与迁移命令、备份／恢复说明、故障码、任务状态查看、索引重建、性能与用量日志示例。标明 Windows 本机已验证范围；其他平台只有实际运行后才写为支持。

**完成条件**：从空目录按文档可安装并完成阶段 2～4 的一条闭环；进程退出和重启后行为一致；部署状态、构建状态、运行状态分别记录。

## 依赖与顺序

```text
阶段 0 → 阶段 1 → 阶段 2 → 阶段 3 → 阶段 4 → 阶段 5
                    │            │
                    └── 首个可演示的同用户跨 Agent 记忆闭环
                                 └── 自动提取首次闭环
```

阶段 2 优先于自动 LLM 提取，因为它先验证最关键的共享边界、DSH 注入和读写协议，且无需调用模型。阶段 3 再增加自动化，不推倒阶段 2 的数据模型。

## 最小验证矩阵

| 风险 | 必要检查 | 证据 |
|---|---|---|
| scope 串读 | 两个不同用户、相同文本和 Agent 名称，交叉读取应拒绝 | 本地请求与响应 |
| 事件重复 | 同事件重放、不同正文同键冲突 | 数据库行数与错误码 |
| 证据冒名 | 助手输出伪装成用户事实 | 候选停在 held 或拒绝 |
| 纠错／遗忘滞后 | 修改后立即再搜索／compose | 返回内容不含旧记忆 |
| 断电／重启 | 已提交证据和队列重新加载 | 状态与作业 ID 一致 |
| DSH 插入位置 | 一条实际 Agent A→B 对话 | 运行日志与回答中的来源 ID |

这些检查是最短的实现验收，不是另设“测试阶段”。不要批量购买 API 调用来证明尚未达到的模型质量；如果后续发现真实召回问题，再选具体失败样本做针对性改进。

## 首版不声称的指标

不要声称达到 EverOS 或 Hindsight 的基准成绩、SOTA 准确率、中文最优分词、稳定的毫秒级延迟或生产多租户认证能力。首次交付只报告本机实现、实际运行的 DSH 路径和上述必要检查。历史项目的 LoCoMo/LongMemEval 结果不能转移为本项目结果。
