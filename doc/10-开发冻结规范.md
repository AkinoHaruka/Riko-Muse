## B. 第一版技术选择，不留二选一

| 编号 | 固定选择 | 不在 v1 实现 |
|---|---|---|
| D-01 | 独立 Rust `memoryd` 进程；本机 HTTP JSON 协议；DSH TypeScript 薄适配器 | Node FFI、把内核写成 TS |
| D-02 | SQLite WAL 是唯一规范存储，Rust `rusqlite` bundled SQLite；migration 文件固定版本 | Markdown 双向真相、Redis、Postgres |
| D-03 | SQLite FTS5 `unicode61` 处理拉丁文；另建 Unicode 二元字索引覆盖中文；索引均为派生状态 | embedding、图扩散、cross-encoder |
| D-04 | 每个 `(tenant_id,user_id)` 一个 256-bit 随机访问令牌；服务端由令牌哈希查出 scope | 从请求正文、Agent、preset、session 推断用户 |
| D-05 | 事件先同步入 L0，提取任务异步排队；仅 `turn/end` 或显式 flush 关窗 | 每条消息都调模型 |
| D-06 | L1 仅 `fact/preference/instruction/episode`；候选必须引用真实用户事件 | 自动 L2/L3、情感画像、跨证据推断 |
| D-07 | `active` 只接受原文可定位的用户明确表述；其他提取保留 `held` | LLM 自报高 confidence 直接入库 |
| D-08 | 自动上下文最多 5 条、2000 Unicode 标量字符，搜索路径不调用模型 | 无限历史注入 |
| D-09 | forget 即时排除记忆及派生索引；原始 L0 保留并明确告知 | 把 forget 描述成物理清除 |
| D-10 | 同一进程内 SQLite 作业轮询，单 worker 串行提取 | Redis 消费组或分布式锁 |

这里的数值是首版工程默认值，不冒充上游已验证的最优参数。统一定义在 `memory-contract` 的版本化默认配置中，避免多份硬编码。

## C. 账户与 DSH 的准确边界

内核支持多用户：不同用户拥有不同访问令牌，查询时仅根据令牌确定 `(tenant_id,user_id)`。同一用户在不同 DSH Agent 中使用同一个令牌，因而默认共享。一个 DSH 安装如果只服务一名用户，插件配置一个令牌即可。如果一个 DSH 进程同时服务多名用户，适配器必须从 DSH 提供的可信认证上下文选择对应令牌；当前本地源码调查还没有证明这个 Hook 可用，所以该部署模式在 v1 **不开放**，不能按 Agent preset 或用户输入猜身份。多个单用户 DSH 安装仍可接同一内核的不同用户账户，内核会隔离它们。

这满足 U-03/U-04，同时准确说明首版宿主支持边界。未来多用户 DSH 进程需单独接入经过核实的身份 API，不修改内核的 scope 原则。

## D. 权威数据与状态

- L0 事件是来源记录，包含宿主、会话、事件序号和消息角色。只追加，不以同键覆盖。
- 模型输出为 `candidate`。`candidate` 的 `source_event_id` 必须存在且属于认证用户。
- 自动 `active` 采用确定性窄规则：`quote` 必须是原始用户消息的完整连续子串；`claim` 必须与 quote 在折叠连续空白后相同；信息需满足 [13-算法与模型契约](13-算法与模型契约.md) 中的明确表述规则。其余进入 `held`。
- Agent 通过工具提出的 remember/correct/forget 必须绑定当前用户的最新原始消息；无匹配拒绝。用户确认不是 Agent 口头声称。
- `memories` 只容纳通过准入的记录和历史修订；`memory_candidates` 容纳 `candidate/held/rejected`。
- 只有 `active` 且当前有效的记忆能进入普通搜索和自动上下文。

## F. 弱模型执行规则

1. 每次只实现一张任务卡；不要同时重构 Rust 内核和 DSH 旧插件。
2. 先打开任务卡列出的上游源码和本项目契约，再改代码。源文件路径不存在时记录新路径，不猜。
3. 只在 `C:\TRAE\Agent-Memory` 新项目目录中写新代码；三个上游仓库及另一个工作区中的 DSH 旧插件是只读参考。
4. 遇到文档冲突、宿主身份无法证明、会改变 U-01～U-07 的要求时，停止该切片并写一段“冲突/证据/建议”。其他不依赖该点的切片继续做。
5. 不凭模型回答、README 宣传、基准截图宣称本项目通过验证。只报告实际编译、运行、DSH 接入和最小检查结果。
6. 不增加“更智能”的推断、自动改写或向量依赖来替代本文件的确定性规则。
