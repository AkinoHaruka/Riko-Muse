# 13 写入、准入、检索和模型契约

本文件给出 v1 可直接编码的算法。模型负责提出候选，不负责权限、作用域、状态转换或删除。Rust 内核是唯一提交者。算法输入已经由 [12-HTTP协议v1](12-HTTP协议v1.md) 的认证层绑定 scope。

## 1. 字符串与时间规范化

- ID 不做大小写折叠，按宿主原值保存，长度上限 256 字符。
- 记忆比较使用 Unicode NFKC、Unicode 小写、连续空白折叠为一个空格、首尾去空白，记为 `normalize_v1`；不删除中文标点，不做同义词替换，不把“喜欢”改写成“偏好”。
- `claim_sha256=SHA256(UTF8(kind + "\0" + normalize_v1(claim)))`。相同 scope、kind、hash 且 active 为精确重复。哈希不当作跨用户搜索键。
- quote 验证使用原始 UTF-8 字节的连续子串；保存 `start_byte/end_byte`。quote 允许前后空白修剪，但不得在内部改字。`claim` 只对 quote 做连续空白折叠，不转第三人称。
- 所有输入时间必须带时区；转 UTC RFC3339。发生时间未知保持 NULL，不用接收时间填充。

## 2. L0 接收伪代码

```text
scope := authenticate_bearer_token(request)
validate request fields, size, timestamp
key := (scope, origin.host_id, origin.session_id, event_seq)
BEGIN IMMEDIATE
  existing := SELECT evidence WHERE key
  if existing:
    if existing.content_sha256 == SHA256(content): return existing.id, already_recorded
    else: return EVENT_CONFLICT
  INSERT evidence with generated UUIDv7 and scope
  INSERT audit event_ingested (no content in detail_json)
COMMIT
return evidence_id, recorded
```

适配器不把 `source_kind=plugin` 的上下文送入提取窗口。为审计需要可将其作为 L0 system 事件保存，但 `source_kind=plugin` 绝不能成为 active 用户记忆的唯一来源。

## 3. 提取窗口与任务

一个 `flush(host,session,through_seq)` 对应 `window_key=v1:<through_seq>`。同 session 允许排入多个递增窗口，但 worker 只能领取最小的未完成窗口；若前窗失败，后窗保持 queued。当前窗口只读取 `(前一已成功 through_seq, 当前 through_seq]` 的事件；首窗下界为 -1。`flush` 如果比已排的最大 `through_seq` 小且不是同一 window_key，返回 409 `STATE_CONFLICT`。该序列从 `extraction_jobs` 持久表计算，不另建内存 cursor。

v1 一个 worker 串行处理所有用户的任务；每次 claim 一条最早的 due job。模型调用 timeout 30 s，lease 90 s，最大 3 次调用；重试延迟取 TencentDB 的 5/15/45 s 序列，第三次仍失败置 dead。请求取消时不修改已提交证据。任务按 `(tenant,user,host,session,window_key)` 幂等；提取结果保存候选时也使用 `(job_id,source_event_id,kind,quote_sha256)` 去重，避免 lease 重领造成重复。

窗口最大 100 个事件、32 KiB 提取输入文本；超过限制不得悄悄截断。适配器在累计 80 个新事件时安排一次显式 flush；若单次事件已超限，事件接收按协议 413 拒绝并给可诊断错误。长历史由多个窗口依次处理。这个限制是首版工程参数，可在实际运行发现需要后调整。

## 4. 模型输入与输出

输入包含按 seq 排序的事件，标注 `event_id,role,source_kind,time,text`；只给当前认证用户的本次窗口，不混入其他用户。仅 user role 的原始消息能支撑自动 active。system/tool/assistant 内容可作上下文，但不得被模型伪装成 user quote。Prompt 版本号 `extract_v1` 随任务保存，便于知道记录由哪个规则生成。

**增量（doc5/02，2026-09-25）**：输入序列化、32 KiB 分窗预算与响应 Schema 对所有 Prompt 版本冻结不变。Prompt 版本由作业行 `prompt_version` 持久化并分派：`extract_v1`（历史）、`extract_v2`（现行）、`extract_v3`（一候选一命题、最短连续原文，与 `admit_v2` 配套，见 doc5/02—03）。`prompt_version` 只选模型提示词；Rust 准入与查库提交规则由 `admission_version`（`admit_v1`/`admit_v2`，迁移 0004）选择，两者分工明确、分别按作业行分派，未知版本显式失败（确定性错误立即 dead），不得退回"最新规则"。旧版本字符串与行为冻结。

**系统提示词必须表达这些约束：**

```text
从给定对话提取可能对未来 Agent 有持续用途的用户事实、偏好、长期指令和事件。
只引用 role=user 且 source_kind=user 的 event_id。
quote 必须逐字复制同一条用户消息中的连续原文；不要改写、补充或拼接多条消息。
临时请求、假设、引用他人的话、助手推断不要提取。没有合格内容时输出空数组。
只输出 JSON，不输出解释或 Markdown。
```

模型响应 Schema：

```json
{"candidates":[{
  "source_event_id":"UUIDv7",
  "quote":"以后回答我用中文",
  "kind":"instruction",
  "occurred_at":null,
  "valid_until":null,
  "confidence":0.9
}]}
```

`confidence` 可缺省，仅作诊断；不能驱动准入。`kind` 四选一。每响应最多 20 条候选，quote 1～512 Unicode 标量字符。JSON 不合法、额外字段、来源 ID 不存在都记录该任务失败或候选 rejected；一个候选失败不丢掉同批其他有效候选。

## 5. 候选准入的确定性规则

依次判断，第一条不满足就停在 `held` 或 `rejected` 并写 reason code：

1. `source_event_id` 必须属于认证 scope、本次窗口、`role=user`、`source_kind=user`；否则 `rejected:BAD_SOURCE`。
2. quote 必须是该事件正文的连续原文子串；否则 `rejected:QUOTE_MISMATCH`。
3. quote 规范化后不得为空，长度 1～512；否则 `rejected:INVALID_QUOTE`。
4. `claim=normalize_whitespace(quote)`。**修订（doc5/02 §1，2026-09-25）**：响应 Schema 从未包含模型生成的独立 `claim` 字段——实际解析器（serde `deny_unknown_fields`）对含 `claim` 等额外字段的响应按严格 schema 报错，整个作业 BAD_JSON 失败，不存在"额外 claim 被忽略并 held:MODEL_PARAPHRASE"的路径；本条原表述作废，以实现为准。改写拒绝由 quote 逐字校验（规则 2 QUOTE_MISMATCH）与 admit_v2 的宽 quote/无主语规则（doc5/03 §2）承担。
5. quote 包含引号中的自述、反事实、假设、转述或明确一次性词（中文 `如果/假如/比如/这次/本次/今天先`；英文 `if/for example/this time/just today`）时，`held:CONTEXT_UNCERTAIN`。本规则故意保守；不尝试理解全部语言。
6. quote 满足下列明确表达之一方可自动 active：长期指令含 `以后/总是/从现在起/记住/always/from now on/remember`；稳定自我陈述以 `我叫/我是/我住在/我喜欢/我不喜欢/my name is/I am a/I am an/I live/I like/I dislike` 开始；职业表达只接受以 `我在` 开始且前 20 个 Unicode 标量字符中出现 `工作`。否则 `held:NOT_EXPLICIT`。匹配时先对前缀做大小写折叠，但保存的 quote 保持原样。
7. 敏感检测使用首版固定模式：`(?i)(password|passwd|密码)\s*[:=：]\s*\S{4,}`、`(?i)(api[_ -]?key|token)\s*[:=：]\s*[A-Za-z0-9_-]{12,}`、`sk-[A-Za-z0-9_-]{12,}`，以及字面词 `身份证/银行卡/诊断/病历`。命中即 `held:SENSITIVE`；单独谈论“token”或“密码”这个词不应被阻断。这是明显内容的保守闸门，不声称覆盖所有敏感数据；首版不自动注入 sensitive held。
8. 在同 scope、同 kind 找到完全相同 `claim_sha256` 的 active 记录：仅增加证据引用，不新建记忆。若匹配已 forgotten 记录的同一旧证据与 claim hash，`rejected:SUPPRESSED_SOURCE`。
9. 若已有同类 active 记录的明确属性键相同而值不同，`held:POSSIBLE_CONFLICT`。属性键仅识别：`name`=`我叫...` 或 `my name is ...`；`residence`=`我住在...` 或 `I live in ...`；`occupation`=`我在...工作`；`response_language`=`以后用...回答`。省略号取固定前后缀之间的非空文本，NFKC＋大小写折叠后比较。无法识别的内容不运行语义冲突识别器，可能存在两条 active；查询时都带时间和来源，不能宣称已自动消解矛盾。
10. 其余通过，单事务创建 active、来源、revision v1、审计、索引 dirty。

模型给出的 `occurred_at/valid_until` 只保存在候选层供以后复核；v1 自动 active 的两个时间列均设 NULL，不能由模型建议直接决定有效期。quote 自身包含的时间词仍保留在 claim 原文中。通过规则的候选 source_class 写为 `user_explicit`；其余按实际原因记为 `model_inferred` 等，但不进入 active。用户明确纠错走 `/correct`，优先于自动准入。复杂语义冲突与多证据 observation 是后续切片。

## 6. 搜索与排序

所有候选先 join `memories` 并强制 `tenant_id,user_id,status=active`、`valid_until > now OR NULL`；对 history 显式请求再按授权加入 superseded/expired，forgotten 永不返回。查询本身不调用模型。

- 拉丁文：将用户查询按 Unicode 字母／数字切词，转义 FTS5 特殊字符，构造 quoted terms。用 FTS5 BM25 顺序取最多 100 个 ID，再按规范表过滤。
- 中文／非空格文字：对 `normalize_v1(query)` 的连续汉字／字母数字段生成 Unicode 二元字组；在 `memory_grams` 中按匹配 gram 数降序取最多 100 个 ID。1 字查询只在当前 scope 最近 500 条 active claim 上做有界 `instr`，不做全库扫描。
- 混合查询若两路都有结果，用 Hindsight 源码中的 RRF 公式 `sum(1/(60+rank))` 融合；单路则保持该路排序。完全包含查询词的 claim 在同分时优先，之后按 `updated_at DESC, memory_id ASC` 固定顺序。
- 响应 `score` 对单路为 `1/rank`，对双路为 RRF 值，只用于同一查询的排序；不要解释为正确概率。空查询和 FTS 无效语法返回 400，不当作无结果。

写 FTS 的 `claim` 列与生成 `memory_grams` 时都使用 `normalize_v1(memories.claim)`；展示给用户时始终读取原始 `memories.claim`。`memory_grams` 的主键使重复二元字只保留一次，所以匹配数是“不同 gram 的命中数”，不是出现次数。

自动上下文在搜索前强制上限 5 条／2000 字符；长期指令先占最多 2 个名额，再填当前查询相关记录。每条带 memory ID、来源时间、原始 quote。文本组装过程遇到超长单条就整条跳过，不截断成可能失去否定词的句子。返回实际包含的 item IDs，便于追踪。

## 7. 纠错、遗忘和索引

纠错和遗忘只经 [12-HTTP协议v1](12-HTTP协议v1.md) 的最新用户证据检查后发生。事务完成后下一次读必须以规范状态为准。索引维护流程固定：规范事务先写 `index_state.dirty=1` 并提交；然后单独事务删除旧 FTS/grams 行、插入当前 active 行，完成后 `dirty=0,generation+1`。索引失败时保留 dirty，搜索可走有界规范表降级，并返回 `index_degraded=true`；绝不能从残留 FTS 行直接返回 forgotten 内容。重建索引按 scope 分批执行，最后用 active 规范表的 ID 集合核对。

forget 为旧 memory 的每个证据引用写 `suppressed_sources(evidence_id,claim_sha256)`；这样重跑同一旧窗口不会让它复活。用户以后在新事件中再次明确说出同一句话，可以形成新记忆；这是新证据，不属于被忘记的旧来源。
