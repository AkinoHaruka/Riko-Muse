# 01 目标与边界

## 1. 产品目标

Agent Memory 是一个独立的、Rust 优先的长期记忆内核。它把不同 Agent 与同一用户交互产生的可复用信息放在同一个用户记忆空间中，并在 Agent 需要时提供带来源的、大小受限的上下文。DSH 是第一位宿主；内核的公共协议不得使用 DSH 专有对象作数据主键，以便以后接入其他 Agent。

成功的最小闭环：用户在 DSH 的 Agent A 明确表达一项持续有效的偏好；事件进入内核并提取为有证据的记忆；同一用户的 Agent B 在相关问题中检索到该记忆；另一用户的 Agent 无法读取；用户纠错或遗忘后，后续注入即时反映最新状态。

## 2. 确定的身份模型

| 名称 | 含义 | 来源 | 权限作用 |
|---|---|---|---|
| `tenant_id` | 一个部署或组织的管理边界；单机首版可用固定部署 ID | 本项目决策 | 所有查询都绑定 |
| `user_id` | 服务端由该用户专属随机令牌查出的稳定 ID | `principals` 表 | 长期记忆的所有者与隔离边界 |
| `agent_id` | 发出／消费事件的 Agent ID | DSH 适配器 | 来源追踪、统计；默认不限制同用户读取 |
| `session_id` | 一段会话的 ID | DSH | 证据定位、幂等；不能替代用户 ID |
| `event_seq` | 会话内事件序号 | DSH | 证据定位、幂等 |

内核 scope 固定为 `(tenant_id, user_id)`，由每用户独立访问令牌在服务端确定。请求正文不接受用户 ID。同一 scope 的 Agent 默认读同一份可用记忆。Agent 身份保存在 `origin_agent_id` 和读取审计中，不进入首版默认读过滤条件。不同 `user_id` 即使名字、文本或 Agent ID 相同，也不能互读。空、未知、由模型文本猜出的用户身份一律拒绝读写。一个 DSH 进程若同时承载多名用户，必须等 DSH 可信身份接口得到验证后再启用该部署模式；多个单用户 DSH 进程可接同一内核的不同账户。

`workspace_id`、`project_id`、`task_id` 可作为检索上下文标签，但首版不用于缩小同一用户的默认共享范围。未来若增加项目私有记忆，必须新增清楚的权限层，不得重用这些标签暗中改变读权限。

## 3. 首版能力

- DSH 会话事件的幂等接收和持久化，至少包括用户消息、助手消息及其来源、时间和会话顺序。
- 从新证据提取候选事实、偏好、长期指令、事件；保留原文来源。可以没有候选，不能为每段对话强造记忆。
- 明确的候选／可用／冲突／失效状态；用户直接表达且可在证据中定位的稳定信息可自动成为可用记忆，含糊推断保留候选。
- 同用户跨 Agent 的检索；关键词与时间、来源过滤；结果携带记忆 ID 和证据引用。
- 有界自动上下文与按需搜索工具。自动注入只选当前有效、相关、未被遗忘的记录。
- 用户可通过 DSH 工具或管理接口查看、纠错和遗忘自己的记忆。
- SQLite 本地持久化、数据库迁移、索引重建、后台任务重试和基本运行状态。

## 4. 首版有意不做

- 旧 Riko／Companion 数据迁移。
- 跨用户共享、团队资产 ACL、Marketplace、组织管理面板。
- 把 TencentDB 的四个服务或 Hindsight 的 Postgres 集群原样搬入 Rust。
- 自动运行长期情感画像、主动关怀、知识图谱扩散、复杂多轮反思。
- 强制使用 embedding、cross-encoder 或外部向量服务。对应能力预留接口，只有出现明确需求和可运行实现时才加入。
- 大规模在线模型基准测试、API 参数海试和为了测试而进行的重复调用。

这些排除项只限制首版，不代表产品永远不支持。新增能力必须保持用户级隔离和来源可追踪。

## 5. 可信度的含义

“可用”表示内核允许把该记录用于检索和上下文，不表示内容在现实世界已被证明为真。来源分别记录 `user_explicit`、`assistant_observed`、`tool_output`、`model_inferred`、`manual_edit`。用户明说的自我事实可以按证据直接使用；助手输出或工具结果不会自动变成用户事实；模型推断要留在候选层。冲突时暂不自动覆盖旧记忆，先把冲突显示为待处理。

这里采用 TencentDB 的分层提取思想、Hindsight 的证据关联，以及 EverOS 的原始情节保留与派生索引分离。每个具体规则见 [04-数据模型与状态机](04-数据模型与状态机.md)。

## 6. 操作与成本目标

- 本地开发不需要 Redis、Postgres、LanceDB、容器编排或额外云服务。
- 事件接收不等待模型提取完成；模型失败时证据仍在，任务可重试。
- 默认按会话边界或显式 flush 批量提取，避免每条消息调用模型。
- 每次模型作业记录模型、输入范围、输出状态、耗时和用量；首版不设未经测量的“准确率”承诺。
- 检索不需要模型调用。自动上下文的候选数、字符数和耗时均有限额。
- 先完成一条端到端路径，再逐步增加检索和巩固能力。
