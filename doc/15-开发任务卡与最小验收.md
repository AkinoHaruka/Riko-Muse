# 15 开发任务卡与最小验收

任务卡为后续开发模型准备。按顺序完成，每卡只改列出的新项目目录，完成后提交可检查的产物与简短证据。默认不新开上游分支，不修改三个参考项目或旧 DSH 插件。任何任务卡的“完成”都指本地代码与指定闭环达到条件，不等于已部署到用户正式环境。

## 卡 0：建立新项目骨架

**读**：[10-开发冻结规范](10-开发冻结规范.md)、[03-架构与决策](03-架构与决策.md)。

**写**：新项目根 `Cargo.toml`、`crates/memory-contract`、`crates/memory-domain`、`crates/memory-store-sqlite`、`crates/memory-extract`、`crates/memory-recall`、`crates/memory-server`、`adapters/dsh`、`.gitignore`、许可和第三方声明。若当前工作区根不是 Git 仓库，可在新项目目录单独 `git init`，不要把三个上游仓库嵌套加入同一 Git 跟踪。

**做**：`memoryd --help`、`GET /v1/version`、读取空配置并打印非秘密有效值。不要先引入 Redis、向量库或 Web UI。

**完成证据**：Rust workspace 能编译；`memoryd` 只监听 loopback；version 响应为 1；三个参考仓库状态未被本卡改动。

## 卡 1：迁移、用户令牌和认证

**读**：[11-数据库v1迁移](11-数据库v1迁移.md)、[12-HTTP协议v1](12-HTTP协议v1.md) §1–2。

**写**：`migrations/0001_init.sql`、SQLite store 初始化、`principal add/rotate-token` CLI、bearer middleware、`GET /health`。

**做**：服务端由 token hash 查 scope；所有授权 API 的 handler 只拿 `AuthenticatedScope`，不读取用户 ID 参数。令牌文件权限设为当前用户可读。迁移成功后才启动 HTTP。

**完成证据**：用户 A/B 两个令牌查出不同 scope；无令牌 401；旧令牌轮换后 401；migration checksum 固定。无需模型 API。

## 卡 2：DSH 事件到 L0

**读**：[14-DSH适配器实施](14-DSH适配器实施.md) §1–3、当前 DSH `session/event` 源码。[EverOS 流水线](../EverOS/docs/how-memory-works.md)用于理解证据先落地。

**写**：`POST /evidence/events`、证据 repository、DSH 事件映射、本地 spool、按 session 顺序发送、启动重放。此卡不调用模型。

**完成证据**：同一事件两次发送只有一条；同键异文 409；A/B 事件不会混 scope；内核停机时事件进入 spool，重启后重放且无重复；插件来源消息不变成 user 证据。若 DSH Hook shape 与文档不同，把实际差异写回 [14](14-DSH适配器实施.md)。

## 卡 3：手工记忆、搜索和 Agent A→B

**读**：[12-HTTP协议v1](12-HTTP协议v1.md) §5、§7；[13-算法与模型契约](13-算法与模型契约.md) §1、§6；当前 DSH `defineTool` 和 `agent/pre-step` 用法。

**写**：`remember/get/search/context` HTTP、memory 与证据事务、FTS5 与二元字索引、DSH 五个工具中的 remember/search/get、自动上下文 Hook。

**完成证据**：同一用户 Agent A 记“以后回答我用中文”，Agent B 检索与上下文可见；用户 B 的令牌用同一 memory ID 返回 404；无最近用户事件的 remember 失败；上下文不会重复注入。此卡是首个完整可演示闭环，仍不需要模型提取。

## 卡 4：提取作业与自动候选

**读**：[02-上游源码对照](02-上游源码对照.md) 的三条流水线来源、[13-算法与模型契约](13-算法与模型契约.md) §3–5。特别打开 TencentDB L1 Prompt 的 `source_message_ids` 和 Hindsight 的来源关系实现；不直接复制 Prompt。

**写**：`flush/jobs` API、持久任务／lease、模型客户端、`extract_v1` Prompt、JSON 校验、candidate/held/rejected、自动窄规则 active。模型 key 来自文件或宿主凭据，不进日志。

**完成证据**：同窗口重复 flush 同一 job；合法 user quote active；助手自称用户事实不能 active；模型坏 JSON 不丢 L0；3 次失败后 dead。用固定响应检验准入，外部模型只做一次真实闭环调用以确认连通，不做模型比较或大规模基准。

## 卡 5：纠错、遗忘、索引恢复

**读**：[04-数据模型与状态机](04-数据模型与状态机.md)、[11-数据库v1迁移](11-数据库v1迁移.md) §3、[12-HTTP协议v1](12-HTTP协议v1.md) §6。

**写**：correct/forget HTTP、DSH 工具、revision、suppressed_sources、索引 dirty/rebuild、`memoryd doctor/backup/rebuild-index`。

**完成证据**：纠错后新上下文只见新值且旧值可按历史查看；forget 提交后普通搜索和自动上下文立即看不到；相同旧任务重放不能复活；索引删除后重建只恢复 active；原始 L0 保留且操作响应告知用户。

## 卡 6：交付说明

**读**：[07-开发顺序与验收](07-开发顺序与验收.md)、[08-开放事项与变更规则](08-开放事项与变更规则.md)。

**写**：新项目 `README.md`、本机安装、DSH 独立 profile 装载、principal 创建、令牌文件配置、备份／恢复、错误码和已验证平台。来源许可与第三方说明保持准确。

**完成证据**：从空库跟 README 可达到卡 3～5 的一条闭环；汇报已改文件、构建状态、实际运行状态、未实现项。不要把本地成功说成已推送、部署或对其他 DSH 用户开放。

## 最小验收记录格式

每卡提交以下 8 行即可；不要为了交报告额外跑大规模 API 测试：

```text
任务卡：
代码 commit / 工作区状态：
实际修改的文件：
参照的上游文件与 commit：
构建命令与结果：
本卡必要检查与结果：
DSH 实际运行证据（若适用）：
未验证或与文档不同之处：
```

如果发现设计无法按当前 DSH 接口实现，先记录确切源码位置和失败点，再只改胶水层或更新对应契约。不要用另一个 Agent ID、会话 ID 或模型文本替代用户身份。
