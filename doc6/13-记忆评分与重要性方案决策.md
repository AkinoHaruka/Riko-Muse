# 13｜记忆评分与重要性方案决策

状态：**已作为 D6 的实现边界采纳**（2026-09-28）。普通记忆没有统一可信度/重要性分数；本阶段没有引入普通记忆 importance 字段或通用打分器。该决定已落实为“不以分数取代证据、准入和检索相关性”的范围约束，不代表意见置信度或排序校准已经完成。

## 1. 决策

1. **普通记忆默认不设统一的可信度/重要性总分。** 真实性、重要性、意见置信度、检索相关性和 Agent 执行质量是不同维度，不能合成一个分数。
2. **通用记忆的 confidence 仅适用于意见类记录。** 它表达对该意见判断的置信估计，不证明意见有证据，也不代表其重要程度。若采用，先在有可判定结果或可靠人工标签的意见样本上验证校准；未校准时只作诊断。校准后也只能承担另行定义的意见展示/排序用途，不能代替证据或单独决定记忆准入、拒绝和删除。
3. **importance/priority 仅在有明确排序或上下文预算需求时引入。** 字段必须明确定义为重要性，并与 confidence 分开。它可以按明确策略影响展示次序或选择建议，不能单独改变事实可信度、记忆状态或遗忘结果。
4. **专用对象可保留专用指标。** Agent 执行案例、技能等对象上的质量、置信度或成熟度分数，限定在各自对象与用途内，不推广成普通用户记忆的通用评分。
5. **没有清楚的产品动作依赖某个分数时，不存该分数。** 评分字段必须能说明“谁使用它、改变什么行为、如何验证有帮助”。

时间新鲜度是独立的排序因子，不是 `importance`、`confidence` 或记忆有效状态。按 [12 §6](12-遗忘、过期与时间衰减方案决策.md)，首版只给 episode 的 Retrieved 排序加有界 recency 乘数；不能据此激活/遗忘记忆，也不能让稳定记忆因旧而降级。

## 2. 三个上游方案的得失

| 上游做法 | 分数含义 | 优点 | 局限与源码现状 |
|---|---|---|---|
| Hindsight 旧版 `confidence_score` | opinion 记录的 0–1 置信值 | 能显式表示某项观点判断的不确定性，便于后续诊断。 | 置信值不等于证据强度，若未经校准容易造成伪精确。当前检查的 Hindsight 源码已删除 opinion 类型及该字段；它是历史设计，不是当前可直接采用的机制。 |
| TencentDB `priority` | L1 记忆的重要性/处理优先级，缺失时默认 50 | 简单、直观，便于抽取时表达重要程度，并可用于有预算时的优先级策略。 | 它不代表记忆真实或模型确信；不同记忆类型使用不同评分区间，低分过滤还会把模型评分误差变成信息遗漏。默认 50 是缺省值，不是经过校准的中性真值。 |
| EverOS 通用记忆不设统一分 | 普通 episode 等没有统一 importance/confidence 字段 | 不把不同含义压成一个数，减少维护和虚假精确。 | 若产品需要按重要性分配有限展示空间，就需要另设明确的选择机制。EverOS 的 Agent case/skill 有专用 `quality_score`、`confidence`、`maturity_score`；因此准确说法是“普通记忆无统一分”，而非“系统任何对象都无评分”。 |

相关源码位置：Hindsight 的 opinion/置信字段删除迁移 `hindsight/hindsight-api-slim/hindsight_api/alembic/versions/g2h3i4j5k6l7_remove_opinion_fact_type.py`；TencentDB 的分类型评分提示 `tencentdb-agent-memory/MemoryCore/src/core/prompts/l1-extraction.ts`、缺省值 `tencentdb-agent-memory/MemoryCore/src/core/record/l1-extractor.ts`；EverOS 的 Agent case/skill 指标见 `EverOS/src/everos/memory/models.py` 与 `EverOS/src/everos/infra/persistence/markdown/mds/agent_skill.py`。

## 3. 选择规则

| 要解决的问题 | 选择 |
|---|---|
| 想知道一条内容是否有来源、是否可核实 | 检查来源、证据与确认状态。confidence 或 priority 都不能代替这些信息。 |
| 想表示某项意见判断有多大把握 | 仅对 opinion 使用 confidence；先验证分数与实际正确率的校准关系，再决定是否用于产品行为。 |
| 想在有限上下文或列表中优先展示重要内容 | 使用独立 importance/priority，并明确评分主体、使用场景、默认值及低分处理方式。 |
| 没有上述具体需求 | 不增加通用评分字段；用检索相关性、对象类型或明确的用户选择解决对应问题。 |

## 4. 对本阶段的约束

- 本文确定评分语义与引入条件，不授权新增数据库字段、API、排序公式或阈值。
- Hindsight 当前已移除的 opinion `confidence_score` 不作为当前实现基线；若将来恢复意见置信度，须单独定义对象范围、标注来源和校准验收。
- TencentDB 的 `priority` 不作为可信度分复制；若将来需要重要性排序，须以独立字段和明确消费规则提出实现任务。
- EverOS 专用 Agent 指标不外推到通用用户记忆。
- 召回相似度、BM25、RRF、reranker 分数表达检索相关性，不是事实可信度或重要性。
- episode 的 recency 因子只表达时间新鲜度；它独立于重要性和置信度，不能写成全局 `memory_score`。
