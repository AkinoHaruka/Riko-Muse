## 4. 发现的配置与验证风险

1. **验证模式与 Auto Dream 开关语义不一致。** 关闭 `dream.enabled` 会禁用 runner claim；显式 trigger 仍能入队，但不能被 DSH 执行。本轮为执行唯一 manual job 临时开启了 `dream.enabled`，并用新鲜合成事件确保 Auto Dream 的 15 分钟 idle 条件未满足。若后续要求“定时调度关闭、manual runner 仍可运行”，应先拆分 scheduler 开关与 runner 执行能力，并做确定性验证；否则复验需重用本轮的短时 guard 方法。
2. **Embedding 故障会快速自动重领。** `EMBEDDING_UNAVAILABLE` 路径 5 秒后重新调度；本轮观察到 14 个 generation/attempt。它违反本轮“串行、无自动重试、错误后停止”的验证约束；继续真实 API 测试前应为 provider failure 设置人工重试/熔断或单次尝试上限，并确保触发限额后 runner 停止 claim。
3. **Provider 状态丢失。** embedding client 在非 2xx 时有 HTTP 状态，但 Dream 层统一映射成 `EMBEDDING_UNAVAILABLE`，日志/作业诊断没有区分 401/403、429、超时和其他响应。应保存安全的 status/error class（不记录凭据或响应正文），并在 429/凭据错误时停止本轮 runner。
4. **凭据加载未验证。** 临时脚本把 Google endpoint 的下一整行作为 key 写入文件，而非解析有明确边界的凭据值；本轮不证明 Gemini 请求认证成功。后续应先完成本地解析与格式断言，再进行一次受控调用；不得直接复用本轮失败配置。
5. **Google 检索任务类型尚未接线。** 当前 `EmbeddingClient` 请求体只有 `model` 与 `input`（`agent-memory/crates/memory-server/src/embedding.rs:102-109`），没有区分 document/query task type。Google 文档为 `gemini-embedding-001` 提供检索任务类型说明：[Gemini Embeddings](https://ai.google.dev/gemini-api/docs/embeddings)。本轮没有评估该差异对向量召回的影响，也不能宣称检索质量达标。
