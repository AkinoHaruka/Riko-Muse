范围：使用 `模型.txt` 中配置的真实模型端点，针对 D6 Dream 提取格式与 embedding 相似度做少量 API 探针。仅使用合成文本；未启动 memoryd/DSH 完整链路，未打开任何数据库，未修改代码。

## 1. 结论摘要

- **真实 API 连通：已验证到端点级。** Gemini chat、Gemini embedding 和 SiliconFlow/Qwen 均有真实服务端响应；其中 SiliconFlow 第一次请求在客户端 60 秒超时，等待后单次重试成功。
- **D6 提取格式：Gemini 单样本通过结构检查。** 一次合成输入返回一个 JSON 候选；JSON 可解析、无 Markdown 围栏，证据 ID 与 quote 精确匹配，claim 非空，kind 为预期的 `preference`。
- **Qwen 提取：服务响应但该次候选不可用。** 重试响应包含正确证据 ID、逐字 quote 和 `instruction` kind，但 `claim` 是字面量 `"..."`，不能作为有效记忆候选。
- **Embedding：API 可用，语义排序样本不理想。** 一个相关问题与一个无关文本的对比中，相关项相似度反而较低；样本量太小，不能据此判断总体召回质量，也不能把它当成模型或实现的定论。
- **memoryd/DSH 集成、Dream/Rust 提交、语义质量和生产效果：仍未验证。** 本轮不是应用端到端验证。

## 2. 限流与调用范围

调用按串行执行，没有并发请求或自动重试；Gemini 两次推理请求之间间隔至少 5 秒，SiliconFlow 超时后等待至少 30 秒才手动重试一次。Embedding 的 3 条输入在单个 batch 请求中发送。

## 3. 定向样本与观察

### 3.1 Dream 提取格式探针

Gemini 请求使用当前 DSH Dream runner 中的提取指令与 JSON Schema 约束，代码位置为 `agent-memory/adapters/dsh/src/dream-runner.ts:110-122`。输入是合成的用户偏好事件，携带合成 evidence ID。

检查结果：

- 返回 JSON 可以解析，未包 Markdown 围栏；
- 返回 1 条 candidate；
- `evidence_id` 与合成输入相同；
- `quote` 与输入原文逐字相同；
- `claim` 非空，`kind=preference`；
- 只验证了单条格式样本，没有经过 Rust admission、embedding 去重/合并或数据库提交。

Qwen 的一次成功 HTTP 响应使用相同用途的受限提取输入。它给出了精确 evidence ID、quote 和预期 kind，但 claim 为占位字符串 `"..."`，因此本次候选在内容层面不合格。首次请求的超时不代表服务端拒绝，也不代表请求必然未执行。

### 3.2 Embedding 相似度探针

向 `gemini-embedding-001` 的单个 batch 请求提交以下三条合成文本：

1. 记忆：她的职业是软件工程师，主要负责后端系统开发。
2. 相关问题：她从事什么工作？
3. 无关文本：她喜欢周末烤面包。

观测到：`cos(memory, related_query)=0.6921`，`cos(memory, unrelated_text)=0.7720`。在这一个小样本中，无关文本排序更高。该探针只有一个记忆、一个相关问句和一个无关对照；未做多类、多语料或重复稳定性测试，**只能记录为一次反例观察，不能外推成总体效果结论**。本轮也没有评估 task type、向量归一化、候选集分布或完整召回排序链路。

## 7. 第二轮：OpenRouter 与官方 DSH 应用级验证（2026-09-27）

### 7.1 范围与限流

- 使用 `模型.txt` 中的 OpenRouter Chat Completions 配置，模型 ID 为 `stealth/space-bunny-alpha`。凭据只在当前进程环境变量中使用，没有复制到配置、仓库或报告。
- 使用全新 `%TEMP%/agent-memory-openrouter-*` schema 11 数据库、一个 synthetic principal 和全新 DSH home；未打开 dana/realtest 或其他已有用户库。
- DSH provider 配置 `maxRetries=0`；本轮不做自动重试。OpenRouter 直连接口探针为 1 次成功请求；随后 DSH headless 完整执行 1 次。DSH 内部请求总数没有从 provider 侧遥测单独计量，因此不把 CLI 调用次数冒充精确 HTTP 请求数。
- 真实 DSH 一次性进程使用实际 OpenRouter provider。运行约 12.1 秒，模型回答只含合成测试代号与 Soul 标记；没有真实用户正文。

### 7.2 预检与真实 API

OpenRouter 直连 Chat Completions 探针返回 HTTP 200，耗时约 6.508 秒，usage 为 prompt/completion 255/67 tokens。输出 JSON 可解析、无 Markdown 围栏；candidate 数为 1，合成 evidence ID 与 quote 精确，claim 非空，kind 为 `preference`。这只证明所测模型的单样本协议形状。

DSH 配置预检期间发现两项 Harness 约束，均在真实请求前修正：`retryableCodes` 不能是空数组（保留非空 `RATE_LIMIT` 配置，同时 `maxRetries=0`），该模型未声明支持 `reasoningEffort=low`（移除显式 reasoning effort）。两次预检失败都没有向模型端点发请求；修正后的 `--dump-config` 通过。最终 DSH 调用退出码为 0，模型回答：

```text

```

### 7.3 memoryd + DSH 合成闭环

隔离库启动于临时 loopback 端口，`/v1/version` 返回 protocol 1、schema 11，`/v1/health` 为 `ok`。内核未配置 chat/embedding provider，并显式设置 `dream.enabled=false`，因此这次运行没有排队 Dream，也没有触发向量调用。

预置与调用结果：

| 步骤 | 结果 |
|---|---|
| 合成最新用户事件 `POST /v1/evidence/events` | 201；Rust 返回 evidence ID |
| 基于该事件调用 `POST /v1/memories/remember` | 201；创建 1 条 fact |
| `POST /v1/resident/pins` | 201；固定该记忆 |
| `PUT /v1/soul`，agent=`openrouter-validation-agent` | 201；回读正文与写入完全一致 |

| 官方 DSH headless + OpenRouter | 退出码 0；实际模型输出 Soul 标记和仅在 resident 记忆中的随机代号 |

DSH 退出排空后，隔离库中有 4 条 evidence、1 条 memory、1 条 resident pin、1 条 Soul revision 和 2 个等待提取的旧版 extraction job；spool 的 5 条 event 记录均有 5 条 receipt。等待提取作业是预期结果：本次 memoryd 未配置旧 extraction worker，不代表 Dream 提取成功。`PRAGMA foreign_key_check` 返回 0 项。验证结束后 memoryd 已停止。

这是一次真实 DSH + 真实 OpenRouter 的受控行为样本：同一 DSH Agent 的 Soul 与 Resident 可从内核读出并影响模型回答；它不是 Alice/Bob 多 scope 矩阵，也没有抓取 OpenRouter 收到的原始 request body，因此不单独替代官方 DSH mock 下的 wire/role 证据。
