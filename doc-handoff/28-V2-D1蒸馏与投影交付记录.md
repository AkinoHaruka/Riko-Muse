## 1. 交付内容

规范：[doc7/06-V2-D1-蒸馏与投影施工规范.md](../doc7/06-V2-D1-蒸馏与投影施工规范.md)（动工前先写）。

V2 文档 03 要求「三个不同产物」，本卡逐一落地，**没有**把四个 kind 查询包装成蒸馏：

| 产物 | 实现 |
|---|---|
| 精炼常驻 `compact_memory` | 按优先级 + 双预算（24 条 / 1200 字符）从**当前可见**记忆装配；与 Resident pin 去重；整体替换、版本递增 |
| 四分面 `facets` | `facet_v1` 确定性规则：experience / opinions / reflections / world，同一条可进多个分面 |
| 只读 Markdown 投影 | `memoryd export` 渲染 COMPACT.md + bank/*.md + manifest.json，先写临时目录再整体替换 |

**多源概括（模型生成的段落级综述）不在本卡**：V2 文档 03 §2 把它归给 upkeep/Dream 的版本化生成器。
本卡只交付确定性摘录层；`observed_or_inferred` 与 `generator_version` 字段已就位，接入生成器不需要改表。

### 1.1 迁移 0016（`0016_derived_views.sql`）

- `derived_items`：compact 与四分面共用，`document_kind` 区分；逐条 `generator_version`、
  `source_fingerprint`、`batch_version`、`status(active/stale/removed)`。
- `derived_item_sources`：逐条来源 (memory_id, memory_version, claim_sha256)，复合主键；
  `ON DELETE CASCADE` 挂在 items 上。
- `derived_exports`：只读投影的 manifest（**正文不入库**）。
- `0001`—`0015` 未改动；`SCHEMA_VERSION 15 → 16`；`d69_tests` 的冻结历史断言同步为 16。

### 1.2 分面规则 `facet_v1`（确定性、本项目选择）

| 分面 | 判据 |
|---|---|
| experience | `kind='episode'`；或 `kind='fact' AND occurred_at IS NOT NULL` |
| opinions | `kind='preference'`；或 `kind='instruction'` 且正文含偏好标记 |
| reflections | `status='superseded'` **且**存在 `memory_relations` 取代边 |
| world | `kind='fact'`；或 `kind='instruction'` |

刻意**不**采用的原稿简化（写进代码注释）：不把 kind 一对一映射到分面；不把「有 supersedes 链」
直接等于反思；不把 `valid_until IS NULL` 当长期有效——有效期由 V2-P1 的可见性谓词决定。

### 1.3 失效与闭包

- **读路径即时屏蔽**（不等重建）：条目的每条来源都要满足「记忆当前可见 ∧ version/claim_sha256 未变」，
  否则该条目不返回并计入 `skipped_stale`。reflections 的来源按构造就是 superseded，
  走历史宽容路径（只核版本/哈希与未被遗忘）。
- **purge 闭包**：`purge_confirm` 第 7.5 步删该记忆的 `derived_item_sources` 行，
  再删因此变成零来源的孤立条目——不允许存在无法定位的派生正文。
- 派生候选复用 V2-P1 的 `visible_memory_sql`，不另写一套可见性口径。

## 4. 本轮修出的缺陷（都在本卡实施过程中被自己抓到）

| # | 位置 | 现象 | 修复 |
|---|---|---|---|
| 1 | 迁移 0016 初稿 | `derived_item_sources` 的复合外键在父表找不到匹配唯一约束 → 任何 purge 都报 `foreign key mismatch`（6 个既有测试同时失败） | `derived_items` 补 `UNIQUE (tenant_id, user_id, id)` |
| 2 | `derived_refresh` 候选查询 | 绑定顺序写成 (now, read_json, tenant, user, domain)，与 SQL 文本顺序不符 → 候选集恒空、派生视图全空（7 个新测试同时失败） | 改为 (tenant, user, domain, now, read_json)；沿用「谓词只用无名 `?`」纪律 |
| 3 | `GET /v1/facets` | 先校验后归一化，导致 `?kind=world` 被 400 拒绝（与自己的错误提示矛盾） | 先补 `facet_` 前缀再校验 |
| 4 | `v2_d1_tests` 第 4 项 | 断言「重建后条目消失」，但来源只是版本前移、内容未变 → 重建**应当**重新派生 | 改为三段正确断言：改版本→屏蔽→重建按新版本复现→来源真失效→重建消失 |
