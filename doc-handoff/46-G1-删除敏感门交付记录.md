## 2. 主语门联动的最终行为

原规则中（`lib.rs` 约 1156 行），`unclear_subject` 判定如下：
```rust
fn unclear_subject(quote: &str) -> bool {
    let q = quote.trim().to_lowercase();
    !has_first_person_subject(&q) && !has_third_person_marker(quote)
}
```
原本注释为：*「已识别第三人主语的不在此停（继续到 THIRD_PARTY）」*。

在本次删除敏感门后：
1. **主语明确的第三人陈述**（例如含「我姐」「我哥」「我妈」「我们家小孩」等已识别第三人主语，或 claim 以「用户」为主语的改写）：
   - 在规则 6 `unclear_subject` 不被拦截（主语明确，不属于 `UNCLEAR_SUBJECT`）；
   - 由于规则 9 `THIRD_PARTY` 已经删除，陈述不会在此被 held；
   - 随后进入后续结构性规则正常裁决：若命中显式句式（或 claim 符合改写规范），则可直接成为 **`Active`**；若句式不符合要求，则按后续规则裁决（如 `NOT_EXPLICIT` 或 `TEMPORAL`）。
2. **主语不明的陈述**（既无第一人称主语也无已识别第三人主语，如「平时主要写 Rust」「老笔记本电池坏了」）：
   - `unclear_subject` 依然返回 `true`，继续在规则 6 稳定输出 **`Held("UNCLEAR_SUBJECT")`**。
3. **结构规则保持完备**：
   - `UNCLEAR_SUBJECT`、`CONTEXT_UNCERTAIN`、`NON_MINIMAL_QUOTE`、`MULTI_CLAIM`、`TEMPORAL`、`NOT_EXPLICIT`、`KIND_MISMATCH`、`BAD_SOURCE`、`QUOTE_MISMATCH`、`INVALID_QUOTE` 结构门全部原样保留。
