## 3. V2-1 事件线与可靠性（真实 DSH 闭环 ✅）

官方形状（已核对 `packages/core/session/src/types.ts`）：`event.seq` 连续非负整数、`event.time` **Unix 毫秒数**、`user/message` 的 `data` 即 `UserMessage`、`assistant/message` 与 `tool/result` 正文在 `data.message`。

实现：回调只进有界内存队列（1024 条 / 8 MiB，满则记 `CAPTURE_GAP` 拒收）→ 单一异步写入者 `appendFileSync` + `fsyncSync`，确认落盘后才进发送链 → 同 session 顺序发送 → 内核 200/201 的 `evidence_id` 写进 `receipts.jsonl` 才算 ack → `turn/end` 的 flush 等该 session 前序全部 ack。失败分类：可恢复（离线/超时/429/5xx）指数退避重试；401 暂停该令牌全部出站；400/409 永久停该 session 并记 opId/requestId。`cursors.json` 原子写；启动时用官方 `ctx.sessionQuery.readEvent` 对已知 session 定点对账（上限 500 条 / 30 秒），失败记 `CAPTURE_GAP`。

**实测输出（真实 headless 会话，两次独立 session）**

```
evidence_events：
('01a0d463…','session-6e7feeee…', 8, 'user','user','只回复ok')
('01a0d464…','session-4866f668…', 8, 'user','user','只回复ok')

spool/events.jsonl：event op + flush op（flush:8，同一 session 顺序）
spool/receipts.jsonl：{"opId":"…/8","kind":"event","evidenceId":"01a0d463…"}
                      {"opId":"…/flush:8","kind":"flush"}          ← flush 在 event 之后 ack
spool/cursors.json：{"session-6e7feeee…":8,"session-4866f668…":8}
```
