## 2. 依赖与构建

官方 clone 用 corepack 固定 pnpm 11.7.0（系统 pnpm 是 10.33，不能直接用）：

```bash
cd /c/TRAE/Agent-Memory/deepseek-harness
corepack pnpm --version          # 11.7.0
corepack pnpm install --ignore-scripts   # 必须 --ignore-scripts：lefthook postinstall 在本机被 safe-delete 钩子挡住
corepack pnpm run build:lib:host         # tsc -b tsconfig.host.json + tsdown（约 1m30s）
```

包没有自己的 `build` 脚本，`pnpm --filter X... run build` 会报 `ERR_PNPM_RECURSIVE_RUN_NO_SCRIPT`；只有根脚本 `build:lib:host` / `build:lib` / `build` 能构建。根 `.npmrc` 已追加 `verify-deps-before-run=false`，否则每次 `pnpm run` 都会重跑 install 并被 lefthook 拖死。

适配器：

```bash
cd /c/TRAE/Agent-Memory/agent-memory/adapters/dsh
npm install                       # file: 链接已在 package.json devDependencies 里
./node_modules/.bin/tsc --noEmit -p tsconfig.json   # 对真实 DSH lib 类型检查
./node_modules/.bin/tsc -p tsconfig.json            # 产出 dist/
```

`package.json` 的 `devDependencies` 用 `file:../../../deepseek-harness/...` 指向官方 clone 的五个包（cordis / tools / llm / session / agent），因此**必须先 `build:lib:host`**，否则类型解析不到 `lib/types/*.d.ts`。

Rust：

```bash
cd /c/TRAE/Agent-Memory/agent-memory
cargo build --workspace
cargo test --workspace            # 25 passed
```

## 3. 运行三件套

### 3.1 内核 memoryd

```bash
cd /c/TRAE/Agent-Memory/agent-memory
./target/debug/memoryd serve --config "C:/Users/shen_/AppData/Local/AgentMemory/v2/alice/config.toml"
# 校验：curl -s http://127.0.0.1:8791/v1/version
# 期望 {"protocol_version":1,"schema_version":2,"build":"dev"}
```

`config.toml` 只有非秘密项：`listen_addr=127.0.0.1:8791`、`db_path`、绝对 `migrations_dir`。令牌用 `memoryd principal add --tenant local --user alice --token-out <file> --db <db>` 生成过一次，不要重复 add（会拒绝覆盖）。

### 3.2 本地假模型（**仅测试装置**）

```bash
node "C:/Users/shen_/AppData/Local/AgentMemory/v2/mock-model.mjs"
# curl -X POST http://127.0.0.1:3977/anthropic/messages -H 'content-type: application/json' \
#   -d '{"model":"m","messages":[{"role":"user","content":[{"type":"text","text":"ping"}]}]}'
```

协议说 Anthropic Messages SSE（已核对 `packages/llm/llm-deepseek/src/translate.ts`）：`message_start` → `content_block_start/delta/stop` → `message_delta`（stop_reason）→ `message_stop`。路由到本机靠环境变量 `DEEPSEEK_BASE_URL=http://127.0.0.1:3977/anthropic`（见 `llm-deepseek/src/config.ts` 的 `BASE_URL_ENV`）。脚本按最近一条 user 文本关键词决定行为：

| 关键词 | 行为 |
|---|---|
| `记住指令` | `memory_remember{quote:"以后回答我用中文",kind:"instruction"}` |
| `搜索一下` | `memory_search{query:"中文"}` |
| `取记忆 <id>` | `memory_get{id}` |
| `纠错流程` | 先 search 拿版本 → `memory_correct`（版本从 tool_result 解析） |
| `遗忘流程` | 先 search 拿版本 → `memory_forget{target_quote:"以后回答我用英文"}` |
| 其他 | 纯文本，附带「是否看到记忆注入 + tools 数量」 |

每个请求把可见工具名与 `sawPluginMemory` 写入 `mock-state.json`，供断言用。

### 3.3 DSH 启动

```bash
cd /c/TRAE/Agent-Memory/deepseek-harness

DEEPSEEK_BASE_URL=http://127.0.0.1:3977/anthropic \
DSH_HOME="C:/Users/shen_/AppData/Local/AgentMemory/v2/dsh-home" \
```

## 4. 故障定位（本机已踩过的坑）

| 现象 | 原因与处理 |
|---|---|
| `cargo build` 链接报 LNK1104（exe 被占用） | 后台 `memoryd` 占着 `target/debug/memoryd.exe`；先 `taskkill //F //PID <8791 监听者>` 再编译 |
| `corepack pnpm install` 在 lefthook postinstall 失败 | 用 `--ignore-scripts`；若报 stale lock，把 `.git/dsh-lefthook-install.lock` 改名（本机 `rm` 会被 safe-delete 钩子拦截，用 python `os.replace`） |
| `pnpm --filter ... run build` 报 NO_SCRIPT | 包级无 build 脚本，改用根 `build:lib:host` |
| 适配器 tsc 找不到 `@deepseek-ai/*` 类型 | 官方 clone 没构建；先 `corepack pnpm run build:lib:host` |
| `mock-model.mjs` 写文件报 `c:\C:\Users\...` | Windows 下 `new URL().pathname` 带前导斜杠；已用 `fileURLToPath` 修好，别再改回去 |
| 模型调用 `MISSING_CREDENTIAL` | 随便给个 `DEEPSEEK_API_KEY` 值即可过门（headless 无真实鉴权） |
| 会话里没有 L0 | 查 `event.time` 是否数字毫秒、`source.kind==='user'`、spool 是否有 op、receipts 是否含 `evidence_id` |
