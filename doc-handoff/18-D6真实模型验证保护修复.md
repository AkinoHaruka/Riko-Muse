## 2. 修改

### 2.1 Auto Dream 开关与手动 runner

`dream.enabled` 在配置示例与 doc6/10 中定义为 Auto Dream 定时调度开关。此前 `/v1/dream/runner/claim` 也检查该值，导致 `enabled=false` 时手动 trigger 虽可入队，却无法由合法 DSH runner 执行。

现在该开关只控制定时 scheduler；显式 manual/compact/custom 作业仍可由在线、已注册且具备所需能力的 runner 领取。embedding 未配置时仍返回 `missing_embedding` 并保留作业，不启动模型链。全局服务停机与 provider 可用性仍是独立条件。

新增内核级回归用例：配置 `dream.enabled=false`，写入合成 L0 事件、创建 manual trigger、注册 runner 后，直接调用 claim handler，确认其返回 `claimed`；再模拟 `SUBAGENT_FAILED`，确认作业落为 `provider_wait` 且下次运行时间至少 23 小时后。

### 2.2 Embedding 安全错误分类与冷却

- `EmbeddingError` 对 HTTP 非成功响应保留状态码；job 的 `error_code` 可区分 `EMBED_HTTP_401`、`EMBED_HTTP_403`、`EMBED_HTTP_429` 等状态。超时、传输错误、坏响应、维度不符和向量错误也各有固定安全类别。
- 不持久化 provider 响应正文、请求 URL、header、key 或 reqwest 原始错误；`Display` 不再输出传输错误内文。
- Dream candidate adjudication、manual redecision 和语义索引遇到 embedding 错误时，作业写入 `provider_wait`，保留冻结输入/证据分配，`run_after` 设为 24 小时后；本次失败后不会在几秒内重新请求 Gemini。
- embedding 的诊断码沿 Dream job/语义 job 现有 `error_code` 暴露，无需 schema 迁移。

### 2.3 Chat 与 DSH 子 Agent 失败

- Dream 内部 OpenAI 兼容 Chat 客户端将非 2xx 作为安全的 `MODEL_HTTP_<status>` 类别；HTTP 401/403/429 直接进入 24 小时冷却。
- 其他 Dream Chat provider 故障最多做有限短退避；达到当前作业尝试上限后保留 `provider_wait`，24 小时后再试，不把 provider outage 误标成确定性 dead。
- DSH runner 的 `SUBAGENT_FAILED`、`SUBMIT_FAILED` 和 `RUNNER_DISPATCH_FAILED` 保留作业并转 `provider_wait`，24 小时后再试；`BAD_CHILD_OUTPUT` 是确定性错误，仍立即 dead。
- DSH 子 Agent 层目前只传递通用失败码，无法从 Rust job 诊断反推出 OpenRouter 的确切 HTTP 状态。要核对该状态仍需结合只记元数据、不记 prompt/响应的本地代理日志；429/凭据错误发生后不得重发 provider 请求。

## 4. 下一次受控续验门槛

1. 先在本地安全解析模型配置文件，只输出字段是否存在、模型名与 endpoint；不得把 key 写到终端、日志、报告或仓库。模型名继续严格限制为用户文件列出的值。
2. 新建全新临时 schema 11 库和 DSH home；使用 `dream.enabled=false` 验证只停定时调度、手动 runner 仍可工作。一个 synthetic principal、一个 manual trigger、单次串行 provider 请求。
3. Gemini embedding 请求最多发一次。错误诊断读取 job 的安全 `error_code`；如果为 401/403/429 或额度错误，立即停止该 provider，不重试。因为本轮的 24 小时 cooldown 已生效，失败后 runner 可以轮询 memoryd，但不得在 cooldown 到期前再请求 Gemini。
4. 只有拿到 Rust adjudication job/receipt 和最终 memory 状态后，才继续 semantic index、零词法命中/正确沉默探针。候选落库不能称作 Active 记忆或语义召回通过。
5. DSH 父 Agent/child 的 Chat 接线仍使用本地 Anthropic-to-OpenAI 转换器；这只能验证当前 DSH runner 链，不能称作 DSH 原生 OpenRouter provider 支持或生产安装。
