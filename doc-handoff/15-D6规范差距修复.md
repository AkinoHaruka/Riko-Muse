## 3. 本轮验证

### 确定性检查

- `cargo build --workspace`：通过。
- `cargo fmt --all -- --check`：通过。
- `cargo test --workspace --quiet`：**120 passed，0 failed**（domain 3、extract 19、recall 4、server 15、SQLite store 79）。
- `agent-memory/adapters/dsh` 的 `npm test`：**16 passed**；涵盖 DSH event 顺序、compact trigger spool、离线重放、父 Agent 来源捕获、retire/restore span 参数。
- `git diff --check`：通过；仅有 Windows CRLF 提示，没有 whitespace error。
- schema 10→11 在测试副本/临时库路径验证；未用新二进制打开旧用户库。

### 官方 DSH + 固定响应/mock

在独立临时数据库与本机 mock 端点运行官方 DSH clone（HEAD `477b4f4`）：

1. 高上下文会话实际观察到 `compaction/end`；adapter 使用持久 compaction ID 建立 Dream trigger。
2. Dream runner 领取持久作业；官方 `ctx.subagents` 启动受限 child；固定响应输出经 Rust 校验，主题页 job 到 `succeeded`、页面为 `published`，source memory IDs/versions 可查。
3. memoryd 停止期间的用户/assistant L0、flush 和 compact trigger 留在 spool。恢复 memoryd 后重新启动 DSH，自动 replay 获得 receipts；对应 L0 顺序到达、Dream job 完成，SQLite `foreign_key_check` 为空。
4. 普通 turn/end 未启动 Dream 模型调用。测试请求日志中可见普通 turn 请求，但没有 Dream/compact 带来的模型调用。
5. dead consolidation 的 retry 将 consolidation job 与 Dream parent 一起重排；随后通过 DSH runner 成功发布，generation 递增，冻结输入/attempt 不被重置。

上述结果是**官方宿主进程 + 固定响应/mock**证据，不是真实模型连通、模型质量或生产部署证据。
