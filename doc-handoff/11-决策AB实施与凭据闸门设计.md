## 1. 决策 A：`memory_remember` 409 的窄映射（commit `ea23c29`）

- `adapters/dsh/src/tools.ts`：`toToolResult` 新增 `rememberStateConflict` 选项，**仅 memory_remember 调用点传入**：HTTP 409 + `error.code=STATE_CONFLICT` → `{ok:false,error:{code,message}}`。其他工具同名错误不变，仍 throw（带 request_id）；401/网络/坏 JSON/内部错误不在此列。
- `tsc --noEmit` 与 `tsc -p` 通过（dist 已重建）。
- 验收（doc5/09 §2 四条）：

| 验收项 | 结果 |
|---|---|
| 本地固定响应与真实 DSH 宿主同信封 | ✅ 直连 8795 的 409 JSON 与宿主 tool_result 内容逐字一致（三种门各验一次） |
| 三种直写窄门保留原 code/message、不回显正文 | ✅ 需保存指令（「我对芒果过敏，你帮我记一下。」）、TEMPORAL（「请记住：下周一要去医院做体检。」）、SECRET（「请记住：我的密码：abcd1234。」）均返回结构化 `{ok:false,error:{code:"STATE_CONFLICT",message:<原文案>}}`；凭据值未回显 |
| 另一工具人为 STATE_CONFLICT 仍走协议错误路径 | ✅ stub 内核（`stub_kernel_409.mjs`，8796）对 `/v1/memories/search` 返回 409 STATE_CONFLICT → 宿主 tool_result 为 `Error: agent-memory 内核错误 code=STATE_CONFLICT request_id=stub-conflict: …`（throw 路径） |
| 不能解决「不调工具却谎报成功」 | ✅ 如实记录：本轮两项分开报告；谎报问题的闸门见 §3 |

- **验收中如实记录的边界**：mock 验收句「我的密码是 abcd1234」（无分隔符）未被 `secret_like` 命中而误存为 active——检测器要求「密码+分隔符+值」形状。该记忆已用正规 forget 流程清除（suppressed source 落库）。这是 doc5/03 §7 词表法保守拦截的已知漏报，**未放宽**；mock 场景已改用检测器支持形状「我的密码：abcd1234」。

## 2. 决策 B：直写单命题粒度门（commit `4cb7eb5`）

- `memory-extract/src/lib.rs`：新增 `multi_proposition_for_direct_write`——任何 `，/,/；/;/。` 之后（跳过空白）以「以后/从现在起/我/平时主要写/还/也」起始即判复合。**不复用、不改动 admit_v2 的 `multi_claim`**（其行为已绑定作业行 admission_version）；分句起点之外不推断。
- `memory-store-sqlite`：`StoreError::CompoundWriteForbidden`；`remember` 在 span 与高风险类别校验之后、去重/创建之前执行粒度门（所有 kind 适用）；不自动拆分、不写部分记忆。已存在的复合 active 不在迁移中处理（doc5/09 §3）。
- `memory-server/src/main.rs`：映射 409 `STATE_CONFLICT`，消息「一次只能保存一个命题：请把复合内容拆开，对每个命题用单独的「请记住：<原话>」分别保存」（不回显正文）。
- `cargo test --workspace`：**71 passed / 0 failed**（新增 `direct_write_multi_proposition_detection`、`remember_compound_write_rejected`：全 kind 复合拒绝、高风险先于粒度门、拒绝不落库、两条分别保存得独立 ID）。
- HTTP 冒烟（d5dsh 8795，真实 Bearer）：复合 remember → 409 新文案；单命题「请记住：我对花生过敏。」→ 201 active。
- **DSH 宿主回归**：复现 doc-handoff/10 §2.2 会话 7b 同一场景（旧代码双写 2 条 active），新代码宿主 tool_result 为结构化 `{ok:false,error:{code:"STATE_CONFLICT",message:"一次只能保存一个命题…"}}`，active 集合不变。
- 已知最小集合边界（如实记录）：「我住在城东的滨江小区，家里养了一只猫」这类第二分句不在起点表内的复合句仍可直写；扩大起点表属新决策。

## 3. 保存凭据闸门（doc5/09 §1/§5.2）：官方源码核对与最小设计（**未实现**）

### 3.1 官方 clone 可用事件/通道（@477b4f4 实测 grep）

| 面 | 事实 | 对闸门的意义 |
|---|---|---|
| `agent/assistant-stream` | 只读流事件 | 可观察但不能改写回复 |
| `agent/turn-stopping` | serial 派发 `{turn, signal}`（agent-loop/src/agent.ts:343） | 回合收尾可挂异步核验（本轮设计落点） |
| `agent/status` | `{status}` 状态转移 | 空闲判定辅助 |
| `agent/pre-step` / `session/event` | 适配器已在用（注入/捕获） | 不新增接线形状 |
| 回复拦截/改写 Hook | **不存在**（core/agent-loop 无 post-reply 可变钩子） | 印证 doc5/09 §1「不凭空假定」；宿主提示不能靠改写模型文本实现 |
| 工具卡（tool presentation） | 工具调用在宿主 UI 可见 | 模型调了写工具时用户看得到卡片；**没调工具时无任何卡片**——正是谎报场景的识别缺口 |

### 3.2 最小设计提案（供用户定稿；受控试用期间即可用）

1. **写回执台账（适配器侧，零协议改动）**：适配器本就持有每个写工具的结构化结果。在 `agent/turn-stopping`（serial，可异步）把本 turn 的写操作清单落到 JSONL 台账（按会话滚动，形状类似 `proxy-requests.log`）：`{turn, tool, ok, memory_id?, version?, code?}` + 汇总行 `kernel_writes: N`。台账由**开发者核对**，不进模型上下文、不依赖模型转述——这就是 doc5/09 §1 的「同等机制」。
2. **受控试用核对规程**：凡模型声称「已记住」，核对者以台账 `kernel_writes>0` 且 memory_id 可在 `memory_search/get` 命中为唯一凭据；`kernel_writes=0` 一律记为「未确认保存」并计入假阳性统计（验收必须复现会话 7 那类「不调工具却声称已记住」）。
3. **后续可选增量（各需独立卡）**：内核 `GET /v1/sessions/{id}/write-receipts`（按 origin 会话查写回执，doc/12 增量）；宿主 UI 状态面（超出本轮范围）。
