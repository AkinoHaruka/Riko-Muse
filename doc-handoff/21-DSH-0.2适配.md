## Android 模型提供商设置后续（2026-09-29）

在 DSH 0.2 源码接口核对后，Riko-App Bridge 增加了 DSH 模型设置代理。该实现最初位于 `agent-memory/adapters/dsh`，后已拆分到仓库根目录的独立 `riko-app-api/` 包：

- `GET /model-settings` 通过 DSH settings/credentials 查询提供商配置与密钥是否存在；不回读密钥值。
- `POST /model-settings/discover` 调用 DSH `llm.discoverModels`。
- 提供商凭据写入/删除分别走 `POST|DELETE /model-settings/providers/{id}/credential`。
- 自定义兼容提供商走 `POST /model-settings/custom-providers` 与 `PUT|DELETE /model-settings/custom-providers/{id}`；DSH profile 与 credentials 分开持久化。
- Riko Android 设置页增加提供商 Key 写入/删除、自定义 API 地址/协议/模型列表编辑及 DSH 模型发现。Key 仅作为表单临时状态，经 Rust JNI HTTPS 请求提交，不回存 App。

本地 `npm test` 为 20/20，覆盖 provider credential write-only、标准 provider key 绑定、模型发现、自定义 provider 写入失败后重试及响应不回显 key；Android `:app:assembleDebug --offline` 成功，debug APK 已安装到 `emulator-5554`。此处未使用真实提供商密钥或调用模型 API。App 的 `riko.asia` Bridge 尚未部署这些新路由，故生产端到端仍未验证；本地文件变更待本次提交完成后另行发布/部署。
