基线 `main@b766135`（D4-7）。本轮为 D4-7 记录中「明确未做/未验证」的收口：**真实 DSH 宿主复验（收口 1）**、**真实用户库副本上演练迁移 0003（收口 2）**、**定向源码复核（复核 3）**。全程未调用任何外部模型：宿主对话用本机 `mock-model.mjs`（3977，Anthropic Messages SSE 固定响应），提取 worker 用本机 `mock_extract_server.py`（3979，固定 JSON）。本轮**仍未做模型质量验证**。

## 1. 收口 1：真实 DSH 宿主复验 doc4 改动 ✅

**环境**（全新搭建，不碰 alice/dana/realtest 三套既有环境）：验证库 `d4closeout/host.db`（空库直装 schema 3）、内核 8795、适配器 dist 重建（`tsc --noEmit` 通过后 `tsc -p`）、DSH `--profile memory-hl` + 独立 patch（hostId `dsh-d4verify`）。四个会话均为**真实 DSH 宿主**（官方 clone 477b4f4 headless CLI）发起。

| 会话 | 场景 | 观察结果 |
|---|---|---|
| A | 普通短对话 | 3 op（user seq8、assistant seq17、turn/end flush:17）全部 ack；作业 `v1:17` succeeded（attempts=1，usage 42/3 来自固定响应端点） |
| B | 单条 ~26 KiB 用户消息 | **主动 flush 触发**：字节阈值（24 KiB）在 turn/end 之前排出 `flush:8`，随后 turn/end 再排 `flush:16`；opId/through 递增，不重复排已 ack 窗口。服务端 `v1:8` 正常作业；`v1:16` 为**零模型调用 checkpoint**（窗口内只有 assistant 事件：attempts=0、model_name=NULL）——doc4/03 §2 契约如实生效 |
| C | **内核停机中**对话 | 3 op 全部落 spool 未 ack；退出排空按 5s deadline 收尾，未 ack 保留（不丢、不伪造 ack） |
| D | 内核恢复后对话 | 启动重放自动补发 C 的 3 个 op → 全部 ack；C 的事件/作业（`v1:17` succeeded）与 D 自身数据齐平 |

**链路追账**：8 个 event receipt 的 evidence_id 与 L0 `evidence_events` 逐条相等（0 缺失、0 多余）；5 个 flush receipt 对应 5 个作业；audit 13 行。每个 session 的捕获光标停在最后正文事件（17/16/17/17），flush through == 光标；D 启动时经官方 `sessionQuery.readEvent` 对 A/B/C 逐 seq 对账到日志末尾，beyond-cursor 无事件——**没有漏事件，也没有把未接收事件纳入 flush**。

**已知限制（如实记录）**：适配器内存队列满（1024 条/8 MiB）拒收光标不推进，属单元测试覆盖（6/6 node:test），真实宿主难以自然触发 1024 条积压，本轮未在真实会话重现；光标语义（未接收 seq 不被后续 flush 越过）经离线会话 C→D 重放路径间接验证。

**本机坑（新增）**：长 prompt 经 `corepack pnpm dsh` 转发受 cmd 8191 字符命令行上限限制（报「命令行太长」，ELIFECYCLE exit 1，进程未启动）；用 `node --import tsx/esm apps/cli/src/bin.ts`（与 pnpm 打印的命令完全一致）直连官方入口可传 ~26 KB 参数。中文长文本还会被 Git Bash 命令替换按 GBK 重编码，大文本一律用 ASCII 填充。

## 3. 复核 3：定向源码复核（jobs.rs / worker.rs / events.ts / evidence.rs）

### 3.1 确认符合契约的点（均核对到源码行）

- **领取事务**（`jobs.rs:283-334`）：单事务内先条件化恢复过期 running 再选「无未完成前窗」的 due 作业；前驱阻断按 `(scope,host,session)+through` 数值判定，一个 session 的坏窗口不饿死其他 session；`run_after<=now` 对 queued/retryable 统一（退避不可绕过）；领取 UPDATE 带状态条件且 generation 原子 +1。
- **过期 running 恢复**（`jobs.rs:342-394`）：恢复 UPDATE 带 `status='running' AND claim_generation=旧值` 条件，不覆盖已提交行；attempts+1，满 3 次 dead，错误码 `WORKER_LEASE_EXPIRED`。
- **续租与旧代际隔离**：续租条件 UPDATE（`jobs.rs:438-449`），模型网络调用不持锁；`complete_job`/`fail_job` 0 行影响返回 `StaleClaim`（468-530）；`save_candidate` 在**事务内**重核 status+generation（687-695）；worker 提交模型结果前先 `job_generation_current` 预检（`worker.rs:884`）。
- **分窗边界**（`flush_window`，`jobs.rs:69-243`）：幂等检查先于乱序检查；through 越过已收最大 seq 或小于已排最大均 409；事务内重读事件贪心分组（100 事件/32 KiB 实际序列化字节）；单事件超限独立 dead；无 user 组与空 seq 范围 succeeded checkpoint；全部同事务+审计。与 doc4/03 §2 伪代码逐条对应（会话 B 的 `v1:16` checkpoint 实测佐证）。
- **skip 后前窗放行**：`window_lower_bound`（`jobs.rs:249-273`）只把 succeeded 或有 skip 行的前窗计入下界，未跳过 dead 不可越过；claim 的前驱阻断同样豁免有 skip 行的 dead（298-300）；`skip_dead_job`（562-616）只接受 dead+WINDOW_TOO_LARGE、幂等、同事务写审计。
- **重复 ingest 幂等**（`evidence.rs:91-125`）：同 `(scope,host,session,seq)` 同内容哈希 → **200 already_recorded**（返回原 evidence_id）；仅同键不同哈希 → 409。因此适配器把 409 归为 permanent 不会误伤 spool 重放（会话 C→D 实测佐证）。
- **worker 外层分类**（`worker.rs:805-973`）：一旦 claim，任何错误离开前都 `fail_job` 落状态，无「留在 running」的路径；窗口超限不调用模型；候选部分写入后重试幂等（唯一键 `(job_id,source_event_id,kind,quote_sha256)`）。

### 3.2 发现（按用户边界分类：「必须修」= 有明确失败路径；本轮只记录不修）

| # | 发现 | 定级 | 依据与影响 |
|---|---|---|---|
