## 1. 实施结果

### D6-11｜官方 DSH child 隔离

- 官方源码核对补记在 [13-D6源码核对 §12](13-D6源码核对.md)。上游 `SubagentStartRequest.toolFilter` 在 in-process child 创建窗口调用 scoped `tools.restrict()`；适配器把 Dream child 的初始 allowlist 设为空。
- Dream 只读工具只注册到被 AsyncLocalStorage 绑定的 child scoped context。没有 `child.ctx.tools.register` 时拒绝启动，不退回全局工具注册。
- Soul assemble、Resident/Recall pre-step 和 L0 捕获均排除 subagent/fork session。固定响应官方 DSH 日志中 child 的 `system_has_soul=false`，工具集合只有当前 phase 允许的 Dream 读取工具。

### D6-12｜job-scoped 只读 API 与快照

- 新增 `POST /v1/dream/jobs/{job_id}/read`，操作为 `manifest`、`evidence`、`search_memories`、`get_memory`、`search_pages`、`get_page`。身份 scope 只从 Bearer token 派生。
- Rust 复核 runner、job、lease、generation、冻结 evidence、对象生命周期和读取目标版本；搜索出的 L1/page 版本及 fingerprint 被固定到当前 generation。详情 API 不能读取未经当前 generation 搜索登记的 ID。
- 每 job 默认 32 次读取，数据库字段约束为 1—64（本版没有用户配置接口）；一次 evidence IDs 最多 20 个，query 最多 512 字符，search limit 1—10。读取 receipt 只记 query hash、结果数量和语义搜索完整状态，不保存 query 正文。
- `0012_dream_read_snapshots.sql` 新增读取计数、search receipts 和 target snapshots；purge 目标时通过外键清理相关快照。

### D6-13｜多阶段只读探索与 Rust 提案提交

Dream child 按 phase 使用不同能力：

| phase | 可用读取工具 |
|---|---|
| extract / redecision | manifest、冻结 evidence |
| adjudicate | 上述工具 + 搜索/读取 L1 |
| consolidate | 上述工具 + 搜索/读取有效页面 |

工具错误返回结构化失败；child 提示词要求在读取不完整或语义搜索不可用时 defer，不得把“工具失败”说成“没有匹配”。候选、adjudication、L1 变更与主题页发布仍经过 Rust 的来源、scope、version、generation 和状态复核。

### D6-14｜已有页面比较、更新和词法索引

- `0013_topic_page_description.sql` 为主题页加入 description 及 revision 前后版本，并重建 page FTS，使标题、描述、正文共同可检索；无效来源页不恢复进索引。
- `consolidate_v2` 要求先搜索页面；若找到已有同 key 页，必须读其冻结版本再发布更新。固定响应官方 DSH run 创建 page version 1，后续读回同一页并更新为 version 2，来源从 2 条扩到 3 条。
- **实施中修复一处真实索引缺陷**：Dream adjudication 新建或更新 Active L1 时原先未写 `memory_fts`/`memory_grams`，导致可见记忆无法被后续词法搜索与整理输入选择发现。现在索引更新在对应 L1 事务内完成；supersede 时清除旧对象索引。新增 create/update 搜索回归断言。临时库观察到的旧索引已用 `memoryd rebuild-index` 修复，Rust search 随后找回两个有效目标。
