## 2. 实施

- schema **23**：`0023_task_driver.sql` 新增 `task_claims`，同 scope/domain/task/signal 由 SQLite 原子领取；租约 3600 秒，失败最多 3 次，指数退避，成功/耗尽状态保留供状态查询。旧迁移及旧 checksum 未修改。`SCHEMA_VERSION` 已同步。
- `serve` 按 `[schedule] driver_enabled=true`、`driver_interval_secs=900` 定时扫描 active domain 与 `background_due`。upkeep 真调用 `entries_refresh` 与 `derived_refresh`；relationships 真调用 `relationship_refresh` 与 `derived_refresh`。首次建图的 due 输入扩为 active memory 更新，否则实体表为空时永远不会自动刷新。
- nightly/quiet 在 `[generation] enabled=true` 时调用 P1 现有 `generation_run`，继承其引用校验、模型失败回执和 ledger；关闭时刷新确定性 synthesis 模板并记 `empty`。quiet 与 upkeep 分别消化 user event 到各自 `processing_ledger` 行，避免 upkeep 提前消化后 quiet 无法 due。每次实际领取成功、空、失败或重检不再 due 均有 `task_runs` 回执；失败不写成功 ledger。
- 新增鉴权只读 `GET /v1/tasks/status`，按 Bearer scope 与域授权返回最近 40 条 claim/运行状态。`/v1/tasks/due` 仍只读，`/v1/tasks/run` 仍是手工回执；内置驱动调用与这两个端点同一 Store 判定/记账方法，避免服务内循环携带用户 Bearer token。
