### 2.2 投影规则 `entity_v1`（确定性、保守）

输入是写域内**当前可见**的 active 记忆（复用 V2-P1 的 `visible_memory_sql`）。只识别两种句式：

| 句式 | 例子 | 产出 |
|---|---|---|
| A：`<REL><叫\|叫做\|名叫\|名字是><NAME>` | 我妻子叫小雨 | person(小雨, relation=妻子) |
| B：`<NAME>是[我\|我的]<REL>` | 老王是我的同事 | person(老王, relation=同事) |

宁缺勿滥的拒绝规则（每条都有测试）：
- 名字长度必须 **2—12** 个 `[\u4e00-\u9fa5A-Za-z0-9]` 字符；
- 名字不得是关系词、**代词或自称**（他/她/它/我/你/您/他们…）；
- 名字不得是「自称/代词 + 关系词」的组合（「我妻子」→ 拒），
  但**正常称呼里含关系词照样接受**（「王老师」「李医生」）；
- 一句里给出多个不同候选 → **整条跳过**；
- 关系词必须在受控词表内（「我房东叫张叔」不产出实体）。

条目 body 是来源记忆 claim 的**原文**；`open_threads`/`strengthening`/`in_common`/`history`
本卡保持为空——没有证据就不填。

### 2.3 读接口与排序

- `index`：有预算（默认 24，上限 200）+ `omitted` 省略计数；`stale/removed` 不进索引。
- `get(entity_id, expected_version?)`：逐条复核来源，来源一改即时屏蔽并计入 `skipped_stale`；
  版本不匹配返回 409 `VERSION_CONFLICT`。
- `resolve(q)`：精确匹配 display_name 与别名，返回 `none`/`one`/`ambiguous`，
  歧义时返回全部候选，**不做模糊猜测**（「老」不命中「老王」）。
- 排序：`user_explicit` > `verified_role` > `unranked`，同级按名称再按 id 稳定收尾；
  **提及频率不参与 rank**。本卡没有「用户明确排序」入口，实际只会出现后两档。

### 2.4 生命周期

- **域**：实体域与来源域一致；side 私有实体不进主索引；读按 V2-S1 读域集过滤。
- **重建**：同 (tenant,user,domain) 整体替换，batch_version 递增。
- **purge 闭包**：`purge_confirm` 第 7.6 步删该记忆的关系来源行与别名行，再删零来源的条目与实体——
  不允许无来源的实体存活。

### 2.5 HTTP / CLI

`GET /v1/relationships`、`GET /v1/relationships/{entity_id}?expected_version=`、
`GET /v1/relationships/resolve?q=`、`POST /v1/relationships/refresh`、
`memoryd relationships refresh --config --tenant --user --domain`。

## 4. 临时库 HTTP 冒烟证据（2026-10-06）

脚本：[`v2s1-domain-smoke.ps1`](v2s1-domain-smoke.ps1)（已追加 V2-R1 段）。**未打开 dana/realtest 原库。**

```
R1_SEED_REMEMBER=201
R1_REFRESH=200          batch_version=1 entities=1 items=1 previous_entities=0
R1_INDEX=200            total=1 omitted=0
R1_ENTITY_ID_PRESENT=True
R1_GET=200              items=1 skipped_stale=0 first_section=relationship
R1_RESOLVE_ONE=200      resolution=one        （"小雨" → 唯一命中）
R1_RESOLVE_NONE=200     resolution=none       （"nobody"）
R1_RESOLVE_ROLE=200     resolution=one        （"妻子" 作为 role 别名命中）
R1_INDEX_MAIN_AFTER_GRANT=200 total=1         （此前的 ON_GRANT 授权了 main→side_a）
```

**完整人物事实覆盖受限**：本卡只投影「用户 ↔ 某人」的**单跳关系**，且只覆盖两种句式；
第三人自动准入未放宽，因而更广的人物事实（兴趣、共同经历等）仍无法自动进入图谱。
这是政策与规则的共同结果，单独记录，不写成已解决。

## 5. 本轮修出的缺陷

| # | 位置 | 现象 | 修复 |
|---|---|---|---|
| 1 | `extract_mentions` 的「是」扫描 | 按 `idx + 1` 前进字节，而「是」是 3 字节 → 切在字符中间 **panic** | 改 `idx + '是'.len_utf8()` |
| 2 | 名字接受规则 | 代词句「他是我同事」产出 name=「他」 | 加代词/自称黑名单 + 名字下限 2 字 |
| 3 | 名字接受规则（二次） | 「王老师」因为含关系词「老师」被误拒 → 相似称呼不误并的用例失败 | 只拒绝「自称/代词 + 关系词」组合，正常称呼放行 |

三条都是**自己的测试当场抓到**的；每处都回写进 doc7/07 的规则描述。
