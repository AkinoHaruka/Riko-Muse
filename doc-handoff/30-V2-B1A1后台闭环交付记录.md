需要版本化生成器与真实模型，**本卡不做**；本卡交付可离线验证的那一层，并把生成器接口留好：

| 层 | 本卡 |
|---|---|
| 处理账本与水位（同一信号只消化一次） | ✅ |
| 调度判定（纯函数 + 四项独立开关） | ✅ |
| quiet pass 有界（20 分钟沉寂 / 有信号 / 每日 ≤3） | ✅ |

不由模型自报；模型只能提议，激活/关闭必须有人或可信规则的授权记录。

## 2. 交付内容

### 2.1 迁移 0018（`0018_background_closure.sql`）

- `processing_ledger`：`(域, 任务能力, 信号引用)` 主键，同一信号只消化一次。
- `task_runs`：运行回执（含失败），quiet 每日上限据此计数。
- `repair_actions`：行动、期望行为、条件、反例、status(proposed/active/done/withdrawn)、
  `proposed_by`、`authorized_by`、`close_reason`、`recurrence_count`、来源与生成器版本。
- `repair_action_events`：复发/修复观察；**按 rupture 幂等**，唯一键不含 `observed_at`。
- `rupture_events` 补 `target` 与 `detector_version`（历史行默认 v1 语义，统计不被改写）。

`0001`—`0017` 未改动；`SCHEMA_VERSION 17 → 18`；`d69_tests` 冻结历史断言同步为 18。

### 2.2 调度（`memory-domain::schedule` + `Store::background_due`）

纯函数判定 `upkeep_due` / `relationships_due` / `quiet_due` / `nightly_due`，
以及**由 Rust 查库算出信号计数**的 `background_due`：

- 未消化信号 = user 事件里未出现在 upkeep 账本中的条数；
- relationships 的变化 = 上次成功运行之后更新的实体数；
- quiet 的三重条件：沉寂 ≥ 20 分钟、有未消化信号、当日 < 3 次；
- 每项都返回 `reason`（`due`/`no_new_signal`/`interval_not_reached`/`daily_limit_reached`/
  `not_idle_enough`/`already_ran_today`/`disabled`），便于诊断。
- 配置 `[schedule]` 四项**独立开关** + 参数；测试逐项断言关掉一个不影响其它三个。

### 2.3 `rupture_v2` 分类

`RUPTURE_CUES_V2` = V1 ∪ `你说错`/`你搞错`/`你弄错`（补 doc-handoff/25 的 FN）。
分类只看 cue 前后各 24 字符窗口（**窗口含 cue 本身**）与先后顺序：
第三人引语 → 自我修正 → 第二人称 → 中性。**只有 `agent_correction` 开线/强化线程**，
其余 target 仍然落库留痕（不丢证据，也不误报）。

### 2.4 修复行动（A1）

提议（模型只能 `proposed`，且不得自带授权）→ 激活（user/cli + `authorized_by`）→
关闭（必须显式 `close_reason`；**「久未复发」不接受**）。复发：同一 rupture 重复记录幂等，
不同 rupture 分别计数。

### 2.5 入口

`GET /v1/tasks/due`（只读，不触发任何调用）、`POST /v1/tasks/run`、
`GET·POST /v1/repair/actions`、`POST /v1/repair/actions/{id}/activate|close`、
`memoryd tasks due --config --tenant --user [--domain]`。

## 5. 本轮修出的缺陷

| # | 位置 | 现象 | 修复 |
|---|---|---|---|
| 1 | `repair_action_events` 初稿 | 唯一键含 `observed_at`，同一时刻的两条不同 rupture 互相冲突（UNIQUE 失败） | 改为按 `(action, kind, rupture_id)` 幂等，主键改代理 id |
| 2 | `classify_target` 窗口 | 窗口只取 cue 前后文、**不含 cue 本身**，「你记错了」在句首时被误判 neutral | 窗口纳入 cue 文本 |
| 3 | `background_due` | 归还 `now` 与借用 `today` 冲突（编译错） | 文案先算好，结构体字面量只 move |
| 4 | 行动不合法 | 复用了 `InvalidPageField`，报出「title 1—80」这种与行动无关的话 | 新增 `InvalidRepairAction` 专用变体 |
| 5 | 4 个 muse_tests | V1 时代用例内容不含第二人称，V2 下被判 neutral → 不开线 | 把**测试夹具**改成明确指向 Agent 的纠正（用例本意是归组/幂等/指标，不是分类），期望计数同步为 V2 信号数 |
