## 2. 已实施内容

### 2.1 `FORMAT.toml`

- 常量：`file_store_v1`、格式版本 `1`，以及 evidence/claim/Soul/overview/operation/receipt/fence 的版本常量。
- `FormatDefinition::{parse,to_bytes,read,write}`：严格字段、拒绝未知字段/未知版本、固定顺序、UTF-8/LF/NFC 校验和规范字节复核。

### 2.2 五类规范语法

| 类别 | 实现位置 | F1 行为 |
|---|---|---|
| evidence daily note | `src/evidence.rs` | JSON 块头含 `occurred_at`、`agent_id`；按 `content_bytes` 取 payload；结束标记只诊断；payload 原字节 hash/保存；同 note 重复 ID 拒绝 |
| claim | `src/claim.rs` | front matter 固定字段顺序，含独立 `normalized_claim`；正文原字节保存；hash 直接调用现行 `memory_domain::claim_sha256`；evidence span 支持现行 `(Some,Some)` 与 `(None,None)` 两种语义 |
| Soul | `src/soul.rs` | 固定 front matter、原字节 `body_sha256`、actor 白名单、version 校验、2000 Unicode 标量上限 |
| `MEMORY.md` | `src/overview.rs` | 只解析 front matter、Curated `riko:ref` 与 Compact `riko:derived`；不渲染；重复引用拒绝，悬空引用交给 corpus 校验 |
| operation / receipt / fence JSON | `src/json_files.rs` | 三个 schema ID/format 常量、严格 envelope 与 canonical JSON；receipt 把 `response_json` 作为精确 JSON 字符串保存以维持幂等重放字节；forget fence 保存现行 `evidence_id + claim_sha256 + forgotten_memory_id`，purge fence 不保存正文 |

### 2.3 规范化与 quarantine

- 容器/控制元数据校验 UTF-8、LF、NFC；evidence payload、claim 正文、Soul 正文不做规范化，CRLF 与分解 Unicode 均可逐字节 round-trip。
- canonical 输入均执行“解析 → 序列化后必须与输入逐字节相同”；`MEMORY.md` 按任务要求只解析不渲染。
- `src/quarantine.rs` 提供稳定机器原因码，包括：`hash_mismatch`、`duplicate_id`、`version_regression`、`dangling_reference`、`id_mismatch`、`scope_mismatch`、`domain_mismatch`、`actor_mismatch`，以及 UTF-8/LF/NFC/语法/字段/格式错误。
- `QuarantineReport` 只带路径、原因码、字段与可选对象 ID，不带私密正文；解析器不猜 ID、不自动修复。

## 3. 源码核对中的语义说明

doc8/03 §3.1 同时要求“沿用现行 `memory-domain` 定义”并以“原始字节”描述 `claim_sha256`。现场源码 `riko-memory/crates/memory-domain/src/lib.rs:113-120` 的真实定义为：

```text
SHA256(UTF8(kind + "\0" + normalize_v1(claim)))
```

F1 没有另造算法，而是直接调用该函数；claim 正文本身仍按原始 UTF-8 字节保存。测试同时锁定“空白/大小写规范化后 hash 相同”和“正文原字节不变”。因此没有改变现行 memory-domain 行为，也没有触发格式无法表达现行语义的停止条件。
