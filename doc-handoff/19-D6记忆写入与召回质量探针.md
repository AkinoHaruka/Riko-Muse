# 19｜D6 记忆写入与召回质量探针

日期：2026-09-28  
范围：针对“记忆是否写得对、相关时能否召回、不相关时能否沉默”做小样本探针。只使用 `模型.txt` 中的 OpenRouter Chat 模型 `stealth/space-bunny-alpha` 与 Gemini Embedding `gemini-embedding-001`；测试正文均为合成内容。没有修改产品代码，没有访问 dana/realtest 原库，没有提交代码或文档。

## 1. 结论摘要

- **写入候选质量：有限样本表现可读，无法据此验收完整写入。** 本轮 OpenRouter Dream child 生成了 1 条候选；引文精确对应来源 byte span，主事实抽取正确，但 claim 带有来源上下文中的“虚构/合成评测”限定。该条没有完成 adjudication，因此本轮不能判断 Rust 最终会将它设为 Active 还是 Held。历史上另有 1 条真实 Dream 样本到达 Active，见 §3.1；两条样本都不足以估计稳定性。
- **相关语义改写召回：2/2 命中目标。** Gemini 对两个中文改写都返回 `semantic_status=ok`，目标 memory 以 `reason=semantic` 进入 retrieved。
- **正确沉默：本轮语义探针 0/1。** 一个明显无关的自行车问题仍召回了该目标。当前实现按余弦近邻截取 top-K，没有最低相似度门槛；这次结果证明现有单记忆样本未能正确沉默，不足以把问题归因于 embedding 模型本身。
- **词法召回也有两个具体边界。** 英文无关 query 因共享一个很短的二元 gram 而误召回；中文相关 query 对英文 claim 未命中。离线中文无关 query 正确沉默。
- **未测答案利用率。** 本轮没有再调用父 Agent，让它基于上述查询作答；因此没有“检索到后模型是否正确使用记忆”的证据。

这是诊断样本，不是质量基准：仅 1 条目标记忆、2 个相关语义问题、1 个无关语义问题，不能推导整体召回率、误召回率或人群级表现。

## 2. 环境、模型与调用量

- 所有数据位于隔离的 schema 11 合成数据库副本或全新临时库；测试 principal 为合成 scope。没有打开、迁移或查询 dana/realtest。
- 凭据在用户确认轮换并更新 `模型.txt` 后读取；报告不包含凭据。provider 请求串行、无自动重试；没有观察到 HTTP 429、认证错误或额度错误。
- 本轮质量探针新增 **Gemini 3 次请求，全部 HTTP 200**；新增 **OpenRouter 5 次请求，全部 HTTP 200**。第一次 DSH Dream 探针有 2 次请求，未生成候选；修正临时代理识别后第二次探针有 3 次请求，产生 1 条候选。第二次探针使用本地固定 embedding 响应，不产生 Gemini 请求。
- OpenRouter 临时代理设置每进程最多 3 次远端请求；没有调用 `模型.txt` 之外的模型。
- 本轮结束时 memoryd、DSH 和临时代理已停止；相关测试端口无监听。临时密钥和合成 bearer token 文件已清空。工作区既有修改均保留，没有暂存或提交。

## 3. 写入质量

### 3.1 历史 Active 样本（沿用证据）

`doc-handoff/17-D6真实模型端到端验证.md` §8.1 记录了 1 条既有真实 Dream 成功样本：合成来源表达用户最喜欢周末去天文馆观察星云；候选引文逐字对应来源 `[0,57)` byte span，Rust adjudication 后成为 Active preference。Active claim 用英文表达该偏好，语义主旨与来源相符。该样本说明一次完整路径可以成功，不代表写入稳定性或多样本质量。

### 3.2 本轮候选生成样本（未完成裁决）

在新建合成库中，由官方 DSH `ctx.subagents` 启动受限 Dream child，通过 OpenRouter `stealth/space-bunny-alpha` 生成候选：

| 项 | 观测 |
|---|---|
| 来源 evidence | `01a0e464-81df-7448-927c-07361f04c12b` |
| Dream job | `01a0e464-81e8-7548-9789-dd7ff4fb278d`，最终 `provider_wait / SUBAGENT_FAILED` |
| 候选 | `01a0e464-dff6-74e0-983f-f7c34dfaf0d4`，`kind=fact`，状态仍为 candidate，policy=`dream_policy_v1` |
| 候选原文 | `my fictional project codename is Amber Finch`，44 bytes |
| 来源定位 | byte span `[0,44)`；逐字比较通过，`quote_equals_span=true` |
| 生成 claim | `The user's project codename is "Amber Finch" — explicitly a fictional codename given for a synthetic evaluation, not a real project.` |
| 质量观察 | 核心事实“代号是 Amber Finch”正确；claim 比引文更具体，补入“synthetic evaluation / not a real project”背景。来源消息含有 synthetic evaluation 与 fictional 语境，故本样本中没有发现事实冲突，但 claim 并非逐字文本，不能把 span 校验误读为 claim 全句逐字正确。 |
| 最终裁决 | 未完成。adjudication job `01a0e464-dfff-7355-b3f6-78aa9f6e9569` 同样为 `provider_wait / SUBAGENT_FAILED`；没有 Active memory 或 semantic vector。 |

本轮临时协议代理仍未正确区分所有 child 请求：第三个 OpenRouter 请求被判为非 child 并施加了 90 秒延迟，随后 DSH runner 记录 `SUBAGENT_FAILED`。因此这是**测试装置限制导致的未完成链路**，不能归因于模型候选质量或产品 adjudication 质量。候选内容只能评价到“模型输出 + Rust candidate 保存”这一段。

第一次尝试也因临时代理将 child 识别为父请求而失败，没有候选；不计为模型拒绝或提取失败。两次尝试共消耗本轮 OpenRouter 5 次请求，均 HTTP 200。

## 4. 召回质量

### 4.1 目标记忆与离线词法探针

目标为 §3.1 的单条 Active preference，其持久化 claim 为英文。先将历史合成库通过 SQLite backup 复制到新的临时位置，然后执行 `memoryd rebuild-index`，确认 FTS 与 gram 索引非空、`index_dirty=0`。未在原历史库上执行写操作。

| Query 类型 | 示例 | 结果 | 判定 |
|---|---|---|---|
| 英文相关 query | `The user favorite weekend activity observing nebulae planetarium` | 目标进入 retrieved，`reason=lexical` | 命中 |
| 英文无关 query | `bicycle tire repair` | 同一目标进入 retrieved，`reason=lexical` | **误召回** |
| 中文相关 query | `周末去哪里观察星云` | 未召回，语义支路关闭 | **词法漏召回** |
| 中文无关 query | `怎么修理自行车轮胎` | 未返回目标 | 正确沉默 |

源码核对：`memory-recall/src/lib.rs:33-67` 将字母数字连续段也切成 Unicode 二元 gram；`memory-store-sqlite/src/memories.rs:549-577` 按任意共享 gram 计数并加入候选，没有最低共享比例门槛。本例 query 的 `tire` 与 claim 中 `activity` 共享 gram `ti`，因此短片段重合就足以形成候选。这解释了**本样本**的误召回路径，不代表所有词法误召回都由此导致。

中文相关 query 的词法漏召回与目标 claim 使用英文有关；它只证明关闭语义支路时此样本没有跨语言词法命中。

### 4.2 本轮真实 Gemini 语义探针

使用 Gemini `gemini-embedding-001`、3072 维，在隔离的只含上述一条 Active 目标向量的库中串行发送三个 `/v1/context/bundle` query。三次响应均 HTTP 200，`semantic_status=ok`，没有重试：

| 类型 | Query | 总耗时 | 目标结果 |
|---|---|---:|---|
| 相关中文改写 A | `休息日我会用什么方式放松？` | 1027 ms | 命中，`reason=semantic` |
| 相关中文改写 B | `我最享受的周末活动是什么？` | 514 ms | 命中，`reason=semantic` |
| 无关中文问题 | `自行车爆胎该如何更换内胎？` | 477 ms | **仍命中，`reason=semantic`** |

请求 ID 依次为 `01a0e452-6a6c-74a1-bf65-e8ae2a37164a`、`01a0e452-a061-7110-8f91-a15bbffa6d6e`、`01a0e452-d3de-7456-82d3-3e2960e5ae8e`。耗时样本中位数 514 ms、范围 477–1027 ms；`n=3` 不能用来估算稳定延迟分布。

源码核对：`memory-store-sqlite/src/semantic_index.rs:255-296` 对 scope 内 ready 向量计算余弦相似度、排序并截取 `top_k`；当前没有最低相似度阈值。`memory-server/src/main.rs:3905-3920` 将这些 ID 放进语义候选通道。当前 adapter response 不暴露余弦分数，因此本轮只能确认“被选中/未被选中”，不能量化目标与无关 query 的分数间隔。

所以本轮结论是：**两个相关改写都找到了唯一目标，但在一记忆小库中无关 query 也找到了它。E09 有 2 个正向样本，E12 的正确沉默样本失败 1 次。** 这不足以断言 Gemini embedding 本身差；top-K 无阈值的本地召回策略是一个直接可见的混杂因素，尚未做多记忆候选集与分数阈值对照。

## 6. 后续质量测量所需的对照集

本报告不预先改规则。要判断写入与召回整体质量，应至少建立一组固定合成评测集，让每个样本都能分别标注：原始事件、预期原子事实、正确来源 span、应 Active/Held 的标签、相关改写、近义但无关问题、答案层可区分的有记忆/无记忆结果。每条记忆需与多条无关 query 配对，不能只用一记忆库里的“nearest neighbor 是否返回”代替相关性评估。

对当前证据可直接下的判断仅限于：本轮出现了真实相关召回，也出现了明确误召回与语言不匹配漏召回；候选 span 做得精确，但本轮最终准入没有跑完。整体写入/召回质量仍**未验收**。

## 7. 后续实现：在线语义相似度下限

探针后，在线 query 召回增加 `semantic_min_similarity` 配置：默认 `0.3`，只允许 `0..=1` 的有限数值；向量候选在 top-K 截断和全局 RRF 之前按 cosine `similarity >= floor` 过滤。无候选过门槛时仍报告 `semantic_status='ok'` 和空语义候选，词法及其他通道继续工作。阈值只用于 query 相关性筛选；Dream 写入期候选检索继续走不带该 floor 的扫描入口。

该默认值参考 Hindsight 与 TencentDB 上游检索路径中的配置初值 `0.3`，仅是待评估的工程初值，不是由本项目 Gemini 样本校准出来的质量结论。原 §4.2 无关自行车 query 的误召回仍是**门槛修改前的真实历史样本**；本次没有重新调用 Gemini，尚不知道它的实测 cosine 分数是否低于 `0.3`。因此不能声称这一修复已消除该误召回，E12 修复后仍待针对性复验。

本地确定性回归覆盖 floor 前后的 hit 集、相等边界保留、非法范围拒绝，以及 ready 向量计数不受 floor 影响；配置默认与范围也有单测。验证命令：`cargo fmt --all -- --check`、`cargo test --workspace`（全部通过；memory-store-sqlite 80 项）和 `cargo build --workspace` 均通过。构建仍显示仓库中既有的 unused/dead-code 警告，本次改动没有新增编译错误。尚未更新 §5 的历史实测表格；它保留本轮门槛变更前的真实样本。真实模型质量仍未验收。

## 8. `0.3` 门槛后的真实 query 复验

日期：2026-09-28。使用 §8.9 中保留的 schema 11 合成数据库做只读 SQLite backup，在新临时副本上启动刚构建的 memoryd。副本只有 1 条 active 目标记忆，目标 `01a0e2ad-6809-73b5-8d90-2e65b3f602a2` 的 `gemini-embedding-001 / 3072 / ready` 向量与一个已完成索引作业均在启动前核对。配置显式设置 `semantic_min_similarity=0.3`、`dream.enabled=false`，只启用 `模型.txt` 中的 Gemini Embedding；没有调用 OpenRouter/Chat。dana/realtest 原库没有打开或变更。

| Query 类型 | 总耗时 | HTTP / 状态 | 目标结果 | request ID |
|---|---:|---|---|---|
| 相关中文改写 A：`休息日我会用什么方式放松？` | 1135 ms | 200 / `semantic=ok` | 命中，`reason=semantic` | `01a0e665-d57e-7054-a19c-61d3e8496b9d` |

| 无关问题：`自行车爆胎该如何更换内胎？` | 535 ms | 200 / `semantic=ok` | **仍命中，`reason=semantic`** | `01a0e666-034f-7052-b628-92d7e82c45f4` |

结论：相关 query 仍是 2/2 命中；无关 query 在 `0.3` 下仍被语义通道召回，因此这次复验没有修复该 false positive，E12 仍不通过。它至少说明单纯采用上游 `0.3` 初值不足以让该样本沉默；不能据此推断应把阈值调到某个具体数值，因为本次 bundle 响应不暴露余弦分数。

为测分数，另发起 1 次串行 Gemini batch embedding 请求，输入恰为以上 3 个 query、模型仍为 `gemini-embedding-001`。响应含 3 个 data 项，但 `index` 字段并非全有或全无，评分脚本无法安全映射 query 与向量，未计算或保存分数；没有重试。故本轮新增 Gemini 请求共 4 次：3 次真实 memoryd bundle 请求 + 1 次未能用于评分的批量探针；均未观察到限流或鉴权错误。该批量响应形状不改变前三次单输入 bundle 的观测，也不作为记忆质量结果。

本轮 memoryd 已停止；临时 embedding key 和 synthetic bearer token 副本已清除。合成数据库副本保留以便核对。阈值实现的本地确定性测试仍通过，但真实质量结论是：**2/2 相关命中、1/1 无关误召回；E12 失败，阈值尚未校准。**
