## 2. 规则要点（与 doc5 决策的对应）

- **新作业固定 `extract_v3` + `admit_v2`**（flush 创建的普通/超限 dead/checkpoint 作业同口径，`jobs.rs::flush_window` 显式写当前常量）；**旧作业（含手动 retry）保持原 Prompt + `admit_v1`**，`admit_v1`/`extract_v1`/`extract_v2` 文本与行为冻结；未知版本 → 立即 dead，不退回最新规则。
- **admit_v2 固定顺序**（doc5/03 §2）：BAD_SOURCE → QUOTE_MISMATCH → INVALID_QUOTE → CONTEXT_UNCERTAIN（含「今天先」）→ NON_MINIMAL_QUOTE/MULTI_CLAIM → UNCLEAR_SUBJECT → SECRET → SENSITIVE → THIRD_PARTY → TEMPORAL → NOT_EXPLICIT/KIND_MISMATCH；12—15（抑制源/去重/属性冲突/提交）在 store 层，两版共用。
- **可自动 active 的窄句式**：instruction（以后/从现在起/请总是/记住/请记住/always/from now on/remember 起始，先过敏感等闸门）、preference（我喜欢/我不喜欢/I like/I dislike）、fact/name、fact/residence、fact/occupation（我在X工作、我在X做<职业尾词>、我是<职业尾词>、I am a/an X）、fact/primary-practice（我主要写X/我平时主要写X）。X 非空、1—64 标量、无分句标点；句式之外默认 held。
- **直写窄门**（doc5/04）：SECRET 优先于保存指令检查；TEMPORAL 独立否决；SENSITIVE/THIRD_PARTY 需直接相邻保存指令（最窄读法：空白只在冒号后跳过）。三条拒绝均 409 `STATE_CONFLICT`，消息不回显敏感正文；不新建候选、不伪称 held；普通偏好与既有幂等/审计/遗忘抑制不变。
- **召回不变**：instruction 独立名额至多 2，fact/preference 仅词法命中；`fact/preference` 不常驻注入。
