## 1. 现场源码事实与选型

- 官方 DSH clone HEAD `687f282e8625c6b8d11ff58211a90524be2e4317`。`packages/jobs/jobs-local/src/index.ts:130-162` 的 `LocalJobRegistry` 自述 in-memory，`store = new Map<JobId, TrackedJob>()`；构造器 `:186-195` 仅建立进程内状态及 teardown，没有 SQLite 恢复。它不提供本任务需要的跨重启队列。
- 子 Agent seam 是 `packages/subagent/subagent/src/index.ts:255-284` 的 `startActivation`，要求精确 live parent agent（`:278`）；无父 Agent 在线时不能作为驱动。P0.6 的工具隔离已验证，但不改变此生命周期要求。本卡不创建或冒称 subagent。
- 内核 `memory-server/src/main.rs:986-1139` 已有 `serve` 内置定时循环；`background.rs:504` 的 due 判定与 `:212` 的 task_runs 回执已持久；`main.rs:4137` 的 `/v1/tasks/due` 只读，`:4160` 的 `/v1/tasks/run` 只记账。P1 显式生成入口是 `POST /v1/generation/run`（`main.rs:4210` 起），`generation.rs` 成功才写 processing_ledger。

## 2. 执行契约

1. `[schedule] driver_enabled` 缺省 true，`driver_interval_secs` 缺省 900、最小 1。`serve` 启动即 tick，随后周期 tick；按 `all_scopes` 和 active domain 扫描。与对话在线无关。`/v1/tasks/due` 仍保持只读，驱动消费同一个 `background_due` 判定结果。
2. 四类注册任务只在对应 due=true 时执行。`upkeep` 刷新 entries/derived，`relationships` 刷新关系图与 derived；`nightly`、`quiet` 在 P1 generation 显式启用时走同一生成器入口，关闭时执行确定性刷新并在回执中标记。每次实际领取后，成功、空、失败均写 task_runs；refresh 的实际结果写 detail。不得把回执本身当作执行。
3. 新增 schema 23 `task_claims`：按 `(scope,domain,task_kind,signal_ref)` 唯一租约，SQLite 原子 UPSERT 领取；持有者校验后才提交结果。成功后记录所消费 user event 的 processing_ledger 行；失败不写成功账本。`upkeep` 与 `quiet` 分别消费各自账本，避免前者抢先消化而让后者永远不 due。到期租约可重领，最多 3 次，指数退避，终止失败可见于只读状态查询。一次 tick 内同任务只领一次。
4. `quiet` 在领取前、执行前均重算 due；task_runs 的每日次数上限包括失败，因此执行侧不可绕过上限。`nightly` 同日最多一次。对重复启动的 `serve`，SQLite 租约和 ledger 是最终防重；单进程 Mutex 只用于进程内串行。
5. 只读 `GET /v1/tasks/status` 返回最近回执及 claim 状态，遵循 Bearer scope 和 domain 授权。不得暴露其他用户。现有 `tasks/run` 仍只是手工回执，不等于执行；驱动在完成实际作业后调用相同 Store 回执方法。

## 3. 验收与边界

- 单测覆盖 due 消费、并发领取、防重复 ledger、失败留痕与重试上限、quiet 上限。
- 临时库 `serve` 调小 tick，在无对话情况下构造信号，观察刷新 batch/version、task_runs、processing_ledger 与只读状态；不使用 mock 冒充模型或 refresh。
- P1 模型配置缺失时不能声称生成成功。Dream child 仍由 DSH live runner 负责，本卡不改其任务类型与宿主生命周期；dana/realtest 原库不打开。
