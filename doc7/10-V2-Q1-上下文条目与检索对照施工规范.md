## 0. 定位与不越界

V2-Q1 是**检索增量**，不是换检索。V2 文档 04 §4 明确：不废弃 claim/page 召回、不盲目照搬 entry。
本卡交付：

| 交付 | 说明 |
|---|---|
| `context_entries` + `entry_sources` | 版本化上下文对象，逐条来源可定位 |
| `entry_v1` 确定性切块 | 从**可见的 L0 用户事件**按会话切块，body 逐字、附字节 span |
| entry 召回（补充道） | FTS + 二元字，与 claim/page 同权限、同可见性；**不改**现有两道 |
| 读时失效判定 | 来源事件消失/记忆版本变化 → 条目即时不再返回 |
| 同语料对照 | 预标注问法上的 claim / entry / 合并三路 recall/precision 对照 |
| entry 向量绑定 | `semantic_vectors`/`semantic_jobs` 扩到 `object_kind='entry'`；**只入队不调用模型** |

**不做**：entry 的 LLM 摘要（需模型）、真实语义质量结论（需模型端点）、
把「加一个 chunk 就能提高召回」写进结论（V2 文档 04 §5 明确禁止）。

## 2. `entry_v1` 确定性切块

输入：写域内**当前可见**的 user 事件（`role='user' AND source_kind='user'`），按
`(session_id, event_seq)` 排序。切块规则：

- 会话变化 → 新条目；
- 当前条目字符数 + 下一条 > `ENTRY_MAX_CHARS`（1200）→ 新条目；
- 当前条目事件数已达 `ENTRY_MAX_EVENTS`（8）→ 新条目；
- `body` = 各事件 `content` 用 `\n` 连接的**逐字**原文；`title` = 首条前 40 字符；
- 每条来源记录 `evidence_id` + 整事件 span + `content_sha256`；若该事件已被 `remember`，
  同时记录 `memory_id`/`version`/`claim_sha256`；
- **不概括、不摘要、不拼接改写**。多命题属于同一 entry 是允许的（V2 文档 04 §3）。

## 3. 读时失效与生命周期

条目对某次读请求可见，当且仅当：

1. `status='active'` 且 `domain_id` ∈ 读域集；
2. **每条来源仍成立**：证据行仍存在且 `content_sha256` 未变（purge 会删除证据行）；
3. 若来源带 `memory_id`：该记忆仍通过 V2-P1 的统一可见性判定，且 version/claim_sha256 未变。

不成立的条目在读取时被跳过并计入 `skipped_stale`——**不等下一次重建**。
purge 闭包：删该证据的 `entry_sources` 行，再删零来源的条目。

## 4. 检索与对照

- **新增第五段**？不。entry 召回作为**独立端点** `POST /v1/entries/search` 提供，
  并可在实验里与 claim/page 结果合并；**不改** bundle 的既有分段语义（V2-H1 已冻结）。
- 词法：FTS5（拉丁 token）+ 二元字（CJK），与 page 同形；候选合并后用与记忆相同的
  `visible_memory` 域过滤（entry 用域 + 来源成立判定）。
- **同语料对照**：`doc-handoff` 附一份预标注问法（相关/不相关、跨语言、同义、旧值、
  关系歧义、多来源、上下文依赖），对照脚本对三路（claim / entry / 合并）算
  recall@k 与 precision@k，并**如实报告** entry 只在哪些类别上有增益、哪些类别反而变差。
  语义支路未配置时只报词法结果，不写「语义质量」。

## 5. HTTP / CLI

| 入口 | 语义 |
|---|---|
| `POST /v1/entries/refresh` | 重建本域条目（整体替换、batch_version 递增） |
| `POST /v1/entries/search` | entry 词法召回（域 + 来源成立判定） |
| `GET /v1/entries/{entry_id}` | 读单条（含逐条来源与字节 span） |
| `memoryd entries refresh --config --tenant --user [--domain]` | CLI 等价入口 |

## 6. 验收（`v2_q1_tests`）

1. **切块确定性**：同输入两次重建内容一致、batch_version 递增；会话边界、字符上限、
   事件数上限三种切分都命中；body 逐字等于来源事件内容拼接。
2. **不概括**：entry body 必须是原文子串的逐字拼接，不含任何生成文本。
3. **来源失效即时屏蔽**：删掉（purge）来源事件后不重建即读不到，`skipped_stale ≥ 1`。
4. **记忆版本联动**：来源事件对应的记忆被更正（版本前移）后，条目不返回；重建后一致。
5. **purge 闭包**：purge 唯一来源事件后条目与来源行都不再存在。
6. **域隔离**：side 域条目不出现在主域检索里。
7. **同语料对照**：预标注集合上输出三路 recall/precision；
   **不得**把 entry 有增益的类别推广成整体质量结论。

档位：`cargo build/test --workspace` → 临时库 HTTP 冒烟（refresh/search/get）。
**entry 向量只入队不调用模型**；真实语义质量与真实 DSH 闭环**未验证**。

## 7. 明确不做 / 移交

- entry 的 LLM 摘要与多源概括 → 需真实模型，另立卡。
- 真实语义召回质量 → 未配置端点，记「未验证」。
- 可写导入 / 双向同步 → 暂缓（V2 文档 03 §4）。
- 人物/群组检索融合 → 后续按痛点再立项。
