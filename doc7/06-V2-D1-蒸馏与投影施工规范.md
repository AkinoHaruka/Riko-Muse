## 0. 定位与三个产物

V2-D1 交付**三个互相独立的产物**，不是把四个 SQL kind 查询包装成「蒸馏」：

| 产物 | 本卡交付 | 不交付 |
|---|---|---|
| 精炼常驻 `compact_memory` | 从**当前有效记忆**按预算重建、可重建、带逐条来源 | 不等同用户手动 pin 的 Resident；两者去重后共同进预算 |
| 四分面 `facets` | 逐条带来源的分面投影，按需读取 | 不做 LLM 概括；分面内 body 是 claim 的**确定性摘录** |
| 只读 Markdown 投影 | 从同一数据库快照渲染的导出 + manifest | 可写导入/双向同步（V2 文档 03 §4 明确暂缓） |

**多源概括（模型生成的段落级综述）不在本卡**：V2 文档 03 §2 把它归给 upkeep/Dream 的版本化生成器。
本卡只交付确定性摘录层，并在数据结构上为「生成器版本 + observed_or_inferred」留好位置，
所以后续接入生成器不需要改表。

## 1. 迁移 0016（DDL 冻结）

新增 `0016_derived_views.sql`；`0001`—`0015` 冻结不动；`SCHEMA_VERSION 15 → 16`。

```sql
-- 派生条目：compact_memory 与四个分面共用一张表，document_kind 区分。
-- 每条都必须能定位到具体来源；没有来源的条目不得存在（服务端校验）。
CREATE TABLE derived_items (
  id TEXT PRIMARY KEY,
  tenant_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  domain_id TEXT NOT NULL DEFAULT 'user_main',
  document_kind TEXT NOT NULL CHECK (document_kind IN
    ('compact_memory','facet_experience','facet_opinions','facet_reflections','facet_world')),
  position INTEGER NOT NULL CHECK (position >= 0),
  body TEXT NOT NULL,
  -- observed=可从来源逐字复核；inferred=派生解释（本卡不产生，留位）
  observed_or_inferred TEXT NOT NULL CHECK (observed_or_inferred IN ('observed','inferred')),
  generator_version TEXT NOT NULL,
  source_fingerprint TEXT NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('active','stale','removed')),
  batch_version INTEGER NOT NULL CHECK (batch_version > 0),
  generated_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (tenant_id, user_id, domain_id, document_kind, id)
);
CREATE INDEX derived_items_by_doc
  ON derived_items (tenant_id, user_id, domain_id, document_kind, status, position);

CREATE TABLE derived_item_sources (
  tenant_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  item_id TEXT NOT NULL,
  memory_id TEXT NOT NULL,
  memory_version INTEGER NOT NULL,
  claim_sha256 TEXT NOT NULL,
  PRIMARY KEY (tenant_id, user_id, item_id, memory_id),
  FOREIGN KEY (tenant_id, user_id, item_id)
    REFERENCES derived_items(tenant_id, user_id, id) ON DELETE CASCADE
);
CREATE INDEX derived_sources_by_memory
  ON derived_item_sources (tenant_id, user_id, memory_id);

-- 导出 manifest：只读投影的版本与状态；正文不入库（渲染自同一快照）。
CREATE TABLE derived_exports (
  id TEXT PRIMARY KEY,
  tenant_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  domain_id TEXT NOT NULL DEFAULT 'user_main',
  batch_version INTEGER NOT NULL,
  manifest_json TEXT NOT NULL,
  outcome TEXT NOT NULL CHECK (outcome IN ('complete','incomplete')),
  created_at TEXT NOT NULL
);
```

`derived_items` 不加 FTS/向量：分面与 compact 是**按需读取**的投影，不是独立检索道（避免同源重复打分，
V2 文档 03 §2「不把全部内容常驻注入」）。

## 2. 分面规则 `facet_v1`（确定性、本项目选择）

同一记忆**可以**进多个分面（V2 文档 03 §2 明确允许）。规则必须能从 (kind, status, occurred_at,
relations) 纯函数判定，不读模型：

| 分面 | 收什么 | 判据 `facet_v1` |
|---|---|---|
| `facet_experience` | 有时间与主体的经历、结果、变化 | `kind='episode'`；或 `kind='fact' AND occurred_at IS NOT NULL` |
| `facet_opinions` | 稳定偏好、判断、价值取向 | `kind='preference'`；或 `kind='instruction'` 且正文含偏好标记（`喜欢/偏好/讨厌/更愿意/习惯/prefer/favorite`） |
| `facet_reflections` | 有证据的得失与行为调整 | `status='superseded'` 且存在 `memory_relations` 取代边；条目 body 是**被取代的旧 claim 摘录**，`observed_or_inferred='observed'` |
| `facet_world` | 用户处境、持久事实 | `kind='fact'`；或 `kind='instruction'`（持久约定） |

明确不采用的简化（写进代码注释）：不把 `kind` 一对一映射到分面；不把「有 supersedes 链」
直接等于反思；不把 `valid_until IS NULL` 当成长期有效——有效期由 V2-P1 的可见性谓词决定。

`body` 是 claim 的**原文**（`fold_whitespace` 后的形态），不做概括、不拼接、不改写。
多命题合并与综述留给后续生成器；本卡不产生 `inferred` 条目。

## 3. compact_memory 规则 `compact_v1`

- 候选：当前**通过 V2-P1 统一可见性判定**的 active 记忆（复用 `visible_memory_sql`，
  不另写一套口径）。
- 去重：与当前 Resident 选中项按 `memory_id` 去重（V2 文档 03 §1：compact 与手动 pin 区分，
  去重后共同进预算）。
- 排序（本项目选择，非 Muse 已知算法）：优先级 `instruction > preference > fact > episode`，
  同级按 `updated_at` 降序、再按 `id` 升序稳定收尾。
- 预算：`COMPACT_MAX_ITEMS`（默认 24）与 `COMPACT_MAX_CHARS`（默认 1200）双上限，
  按排序依次装入，超限即停（**不**截断单条正文）。
- 每条 body 同样是 claim 原文，`observed_or_inferred='observed'`。

## 4. 失效、purge 与权限

- **来源指纹**：一次重建把 (memory_id, version, claim_sha256) 集合算成 `source_fingerprint`。
- **读路径即时屏蔽**（不等下一次重建）：条目的每条来源都必须仍满足「记忆当前可见 +
  version/claim_sha256 未变」，否则该条目在读取时被跳过。因此来源一改，投影立刻不注入。
- **重建**：同一 (tenant,user,domain,document_kind) 在同一事务内整体替换，
  `batch_version = 上一批 + 1`；相同冻结输入重建得到相同内容与递增版本，不产生重复行。
- **purge 闭包**：purge 目标涉及的 `derived_item_sources` 行随闭包删除；只剩零来源的条目
  必须一并删除（不允许「没有来源的孤立条目」）。`forget` 同理：来源被抑制后条目读不出来，
  重建后消失。
- **域**：`derived_items.domain_id` 与来源域一致；跨域不合并。读取按 V2-S1 读域集过滤。
- Agent 不得直接写 `derived_items`：只有 Rust 重建路径与 purge 闭包能改。

## 5. HTTP / CLI / 只读投影

| 入口 | 语义 |
|---|---|
| `GET /v1/compact` | 当前 compact 条目 + 预算 + batch_version |
| `GET /v1/facets?kind=<facet>` | 指定分面的条目（缺省返回全部四个分面，各自分组） |
| `POST /v1/derived/refresh` | 重建 compact + 四个分面（同事务、递增版本） |
| `memoryd derived refresh --config <cfg> --tenant --user` | CLI 等价入口（可信运维路径） |
| `memoryd export --config <cfg> --tenant --user --out <dir>` | 只读 Markdown 投影 + `manifest.json` |

导出目录语义（不需要仿 Muse 私有绝对路径）：

```
<out>/<tenant>/<user>/<domain>/COMPACT.md
<out>/<tenant>/<user>/<domain>/bank/experience.md | opinions.md | reflections.md | world.md
<out>/<tenant>/<user>/<domain>/manifest.json
```

- `manifest.json` 含 tenant/user/domain、batch_version、生成时刻、每个文件的条目数与来源定位、
  以及 `outcome: complete|incomplete`；渲染失败记 `incomplete`，不假装成功。
- 多用户/side 域导出到**各自授权路径**（按 tenant/user/domain 分层），不落到全用户混合目录。
- 文件里每行带稳定引用与来源；文件行号只是该导出版本的位置，不是主键。
- 原子替换：先写临时目录再整体替换，保留旧版 manifest 供对照。

## 6. 存储层契约

```rust
pub struct DerivedItem { id, document_kind, position, body, observed_or_inferred,
                        generator_version, source_fingerprint, batch_version, generated_at }
pub struct DerivedView { document_kind, batch_version, items: Vec<DerivedItem>, skipped_stale: usize }

impl Store {
    pub fn derived_refresh(&mut self, scope, dom) -> Result<DerivedRefreshOutcome, StoreError>;
    pub fn compact_view(&self, scope, dom) -> Result<DerivedView, StoreError>;
    pub fn facet_view(&self, scope, dom, facet: &str) -> Result<DerivedView, StoreError>;
    pub fn derived_view_readable(&self, scope, dom, document_kind) -> Result<DerivedView, StoreError>; // 内部共用
    pub fn derived_export_manifest(&self, scope, dom) -> Result<Vec<ExportEntry>, StoreError>;
    pub fn derived_write_manifest(&mut self, scope, dom, entries, outcome) -> Result<String, StoreError>;
}
```

读取实现：一次 SQL 取条目 + 其来源，逐条核 (memory 可见 ∧ version/sha 未变)，
不通过则 `skipped_stale += 1` 且不进结果。

## 7. 验收（`v2_d1_tests`）

1. **跨 kind 正确归面**：episode→experience；带 occurred_at 的 fact→experience+world；
   preference→opinions；含偏好标记的 instruction→opinions+world；普通 fact→world。
2. **不误判**：只有 supersedes 链但无 relations 边的不进 reflections；有 relations 边的进；
   `valid_until` 为空的 fact 不被当成「永久有效」以外的东西（只进 world）。
3. **compact 预算与去重**：超出预算时按优先级截断且不截断正文；Resident 已 pin 的条目被去重；
   同输入重建两次得到相同内容与递增 batch_version。
4. **来源失效即时屏蔽**：改一条来源记忆的 claim（或使其不可见）后，**不重建**也读不到该条目，
   且 `skipped_stale >= 1`；重建后条目消失。
5. **purge 闭包**：purge 掉唯一来源后重建，条目与来源行都不再存在。
6. **域隔离**：side 域的条目不出现在主域读取里；跨域不合并。
7. **导出**：manifest 内容与条目数一致；重导出内容稳定；`outcome` 正确；
   导出不含任何已失效条目正文。

档位：`cargo build --workspace && cargo test --workspace`（构建/测试通过）→ 临时库 HTTP 冒烟
（compact/facets/refresh/export）。真实 DSH 闭环与真实模型：**本卡不涉及，未验证**
（本卡不调用任何模型；模型生成的多源概括属 V2-B1）。

## 8. 明确不做 / 移交

- LLM 多源概括、反思的模型解释、每日 dated notes（需模型生成器）→ V2-B1。
- 可写 Markdown 导入 / 双向同步 → 暂缓（V2 文档 03 §4）。
- entry/chunk 上下文对象 → V2-Q1。
- people/groups 索引与人物页 → V2-R1。
- 投影目录不仿 Muse 私有绝对路径；文件不作为第二真相源。
