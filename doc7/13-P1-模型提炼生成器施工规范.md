# P1 · 模型提炼生成器施工规范

> 2026-10-22。依据交接 33 §1.1、35、36，doc7/01 §1.4、08 §4。P0.5 当时停在规范阶段；P0.6 后当前分支已切至 DSH 0.2.1-rc.2 且真实闭环通过。现有 `alignment_synthesis_refresh` 位于 `riko-memory/crates/memory-store-sqlite/src/alignment.rs:499`；`tasks/run` 位于 `riko-memory/crates/memory-server/src/main.rs:4129`；模型客户端位于 `worker.rs:1284`。旧实现按其原版本冻结。

## 1. 版本与触发

- 旧 `extract_v1/v2/v3/v4`、`admit_v1/v2/v4`、M3 确定性 synthesis 模板与 `SYNTHESIS_REFRESH_POLICY_V1` 不改行为。新增 `synthesis_v2`、`reflection_v1`、`repair_action_v1` 三种生成器。每个生成结果保存 `generator_version`、来源及生成状态；新迁移从 0022 开始。
- alignment 沿用四种已实施触发：无版本、累计 rupture 超过已计数、open 线程数变化、窗口超过 24 小时。先按旧路径生成模板版本，再在显式启用模型时尝试同一窗口的新版；同一窗口不得重复调用。新版与模板版在同一 `alignment_synthesis` 版本链共存，`GET`/compose/bundle 取最高**有效**版本；来源失效时跳过模型版，回退到有效模板版。
- nightly/quiet 仅在原有 `background_due` 判 due 且显式请求运行时生成。普通 turn/end/flush 不触发模型。`[generation] enabled` 缺省 false；关掉时所有旧端点保持原行为。模型未配置或失败时只保留模板；失败写 `task_runs` 的 `error` 回执。不得吞掉失败并宣称模型成功。

## 2. 输入、输出与证据

- `synthesis_v2` 输入限同一写域最近窗口的可见 active memory（最多 24 条、按更新时间倒序）及 open repair thread 所关联、仍有原始事件的 rupture（最多 12 条）。每条输入给模型不透明的引用键与精确 `memory_id`/`rupture_id`/`evidence_id`/byte span。`reflection_v1` 取 nightly/quiet 当前未消化且可见的同域信号，最多 24 条；`repair_action_v1` 仅取对应 open thread 的 rupture 与相关可见 memory。跨 scope/域内容不得入 prompt。
- 模型输出结构化 JSON，`sentences` 数组中每项有 `text` 和非空 `refs`。一个 `text` 只允许一个实质句子；正文由 Rust 逐项拼接。引用必须属于本次输入，且提交事务中重新校验：memory 仍 active、未到期、未 retire、至少一条未被 forget 的用户来源；rupture/thread 仍同域且其 evidence/span 仍存在、未被忘记。至少两个独立来源才允许有立场的 synthesis/reflection；repair action 至少有本 thread 的 rupture 引用。引用只支持本次列出的精确 ID，模型不得自造 evidence_id。
- 任一句无引用、引用不存在/失效、跨 scope/域、空句或多句，**整个模型候选拒绝落库**，绝不部分保存。存储引用的 ID、来源哈希和句子到引用映射。读时复核；失效后立即不注入。引用校验保证可定位与可见，不证明模型句子逻辑上必然被来源蕴含；人工对照单列这一边界。
- 模型不能写入 Soul/L0/L1。repair action 只能 `proposed`，不能激活或关闭；沿用 doc7/08 §4 授权和显式关闭理由。模型 action 与 expected_behavior 每句都须引用。

## 3. 幂等、失败、清理

- 使用 `processing_ledger` 的 `(scope,domain,task_kind,signal_ref)` 记录成功消费；生成器版本与窗口/信号组成稳定 `signal_ref`。失败不记成功账本，记录 `task_runs.error` 与失败原因代码，可重试。模型调用期间不持 SQLite 锁，提交时二次校验并以唯一键保护并发。
- alignment 模型候选拒绝时返回本次模板产出；响应携带 `fallback_reason` 与累计拒绝计数。nightly/quiet 的 dated reflection 没有旧正文模板时，以现有确定性指标/线程清单作为回退摘要；action 无证据时不提议行动，仅留失败回执。不得保存无引用的模型文本。
- purge/forget/retire 必须清理或即时隐藏所有失效生成物及引用记录；旧版本链可审计，但不可注入。历史迁移与历史作业行不改写。

## 4. 验收

1. 无引用、失效引用、跨域引用、多个句子：整份候选拒绝，回退计数增加，模型句子不落库。
2. 同一 signal 二次执行不再调用模型；失败留 `task_runs.error` 且可重试；版本链中模板与模型版同存，读取选择有效最高版。
3. nightly/quiet 原判定与四开关互不影响；repair action 仅 proposed，旧授权规则持续有效。
4. 临时库真实模型跑含纠正与 rupture 的多轮语料，展示模板与模型对照，逐句核 ID/span；分别报告代码、测试、真实模型、真实 DSH、部署档位。不得打开 dana/realtest 原库。
