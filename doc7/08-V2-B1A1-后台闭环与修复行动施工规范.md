## 0. 本卡交付什么、不交付什么

V2 文档 08 把后台闭环拆成「**调度与可靠性**」和「**内容生成**」两层。
内容生成（dated reflection 的散文、action synthesis 的措辞）需要真实模型，**本卡不做**；
本卡交付**可离线验证的那一层**，并把生成器接口留好：

| 层 | 本卡 | 说明 |
|---|---|---|
| 处理账本与水位 | ✅ | 同一信号只消化一次；无新信号零模型调用 |
| 调度判定（纯函数 + 开关） | ✅ | upkeep hourly / relationships hourly / nightly / quiet pass，各自开关互不影响 |
| quiet pass 有界 | ✅ | 20 分钟沉寂 + 有未消化重要信号 + 每日 ≤3 次，参数可配置 |
| rupture 目标分类（`rupture_v2`） | ✅ | 区分对 Agent 的纠正 / 自我修正 / 第三人引语 / 中性讨论 |
| 修复行动与复发观察（A1） | ✅ | 行动有具体文本、期望行为、来源、授权与复发计数；**模型只能 propose** |
| dated reflection / action 文本生成 | ❌ | 需版本化生成器与真实模型 → V2-H1 之后另立卡 |
| bundle 分段与 DSH 消费 | ❌ | V2-H1 |

**硬边界（doc 08 §1、§3）**：普通 turn/end/flush 只登记信号，**不触发 LLM**；
所有派生进 user-role；不得修改 Soul；不得由模型自报统计指标（指标仍由 Rust 算）；
模型只能**提议**关闭修复线程或新增行动，不能直接写最终状态。

## 1. 迁移 0018（DDL 冻结）

新增 `0018_background_closure.sql`；`0001`—`0017` 冻结不动；`SCHEMA_VERSION 17 → 18`。

```sql
-- ruptur 事件补两列：目标分类与检测器版本。历史行是 v1 语义（都会开线程），
-- 因此默认 target='agent_correction'、detector_version='rupture_v1'，历史统计不被改写。
ALTER TABLE rupture_events ADD COLUMN target TEXT NOT NULL DEFAULT 'agent_correction'
  CHECK (target IN ('agent_correction','self_correction','third_party','neutral'));
ALTER TABLE rupture_events ADD COLUMN detector_version TEXT NOT NULL DEFAULT 'rupture_v1';

-- 处理账本：同一 (域, 任务能力, 信号引用) 只消化一次（doc 08 §1）。
CREATE TABLE processing_ledger (
  tenant_id TEXT NOT NULL, user_id TEXT NOT NULL,
  domain_id TEXT NOT NULL DEFAULT 'user_main',
  task_kind TEXT NOT NULL CHECK (task_kind IN
    ('upkeep','relationships','nightly','quiet','rupture_scan')),
  signal_ref TEXT NOT NULL,
  generation INTEGER NOT NULL DEFAULT 1 CHECK (generation > 0),
  processed_at TEXT NOT NULL,
  PRIMARY KEY (tenant_id, user_id, domain_id, task_kind, signal_ref),
  FOREIGN KEY (tenant_id, user_id) REFERENCES principals(tenant_id, user_id)
);

-- 任务运行回执：每日 quiet 次数上限等按此计数；失败也留痕，不吞失败当成功。
CREATE TABLE task_runs (
  id TEXT PRIMARY KEY,
  tenant_id TEXT NOT NULL, user_id TEXT NOT NULL,
  domain_id TEXT NOT NULL DEFAULT 'user_main',
  task_kind TEXT NOT NULL,
  outcome TEXT NOT NULL CHECK (outcome IN ('ok','empty','error','skipped')),
  signal_count INTEGER NOT NULL DEFAULT 0 CHECK (signal_count >= 0),
  detail TEXT NOT NULL DEFAULT '',
  run_at TEXT NOT NULL,
  FOREIGN KEY (tenant_id, user_id) REFERENCES principals(tenant_id, user_id)
);
CREATE INDEX task_runs_by_day ON task_runs (tenant_id, user_id, task_kind, run_at DESC);

-- 修复行动（A1）：具体行为而不是「避免同类问题」。
CREATE TABLE repair_actions (
  id TEXT PRIMARY KEY,
  tenant_id TEXT NOT NULL, user_id TEXT NOT NULL,
  thread_id TEXT NOT NULL,
  action TEXT NOT NULL,
  expected_behavior TEXT NOT NULL,
  conditions TEXT NOT NULL DEFAULT '',
  counterexamples TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL CHECK (status IN ('proposed','active','done','withdrawn')),
  -- 模型只能 propose；激活/关闭必须有人或可信规则的授权记录。
  proposed_by TEXT NOT NULL CHECK (proposed_by IN ('model','user','cli')),
  authorized_by TEXT,
  authorized_at TEXT,
  close_reason TEXT,
  recurrence_count INTEGER NOT NULL DEFAULT 0 CHECK (recurrence_count >= 0),
  source_memory_id TEXT,
  generator_version TEXT,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
  UNIQUE (tenant_id, user_id, id),
  FOREIGN KEY (tenant_id, user_id) REFERENCES principals(tenant_id, user_id),
  FOREIGN KEY (tenant_id, user_id, thread_id)
    REFERENCES repair_threads(tenant_id, user_id, id)
);

-- 执行与复发观察：同一 action 关联多条 rupture 才算复发。
CREATE TABLE repair_action_events (
  tenant_id TEXT NOT NULL, user_id TEXT NOT NULL,
  action_id TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('recurrence','resolved','note')),
  rupture_id TEXT,
  detail TEXT NOT NULL DEFAULT '',
  observed_at TEXT NOT NULL,
  id TEXT PRIMARY KEY,
  -- 复发按 rupture 幂等；唯一键**不含** observed_at（同一时刻两条不同 rupture 会互相冲突）。
  UNIQUE (tenant_id, user_id, action_id, kind, rupture_id),
  FOREIGN KEY (tenant_id, user_id, action_id)
    REFERENCES repair_actions(tenant_id, user_id, id) ON DELETE CASCADE
);
```

## 2. 调度判定（纯函数 `memory-domain::schedule`）

判定必须是纯函数，才能离线穷举验证「无新信号零调用」与各开关互不影响：

```rust
pub struct ScheduleConfig { pub upkeep_interval_secs: i64 /*3600*/,
                            pub quiet_idle_secs: i64 /*1200*/,
                            pub quiet_max_per_day: i64 /*3*/,
                            pub nightly_enabled: bool, pub upkeep_enabled: bool,
                            pub relationships_enabled: bool, pub quiet_enabled: bool }

pub fn upkeep_due(cfg, now, last_run_at, unprocessed: i64) -> bool      // 有新信号 且 距上次 ≥ 间隔
pub fn relationships_due(cfg, now, last_run_at, changed_entities: i64) -> bool
pub fn quiet_due(cfg, now, last_activity_at, unprocessed: i64, runs_today: i64) -> bool
pub fn nightly_due(cfg, now_date, last_nightly_date) -> bool            // 每晚一次，跨日才算
```

- **无新信号 ⇒ 一律 false**（doc 08 §1：无变化不调用模型）；
- quiet 三重条件缺一不可：沉寂 ≥ 20 分钟、有未消化重要信号、当日 < 3 次；
- 四种任务的开关互相独立：关掉 quiet 不得改变 upkeep/nightly 的判定；
- `unprocessed` 由处理账本与信号表决定，不由模型自报。

## 3. `rupture_v2` 目标分类（确定性）

`RUPTURE_CUES_V2` = V1 清单 ∪ 若干漏检表述（`你说错`、`你搞错`、`你弄错`、`你理解错`），
补 doc-handoff/25 记录的 FN（「上次你说错导致损失」）。

分类只看 cue 所在**子句**（按 。！？；，\n 切分）与子句内先后顺序：

| 顺序 | 判据 | target |
|---|---|---|
| 1 | 子句里有第三人称 + 引语动词（他/她/他们/别人/某人 + 说/说过/告诉/提到/认为），且在 cue 之前 | `third_party` |
| 2 | 子句里有自称 + 自错词（我/是我/我自己 + 说错/记错/搞错/弄错/理解错/错了） | `self_correction` |
| 3 | 子句里有第二人称（你/您），或 cue 本身含「你」 | `agent_correction` |
| 4 | 其余 | `neutral` |

**只有 `agent_correction` 会开线或强化 repair 线程**（V13 的 FP 修复：
「不对，是我记错了」不得报成 Agent rupture）。其余 target 仍然**落库留痕**，
供复核与统计，只是不进线程——不丢证据，也不误报。

## 4. 修复行动与关闭授权（A1）

- **提议**：模型（或 CLI/user）只能是 `proposed`；`proposed_by='model'` 的行
  `authorized_by` 必须为空。
- **激活**：只有 user/cli 能置 `active`，并写 `authorized_by`/`authorized_at`。
- **关闭**：`done`/`withdrawn` 必须有 `close_reason`；**单纯没有新纠正不构成修复证据**，
  因此关闭接口要求显式理由，且不接受「久未复发」这种自动理由。
- **复发观察**：新的 `agent_correction` rupture 落到同一线程时，
  该线程下 `active` 的 action 记一条 `recurrence` 事件并 `recurrence_count += 1`；
  同一 rupture_id 重复记录幂等。
- 行动文本必须具体：`action` 与 `expected_behavior` 非空且长度 ≥ 4 字符；
  「避免同类问题」这类空话由调用方约束，规范只强制非空与来源。

## 5. HTTP / CLI

| 入口 | 语义 |
|---|---|
| `GET /v1/tasks/due` | 当前 scope/域下四项任务的 due 判定与依据（不触发任何调用） |
| `POST /v1/tasks/run` | 记账一次任务运行（`task_kind`/`outcome`/`signal_count`），供调度器与上限计数 |
| `GET /v1/repair/actions?thread_id=` | 列出修复行动与复发计数 |
| `POST /v1/repair/actions` | 提议行动（`proposed_by=model|user|cli`；模型只能 proposed） |
| `POST /v1/repair/actions/{id}/activate` | 激活（user/cli，写授权） |
| `POST /v1/repair/actions/{id}/close` | 关闭（必须显式 `close_reason`） |
| `memoryd tasks due --config --tenant --user [--domain]` | CLI 等价入口 |

`/v1/tasks/due` **只读**：它只回答「该不该跑」，不代替 runner 入队，也不调用模型。

## 6. 验收（`v2_background_tests`）

1. **无新信号零调用**：`unprocessed=0` 时四项判定全 false；`changed_entities=0` 时 relationships false。
2. **间隔与跨日**：未到间隔 false、到间隔 true；nightly 同日 false、跨日 true。
3. **quiet 三重条件**：沉寂不足 20 分钟 false；无重要信号 false；当日已 3 次 false；三者都满足才 true。
4. **开关互不影响**：单独关掉任一开关，只影响该任务，其余判定不变（逐项断言）。
5. **账本幂等**：同一 (域, 任务, 信号) 记两次只留一行；不同任务/不同信号各留一行。
6. **rupture_v2 分类**：自我纠正 FP 判 `self_correction` 且**不开线程**；
   「上次你说错导致损失」判 `agent_correction` 且**开线程**（FN 修复）；第三人引语判 `third_party`；
   中性讨论判 `neutral`；四者都落库留痕。
7. **行动授权**：模型提议的行 `status='proposed'` 且 `authorized_by` 为空；
   未授权的 `active` 写入被拒；关闭缺 `close_reason` 被拒。
8. **复发计数**：同一线程下的新 agent_correction 使 active action 的 `recurrence_count` +1；
   同一 rupture 重复记录幂等。

档位：`cargo build --workspace && cargo test --workspace` → 临时库 HTTP 冒烟
（due/run/action 提议-激活-关闭）。**内容生成未实现**：dated reflection 与 action 文本由模型产出，
属后续卡；真实 DSH 闭环与真实模型**本卡不涉及、未验证**。

## 7. 明确不做 / 移交

- dated reflection / action synthesis 的**文本生成**（需版本化生成器 + 真实模型）。
- bundle 分段、DSH 工具与使用纪律 → V2-H1。
- 检索质量对照 → V2-Q1。
- 费用/token 限额的 provider 侧配置 → 与 V2-H1 一并定。
- 历史 rupture 统计不因 detector 升级而改写：新旧版本分别记在 `detector_version`。
