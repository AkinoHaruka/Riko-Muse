# doc7/01 · 数据模型与规则

> 迁移 `0014_muse_alignment.sql`（SCHEMA_VERSION 13 → 14）。只新增表与索引；
> `0001`—`0013` 冻结不动。全部新表挂 `(tenant_id, user_id)` 外键到 `principals`。

## 1. 迁移 0014 DDL

### 1.1 rupture_events（纠正/裂痕事件）

确定性 Rust 规则对 user 事件正文做字节 span 匹配的产物。来源可反查（evidence_id + 字节偏移）。

```sql
CREATE TABLE rupture_events (
  id TEXT PRIMARY KEY,
  tenant_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  evidence_id TEXT NOT NULL,
  host_id TEXT NOT NULL,
  session_id TEXT NOT NULL,
  event_seq INTEGER NOT NULL CHECK (event_seq >= 0),
  signal TEXT NOT NULL,            -- 命中的信号名（如 'correction'）
  cue TEXT NOT NULL,               -- 命中的字面量
  start_byte INTEGER NOT NULL CHECK (start_byte >= 0),
  end_byte INTEGER NOT NULL CHECK (end_byte > start_byte),
  thread_id TEXT,                  -- 归属修复线程（检测时归组回填）
  detected_at TEXT NOT NULL,
  UNIQUE (tenant_id, user_id, evidence_id, signal, start_byte),
  FOREIGN KEY (tenant_id, user_id) REFERENCES principals(tenant_id, user_id),
  FOREIGN KEY (tenant_id, user_id, evidence_id)
    REFERENCES evidence_events(tenant_id, user_id, id)
);
CREATE INDEX rupture_events_by_scope
  ON rupture_events (tenant_id, user_id, detected_at);
```

- 幂等：`UNIQUE (tenant_id, user_id, evidence_id, signal, start_byte)`——重扫/重放不产生重复行。
- 同一事件命中多个不同信号 → 多行（同 signal 只取首个命中 span）。

### 1.2 rupture_scan_cursors（扫描游标）

```sql
CREATE TABLE rupture_scan_cursors (
  tenant_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  last_rowid INTEGER NOT NULL CHECK (last_rowid >= 0),
  updated_at TEXT NOT NULL,
  PRIMARY KEY (tenant_id, user_id),
  FOREIGN KEY (tenant_id, user_id) REFERENCES principals(tenant_id, user_id)
);
```

- 扫描按 `evidence_events.rowid` 单调推进（rowid 即插入序，UUIDv7 主键时间有序）。
- 只扫 `role='user' AND source_kind='user'` 的事件。

### 1.3 repair_threads（修复线程）

```sql
CREATE TABLE repair_threads (
  id TEXT PRIMARY KEY,
  tenant_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  title TEXT NOT NULL,             -- 首个 rupture 的事件摘要（≤80 字符，内容派生）
  status TEXT NOT NULL CHECK (status IN ('open','closed')),
  rupture_count INTEGER NOT NULL DEFAULT 1 CHECK (rupture_count > 0),
  first_rupture_at TEXT NOT NULL,
  last_rupture_at TEXT NOT NULL,
  closed_at TEXT,
  close_reason TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (tenant_id, user_id, id),
  FOREIGN KEY (tenant_id, user_id) REFERENCES principals(tenant_id, user_id)
);
CREATE INDEX repair_threads_by_scope
  ON repair_threads (tenant_id, user_id, status, last_rupture_at DESC);
```

**归组规则（RUST_REPAIR_GROUPING_V1，冻结常量）**：新 rupture 落到该 scope 内
`status='open'` 且 `last_rupture_at` 距本次 `detected_at` 不超过 7 天（`REPAIR_THREAD_REGROUP_DAYS = 7`）
的最近线程；否则新建线程（title = 事件正文截 80 字符）。关线只经 API/CLI 显式关闭
（actor + reason 落 `closed_at/close_reason`）；closed 线程不再吸收新 rupture（新开线程）。

### 1.4 alignment_synthesis（相处指南，版本化派生）

Muse `ALIGNMENT_SYNTHESIS.md` 的内核等价物。**确定性 Rust 派生，不经 LLM**；每版本
绑定窗口与来源，满足 AGENTS.md「所有新内容带清晰来源」。

```sql
CREATE TABLE alignment_synthesis (
  tenant_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  version INTEGER NOT NULL CHECK (version > 0),
  window_since TEXT NOT NULL,
  window_until TEXT NOT NULL,
  rupture_turns INTEGER NOT NULL CHECK (rupture_turns >= 0),
  user_turns INTEGER NOT NULL CHECK (user_turns >= 0),
  correction_free_rate REAL NOT NULL
    CHECK (correction_free_rate >= 0 AND correction_free_rate <= 1),
  open_repair_threads INTEGER NOT NULL CHECK (open_repair_threads >= 0),
  body TEXT NOT NULL,              -- 渲染后的相处指南（含来源 ID 引用行）
  source_refs_json TEXT NOT NULL,  -- {"rupture_event_ids":[…],"thread_ids":[…]}
  generated_at TEXT NOT NULL,
  PRIMARY KEY (tenant_id, user_id, version),
  FOREIGN KEY (tenant_id, user_id) REFERENCES principals(tenant_id, user_id)
);
```

**指标定义（对齐 Muse frontmatter `hatch_alignment_dream_v1`）**，窗口 `[window_since, window_until)`：

- `rupture_turns`：窗口内 `rupture_events` 行数（检测到的纠正轮次）。
- `user_turns`：窗口内 `role='user' AND source_kind='user'` 的事件数（按 `received_at`）。
- `correction_free_rate = clamp(1 - rupture_turns / user_turns, 0, 1)`；`user_turns = 0` 时为 `1.0`。
- `open_repair_threads`：生成时刻 `status='open'` 的线程数。

**再生成触发（SYNTHESIS_REFRESH_POLICY_V1）**：满足任一才生成新版本——
(a) 无任何历史版本；(b) 上一版本 `generated_at` 早于最新 rupture 的 `detected_at`；
(c) 上一版本 `window_until` 距今超过 24 小时。否则幂等返回当前最新版本。

## 2. rupture 信号规则（memory-domain，纯函数）

`memory-domain` 新增 `rupture` 模块（无 IO，与 normalize_v1 同层）：

- `RUPTURE_CUES_V1: &[(&str, &str)]`——(字面量, 信号名)，冻结清单：
  `("不对","correction")`、`("不是这样","correction")`、`("不是的","correction")`、
  `("你听错了","correction")`、`("你说错了","correction")`、`("你记错了","correction")`、
  `("你理解错","correction")`、`("你又","recurrence")`、`("别这样","boundary")`、
  `("不要再","boundary")`。
- `fn rupture_matches(content: &str) -> Vec<RuptureMatch>`：按清单顺序逐字面量 `find` 全部
  出现位置，返回字节 span + 信号名；同一字面量多次出现取首个。修改清单须升级为
  `RUPTURE_CUES_V2` 并新开扫描游标语义，禁止原地改 V1（沿用本仓库 Prompt/准入版本纪律）。
- 已知局限（如实记录）：中文否定/转折语境的误报（如"不是的"出现在引述中）由
  repair 线程的人工关线兜底；规则清单宁窄勿宽。

## 3. M1 · valid_until 到期转换规则

- 扫描：`status='active' AND valid_until IS NOT NULL AND valid_until <= now`，全 scope
  批量（单批上限 500）。
- 转换（每条同事务，沿用 correct 的 CAS 模式，`memories.rs:848`）：
  1. `UPDATE memories SET status='expired', version=version+1, updated_at=now
     WHERE … AND version=? AND status='active'`；
  2. `memory_revisions` 追加审计行：`actor_kind='system'`、`actor_id='memoryd'`、
     `reason_code='valid_until_expired'`、`previous_claim=new_claim=claim`；
  3. `stale_vectors_in_tx(scope, "memory", id)` + `mark_index_dirty()`（同 retire 路径，
     `lifecycle.rs:140`）。
- 只转状态、不删数据；retention 对 expired 的后续清理按 D6-9 既有策略，不因本卡变化。
- 调度：`serve` 内新增 15 分钟 tick 调度器（与 retention scheduler 平行，`main.rs:821` 模式）；
  CLI 新增 `memoryd expire-run --config <f>` 手动执行（两档都如实报告迁移行数）。

## 4. purge 闭包扩展（doc6 闭包纪律）

新表进入既有 purge/retention 闭包（`purge.rs`），规则：

1. **evidence 闭包**（逐 evidence 删除段，`purge.rs:399-422` 之前）：
   - 删 `rupture_events`（该 evidence 的行）；
   - 记录受影响 `thread_id`。
2. **全批收尾**：对失去全部 rupture 事件的线程 `DELETE FROM repair_threads`；
   `alignment_synthesis` 中 `source_refs_json` 引用了被删 rupture/thread 的版本行整行删除
   （SQLite `json_each` 判定；synthesis 是纯派生物，与 pages 的 purge 同待遇）。
3. 墓碑/审计语义不变：本扩展不新增墓碑类目，不写正文进删除账本（只计数）。

## 5. HTTP 扩展（v1 冻结契约不回改）

| 端点 | 语义 |
|---|---|
| `GET /v1/alignment/synthesis` | 返回最新版本行（无则 404 语义空对象） |
| `POST /v1/alignment/synthesis/refresh` | 按 §1.4 再生成策略生成/返回最新版本 |
| `GET /v1/repair/threads?status=` | 线程列表（默认 open） |
| `POST /v1/repair/threads/{id}/close` | 关线（body: `reason`；写 actor 审计） |
| `GET /v1/ruptures?limit=` | 最近 rupture 事件（诊断用，默认 50，上限 200） |

`POST /v1/context/compose` 增加可选字段 `include_alignment: bool`（缺省 false）：
- 缺省 false 时响应与旧版**逐字节一致**（v1 契约不变，旧调用方零影响）；
- true 且存在 synthesis 时，响应增加 `"alignment"` 对象（version/metrics/body），并在
  `text` 头部前置 `<alignment_synthesis version="N">…</alignment_synthesis>` 块；
- true 但无 synthesis 时行为与 false 相同。
