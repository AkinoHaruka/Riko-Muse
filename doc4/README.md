# doc4｜源码复核后的可靠性迭代

状态：**开发规范，尚未实施**。基线：根仓库 `main@a156540`，2026-09-25。本文档基于 `doc3/` 的只读审计及对当前 Rust/DSH 源码的再次静态核对；本轮编写文档时没有运行测试、服务或真实模型。

## 目标与范围

先修复异步提取作业的可恢复性、公平调度与窗口边界，使已持久化的证据不会因为一个坏窗口或一次进程崩溃而让后续提取停摆。然后增加只读诊断入口，让 held 候选和 dead/卡住的作业可见。继续保留 Rust 准入裁决、用户级隔离、同用户跨 Agent 默认共享和原始证据不丢的既定设计。

本阶段**暂停真实模型试验**。施工和验收使用确定性单测、临时 SQLite、固定响应、本机 HTTP，以及适配器的固定事件输入；不要求重新运行真实 DSH 会话。`extract_v3`、fact 自动放行、候选 promote、非指令常驻注入、embedding 和复杂巩固都不在本阶段实施范围；它们的决策条件见 [05](05-候选与召回的决策边界.md)。这不是宣称这些问题已解决。

## 规范优先级

1. 用户当前决定；2. 本 `doc4/` 对队列、窗口、诊断的增量契约；3. `doc2/` 的 DSH 接线和模型版本规则；4. `doc/10`—`15` 的 v1 契约；5. 其余背景文档。若本阶段必须改变旧契约，先按 [06](06-任务卡与验收.md) 更新对应文档，再改代码。`0001_init.sql` 与 `0002_prompt_version.sql` 均不可回改；新增持久字段使用新迁移。

`doc3/` 是调查材料，不自动成为产品规范。尤其其 C-4 把超限窗口描述成“三次重试后 dead”；源码实际是在读取窗口失败后直接返回，作业留在 `running`。本阶段以 [01](01-基线与问题复核.md) 的勘误为准。
