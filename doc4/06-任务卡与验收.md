**完成证据：**每项有当前源码路径/行号与“静态判断”标签。此卡只整理，不对现网状态作结论。

## 卡 D4-2：公平领取、退避与崩溃恢复

**先读：**[02 §2—4](02-作业状态机与调度.md)、`jobs.rs:123-211`。

**负责文件：**`memory-store-sqlite/src/jobs.rs` 中的 claim/recover/lower_bound，以及针对这些函数的确定性检查；不改 worker 模型客户端。

**实施：**把 retryable 到期条件改为 `run_after<=now`；每轮先条件化恢复 lease 过期 running；一次事务选可执行 job，跳过有未完成前窗的 session 而继续选其他 session；按 `through_event_seq` 判前驱和下界；claim 增加 generation 并写 lease。无 candidate 时返回 None，不能把被阻塞行反复取出。

**完成证据：**固定时钟覆盖未到期/到期重试、过期 running 一次恢复并增加 attempts、第三次 dead、同 session 顺序、A 阻塞 B 前进、99→100 的数字下界；检查 SQL 只查本 scope 的前驱，不跨用户串扰。

## 卡 D4-3：worker 的失败落状态与旧执行者隔离

**先读：**[02 §4—5](02-作业状态机与调度.md)、`worker.rs:686-822`、`jobs.rs:214-289,329-498`。

**负责文件：**`memory-server/src/worker.rs`、`memory-store-sqlite/src/jobs.rs` 中的续租/条件化写入、候选事务入口；必要的同模块检查。不得改 `extract_v1/v2` Prompt 或放宽 `admit`。

**实施：**30 秒心跳条件化续租；对模型请求设置取消与超时后及时停止心跳。任何已 claim 的错误都由外层分类写入 retryable/dead；`WINDOW_TOO_LARGE` 与未知 prompt 为确定性 dead。`save_candidate`、complete、fail 都核当前 generation，旧执行者结果不可提交。候选部分已写后中断，再执行同 job 仍幂等；不把“部分候选已保存”说成全批原子化。

**完成证据：**超限无模型调用且 dead；序列化/读库/坏 JSON/模型 timeout 各有可诊断状态；旧 generation 写入影响 0 行；模拟中途停止后能按 lease 恢复。此卡结束时不得留下新产生的永久 running。

**完成证据：**[03 §6](03-提取窗口与超限处理.md) 的 101 事件、32 KiB、单大事件、重放、skip/跨 scope/其他 dead 拒绝逐项成立；D4-4 阶段用 Store/CLI 查 dead，HTTP 列表由 D4-6 补齐。模型调用次数由固定计数器检查，无真实 API 调用。

**先读：**[03 §5](03-提取窗口与超限处理.md)、`adapters/dsh/src/events.ts`、`spool.ts`、`doc2/03`。

**实施：**每 session 80 已接受正文事件或保守 24 KiB 排 flush；`push` 返回 accepted，仅已接受事件推进 lastBodySeq/latestUser/计数；原有 `turn/end`、spool/receipt/发送链语义不变。达到阈值时多次 flush 的 opId 和 through 必须递增，不能重复排已 ack 窗口。
