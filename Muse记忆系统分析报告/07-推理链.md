# 07 · 推理链（关键结论的证据→推理）

> 每条：结论 → 证据 → 推理过程 → 置信度。

## R-1：附录 D 的 rewrite 契约被源证据验证

- 结论：extract_v4 的 rewrite 输出应为 {claim（改写后）+ quote（原文）+ speaker}。
- 证据：[源-Schema] memory.claims 同时有 `claim_text`、`quote`、`speaker` 三列（02 §2.1）。
- 推理：生产 schema 证明 Muse 的线上系统就是"改写命题与原文 quote 并存"。附录 D 在没看到 schema 全表时独立设计出同一契约，说明设计收敛到同一最优解。
- 置信度：高。

## R-2：Riko-Memory 的 ScopeKey 覆盖不了 side-chat 隔离

- 结论：twin 需新增会话级隔离（M5）。
- 证据：[源-文件] `side-chats/<chat-id>/MEMORY.md` 存在（04 §4.1）；Riko-Memory `ScopeKey{tenant_id, user_id}` 源码实测（无 chat 维度）。
- 推理：X 有三级隔离（tenant/user/chat），Y 只有两级。按 X 为准，差的一级要补。
- 置信度：高。

## R-3：bank/ 的"文件形态"是附带的，"蒸馏维度"是本质

- 结论：twin 做 DB 蒸馏视图，不做 bank/ 文件（真 Z）。
- 证据：[源-文件] bank/world.md 条目是 MEMORY.md 的分面重排，内容无新增（04 §4.2）；[源-文件] bank/ 由 runtime 拥有、agent 只读（目录实测）。
- 推理：bank/ 的价值是"四个维度"（experience/opinions/reflections/world），不是"四个文件"。维度可以用 DB 查询实现，文件只是 Muse 实现的载体。X 为准的是维度，不是载体。
- 置信度：中高。

## R-4：md 文件真相源的取舍是双写一致性 vs 可读性

- 结论：真 Z 为"双写一致性成本"（待主人拍板）。
- 证据：[源-文件] D7——条目带 (src: 文件:行号)，证明双轨真实存在且有维护成本；Riko-Memory 源码实测 DB 单一源。
- 推理：双轨的好处是人可读可改，代价是文件↔DB 漂移。单用户本地部署场景下，可读性需求低，DB + 导出视图可替代。这是一个真实的工程权衡，不是"可要可不要"。
- 置信度：中（取决于主人对可读性的权重）。

## R-5：0-active 的根因是 prompt 与门的矛盾，不是模型能力

- 结论：extract_v4 加 rewrite 步骤，门不动（已交付附录 D）。
- 证据：Riko-Muse 源码 `EXTRACT_SYSTEM_PROMPT_V3` 原文（"不得补写主语"）；admit_v2 UNCLEAR_SUBJECT 门；两轮验收 0-active 跨模型复现。
- 推理：prompt 禁止补主语→产出无主语候选→门全扣下。两模型均忠实执行，排除模型变量。R-1 的 schema 证据进一步说明：生产系统用"改写"解决此矛盾，而非放宽门。
- 置信度：高。

## R-6：产品层四任务（Idea/Studying/Skill review/Quiet-moment）可暂缓

- 结论：真 Z 为"产品层功能，twin 无对应 Tab/场景"。
- 证据：[源-文档] 四任务的输出物都是 Tab（Ideas tab、Goals tab）或技能系统。
- 推理：X 为准的是"记忆系统"，这四个的输出物在产品层。twin 第一版无这些产品面，做了也无处交付。注意 D5/D6 的细节（隐式目标检测、技能退役）在将来做时要用。
- 置信度：中高。
