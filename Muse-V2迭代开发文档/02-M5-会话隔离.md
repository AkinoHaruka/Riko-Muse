# 02 · V2-S1：记忆域与 side-chat 隔离

> 依据：[报告 04 §4.1](../Muse记忆系统分析报告/04-源证据-文件层实物.md) 的 side-chat 文件与隔离观察。
> 源文件存在能支持“有独立记忆”；不能证明 Muse 的完整跨检索权限、主域继承矩阵或 privacy_class 取值。下面矩阵是本项目明确选择。

## 1. 保留身份 scope，另建记忆域

当前 ScopeKey 仅 tenant/user（memory-domain/src/lib.rs:11-14），Origin 已有 host/agent/session（:18-22）。session 是 L0 事件来源，新增隔离不能把每个普通 DSH 会话变成私有库，否则破坏“同用户跨 Agent 默认共享”。

保留认证 ScopeKey；增加独立 MemoryDomain 和 ReadDomainSet，服务端由 Bearer 身份、可信宿主会话绑定及已配置策略解析。domain_id 是存储边界，session_id 是来源标识，多次会话可以绑定同一域。

不要照原稿给 ScopeKey 加 Option<chat_id> 然后全局替换；身份隔离与记忆选择是两件事。不要给所有 people 表任意补 chat_id，必须按实体来源域建立投影。

## 2. 默认读写矩阵

| 当前回合 | 写入域 | 默认读取 | 显式扩展 |
|---|---|---|---|
| 普通主会话/普通 Agent | user_main | user_main | 仅获授权的 side 域 |
| side A | side A | side A + user_main | 获授权的 side B 等 |
| side B | side B | side B + user_main | 获授权的其他域 |
| Dream/Relationships/upkeep | 冻结输入所属域的派生结果 | 该作业获授权的同域输入，按策略可含主域 | 不因后台权限自动全域读取 |

side 继承主域是本项目兼容选择，非 Muse 已证实规则；如后续观察要求完全独立，可通过新 profile 调整，旧策略按版本冻结。主域不会自动看到 side 内容。

普通记忆工具的跨域 opt-in 只表达请求，不能自己授予权限。可信用户/管理员配置授权，Rust 计算交集；Agent 任意写 domain_id/chat_id/全域标志均不能提升权限。跨域读取结果带 domain 来源标记，默认不写回主域。显式发布到主域需用户依据、审计和重新准入。

同用户域隔离解决默认可见性；更严格的侧聊授权需服务端 host/session 绑定。现有同用户 Bearer 并非独立会话凭据，不能把一个 JSON 标签声称为强访问控制。

## 3. 拟议新增模型与全链路约束

| 对象 | 约束 |
|---|---|
| memory_domains | (tenant,user,domain_id) 主键；kind=user_main/side；状态、policy_version、创建依据 |
| session_domain_bindings | (tenant,user,host_id,session_id) 唯一绑定；由可信宿主注册/管理员配置，普通 Agent 不可改 |
| 对象域归属 | memories、候选、作业、派生页面、实体、alignment、缓存/索引关联域；组合外键或 Rust 同域校验 |
| 证据域映射 | L0 原事件保持来源身份；新增映射记录 domain；提取窗口不能横跨未经授权的域 |
| 跨域授权记录 | 可信配置下的授权与审计，不由模型提供 tenant/user |

精确去重、claim hash 查找、reinforcement、correct/supersede、retire/restore、suppressed_sources、purge 墓碑匹配、FTS/grams、semantic、Resident、页面及 Dream 读取都必须审计域影响。不能只在 compose 最后过滤；候选集、排序、计数、分页及直接 get/explain 都要在许可域内。

同文记忆在 main 与 side 默认保留各自身份，不跨域 dedup，不跨域更新旧版本，也不泄露另一域的存在。已存在 evidence 的重放不得更改域；同事件绑定冲突明确拒绝。后台结果可见域不得比来源更广，多域派生取共同许可范围，空交集不发布。

## 4. 升级与兼容

新增迁移从 0015 起，号段按 06 分配。旧数据归 user_main，保留原 tenant/user、ID、版本、证据与内容。服务未启用 V2 profile 时继续历史主域行为；side 功能启用后，旧客户端不带选择器也只能使用其可信绑定的域，不能越界。

“NULL=主会话，零迁移风险”的原说法删除：去重键、游标、索引、后台作业和缓存都可能产生风险。迁移在临时副本验证，禁止新 Store 打开 dana/realtest 原库。尚未获授权的 side-to-main 迁移不自动执行。

## 5. 删除与失效

域关闭、域级 forget/purge 均需可信用户/管理员入口；普通 Dream 不获 purge 权限。已有 forget/retention 政策照旧，新增域不扩大删除权。

域级清理覆盖原子记忆、派生内容、关系索引、entry/向量、缓存、审计副本、作业冻结输入及可再生源；跨域发布副本须在影响预览中列出。保留合法的无关主域事实；不能以“删 chat”整库清空。共享原始证据的物理删除必须按完整闭包与其他合法引用核算，不能破坏无关来源。

## 6. 验收

覆盖 main/A/B 三域：主读不到 A，A 默认继承 main 但读不到 B；授权跨读成功且有来源标签；无授权的 opt-in 和猜 ID/get/explain 均不可见。

同 quote 的 main/A 写入不相互 dedup；A 的更正/遗忘不污染 main；实体索引、alignment、蒸馏和向量也不能串域。正常同用户新会话仍共享 main。断电重试、spool 重放和迁移后域归属不漂移。
