# 01 · V2-R1：人物与群组记忆、延迟读取

> 原文件名 M4 保留；doc7 的 M4 已是 extract_v4。本卡不复用该编号。
> 依据：[报告 01 §1.2](../Muse记忆系统分析报告/01-源证据-系统提示词.md)、[03 Relationships](../Muse记忆系统分析报告/03-源证据-官方文档.md)、[04 §4.3](../Muse记忆系统分析报告/04-源证据-文件层实物.md)；更细页结构见 [Muse文档 01 §1.5](../Muse文档/01-存储层.md)。

## 1. 可观察目标

Muse 常驻注入 people/groups 的索引，相关回合再读详情，人物页保留 facts/history/relationship；同名、昵称、角色称呼和 scheduled handoff 都可能触发读取。亲近度排序存在，计算算法未知。

本卡交付“索引→识别实体→读取详情→按当前证据回答”完整路径。单纯按亲近度注入前五人的摘要不能覆盖该行为，会漏掉相关但不在前五的人，也无法核对详情。

## 2. 数据契约（拟议，不是 Muse 原始 DDL）

复用 V2-S1 的 domain_id。每张表包含 tenant_id/user_id，组合外键保证同 scope/domain；不能出现原稿“文字承诺隔离、DDL 没有隔离列”的情况。

| 对象 | 必需字段与约束 |
|---|---|
| relationship_entities | id、tenant_id、user_id、domain_id、entity_kind(person/group)、slug、display_name、summary、closeness_rank(可空)、version、status、updated_at；slug 只在 (tenant,user,domain,kind) 内唯一 |
| entity_aliases | entity_id、alias、alias_kind(name/nickname/role)、来源引用；同一别名允许多个实体，必须返回歧义 |
| relationship_items | entity_id、section(facts/history/relationship/in_common/open_threads/strengthening)、body、occurred_at、valid_until、observation_or_inference、confidence、version |
| relationship_sources | item_id、memory_id、memory_version、claim_sha256、evidence_id、span、source_domain_id；至少一个有效来源 |
| group_memberships | group_id、person_id、关系与来源；组合外键/服务端检查保证同 scope、可见域 |

禁止只有 facts_json/history_json 而没有逐条来源；删除一条原子记忆时必须能定位所有受影响正文。多字段共享同一证据可以，但不能把一个引用当成整页所有推断的依据。

索引条目返回 entity_id、kind、display_name、aliases、role、简短 summary、version、详情引用、更新日期及有依据的 rank。role 仅展示证据明确支持的称谓，不自动把高频同事解释成亲密家人。

历史按发生时间而非提取时间排列，修正保留受控历史链；默认详情只展示当前有效事实。“history”不是绕过过期/遗忘过滤的通道。

## 3. 亲近度与实体归并

排序规则为本项目选择，不能写成 Muse 已知算法：优先用户明确关系/排序，再用已核实的关系角色；未知 rank 排末并稳定按 ID 排序。提及频率只作检索相关性，不自动变成亲近度。用户纠正排序或身份时使用版本检查更新并审计。

“老王”与“王老师”只能在上下文和来源明确相同时归并；重名、代词指向不明则不合并。group 成员关系也需要来源，不能根据同场提及猜成员。保留实体拆分/合并审计，避免误归并扩散到历史、别名和页面。

## 4. Relationships 维护

默认每小时检查新信号；无变化不调用模型。周期来自官方任务定义，“仅新信号才调用”是本项目成本设计。实现复用受控作业基础设施，不直接给 Agent 任意写表权限。

输入冻结：domain、截止事件水位、可见实体版本、已保存 memory/evidence 引用。输出是逐项带来源的更新建议、身份归并建议和排序依据。Rust 复核来源、域、版本及准入；同代际提交实体、来源、审计和索引失效。失败不推进游标；过期租约结果不应用。重试使用同一冻结输入，不能重新抓所有对话。

角色/别名可据已准入事实构建；assistant 叙述、网页或模型推断不能冒充用户表达。派生建议与观察明确分栏，空的 open_threads/strengthening 保持空，不为填字段编造内容。

## 5. 与 THIRD_PARTY 的政策冲突

当前 extract_v4/admit_v4 仍可能把涉及第三人的候选 held（源码 memory-extract/src/lib.rs:518-519）。原稿“只挡敏感第三方”与现行自动门不符。

V2 默认只投影合法 active 记忆中的用户关系及已有用户直写内容，继承来源可见性；held 候选不得成为已核实人物事实。维护任务不能自设宽松准入，也不能复制 held 正文到人物页规避该门。remember 的既有直写政策保持不变。

如需自动保存人物本身的非敏感事实，须先在 doc7 明确允许类别、speaker/subject 区别、敏感细节处理、证据规则和用户更正入口，再新建准入版本；历史 admit 版本冻结。该政策目前未决定。验收分别记录“关系投影通过”和“完整人物事实覆盖受限”，不能合并为 Muse 等价。

## 6. 索引注入与按需读

拟议读接口：index(domain/pagination)、get(entity_id, expected_version)、resolve(query/context)。所有参数先由服务端解析可见域，再查实体，猜 ID 也不能越域。名称解析无结果或多结果时返回明确状态。

DSH V2 profile 每轮注入有预算的 people/groups 索引数据，不注入全页。预算外条目保留检索入口和省略数量；与当前回合有关的条目优先，高 rank 不排挤相关实体。详情经工具读取，不用索引摘要替代已要求的核对。

触发纪律覆盖明确名字、昵称、角色称呼、代词（上下文可解时）、兴趣/活动对应群组、工具/计划任务 handoff。针对已识别实体的事实性回答和推荐须先读取当前页；歧义时不猜。

无关回合不展示人物细节；引用应与当前任务有明显关系。页中的文字作为有来源数据，不可作为 system 指令执行。

## 7. 生命周期与验收

失效来源使受影响条目不可注入，至少先 stale 后重建；别名、摘要、rank、成员关系也在闭包内。forget 阻止旧内容重建，purge 清正文、旧版本、缓存、向量、引用副本与作业输入中可反查文本；其他人物无关条目保留。来源域不得通过全局人物索引泄露。

验收：昵称命中且先 get 再回答；同名不误并；代词和 handoff 能触发；相关的第六个人不会被 top-5 丢掉；side 私有实体不进主索引；更正角色后旧描述消失；遗忘其中一条事实后各投影与索引不再包含；held 第三人候选不被后台激活。
