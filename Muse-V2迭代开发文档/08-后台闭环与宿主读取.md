# 08 · V2-B1 / V2-A1 / V2-H1：后台内化与实际使用闭环

> 依据：报告 01 的记忆/关系使用纪律、报告 03 的后台任务定义、报告 04 的 dated dream 与 alignment 实物。
> 后台 prompt、具体成本与去重算法未观察；本文是可实现的补足方案。

## 1. 职责与时机

即时记忆仍由 Agent 在重要变化出现时调用已有 remember；只有成功才声明保存。普通 turn/end/flush 捕获 L0/排队，不直接调用 LLM。已存在 extraction 与 Dream 管线复用，不能把每个后台任务再做一遍重复提取。

| 任务 | 证据频率 | V2 调度选择 | 产物 |
|---|---|---|---|
| extraction / upkeep | upkeep 有新信号时 hourly，且不替代会话即时写 | 保留主线 extract_v4 队列；每小时只对尚未整理的有效信号合并、精炼 | compact、日期轨迹、四分面；冲突提议 |
| Relationships | hourly | 每小时检查实体/关系变化；来源无变化零模型调用 | 实体页、索引与来源版本 |
| Dreaming | nightly | 用户时区夜间一次；只处理新窗口，确定性指标与来源模板仍保留 | dated reflection、repair actions、具体 synthesis |
| Quiet-moment pass | substantial conversation 沉寂后、有界、每日数次 | 默认沉寂 20 分钟且有未消化重要信号，最多 3 次/用户/日；参数可配置 | 小规模内化，复用 upkeep/反思写入，不直接发送消息 |

20 分钟、3 次是本项目初始参数，不是 Muse 实测常量；“substantial”以未整理有效记忆/纠正/承诺变化判定，纯工具日志不算。普通事件回调只登记信号；定时器识别静默后经受控调度入队，保持 end/flush 无 LLM 规则。受限 child 的输出不作为真实用户事件重抽取。

quiet 与 hourly/nightly 以同一处理账本记录已消化的 event/版本/任务能力，防重复提取、重复强化。每种任务不同产物可共用来源，但重复来源不能重复算“强化次数”。无新信号不造新版本。

已有 Auto Dream 默认启用及用户可关闭能力保留；新的 upkeep/relationship/quiet 开关分别配置。需要启用/停用某任务时不能偷偷改变其他已批准调度语义。

## 2. 可靠性契约

复用 D6 作业的能力，但不能只写“用现有队列”：

- key 包含 scope/domain、task_kind、窗口/水位、generator_version；输入冻结事件 ID、memory/实体/页面版本和策略版本。
- manifest 按许可域构造；只读 source 引用由内核提供，模型返回受控引用位置，内核解析，不赋予模型随意选 evidence 的权力。
- queued/running/retryable_failed/provider_wait/dead/stale_input 明确；租约、claim_generation、provider 冷却、取消、最大尝试继承现行可靠性设计。
- 网络调用不持 DB 锁；返回后复核代际、来源、授权和版本，过时结果弃用/重新入队。
- 输出、来源、审计、dirty/stale 与处理水位按原子语义提交；失败不越过未完成信号。重试不替换冻结输入，不吞失败当成功。
- 每次运行限制输入事件/字符、输出条数、token、模型调用数；以配置硬上限拒绝超限，日志只记安全错误码和计数。
- 借用现有 Dream runner 时继续 job-scoped 能力与受限 child；当前 seam 不足时更新源码核对记录和规范，不能将普通 worker 改名 subagent。

小时/夜间任务可在同一次受控调用中返回多个合法派生产物，减少纯润色调用。token/费用限额按 provider 和产品配置显式分配，运行回执记录实际调用与结果；不猜 Muse 成本。

## 3. nightly 复盘与具体 alignment

当前确定性 rupture_scan 和 synthesis 作为冻结基线保留。V2 新版本增加反思结果，不能静默回改当前规则或把统计指标解释成完整用户人格。

输出至少包括：

| 产物 | 必需内容 |
|---|---|
| reflection | 窗口、做对/做错、哪些变化有证据、哪些是暂定理解、下一步建议；每段 source refs |
| repair item | 具体错误话题/行为、用户期望或边界、修复行动、证据、状态、复发记录 |
| action synthesis | 当前可执行的沟通/工作调整、适用条件、反例/禁止重复行为、来源与版本 |
| progression | 本次与上次的新增/改变/撤销，修复是否得到用户/可验证结果支持 |

例如用户多次拒绝催睡，输出“避免未经请求重复催睡”，引用对应纠正；不能仅输出“避免重复同类纠正”。推断用户模式时标 uncertainty，不能把一次生气归纳成长期人格。

rupture V2 区分对 Agent 的纠正、自我修正、第三人引语和中性讨论；针对交接 25 的自我纠正 FP 与“上次你说错导致损失”FN 加入预标注案例。确定性高置信信号可先标记；模糊语境只进入受限后台复核，不每轮新增 LLM。新增 detector_version，保留历史统计所属版本，不把改变后的指标直接同比。

线程按有来源话题/问题归并，不能把 7 天内所有错误自动归成一条。相同话题复发关联同 repair，歧义保持分开；title 不沿用已判误报的事件。关闭必须有授权与理由：用户明确关闭，或已批准的可信状态转换规则及可定位修复证据；单纯没有新纠正不证明修复。模型只能提议关闭，不直接写最终状态。

全部派生在 user-role；不得修改 Soul、植入未经用户确认的长期指令、自动履行外部行动或恢复已遗忘细节。统计指标仍由 Rust 算，不由模型自报。

## 4. standing context 与按需读取

当前 makeBundleHook 只消费 resident/retrieved；当前 compose opt-in alignment 不会自动出现在这一路。V2 必须扩展 bundle 与 adapter 同步消费，而不是只加 include_people HTTP 参数。

V2 profile 的 bundle 输出分段：compact/Resident、alignment、people/groups index、retrieved；每段含域、版本/来源和完整性状态。总预算由服务端统一分配，索引/摘要/正文分别有上限；不能像简单拼接 alignment 那样预算外无限前置。重复原子来源合并，截断保留引用完整，省略数量和按需读入口可见。

只有用户/管理员 Soul 在 system-prompt/assemble；其它段通过 agent/pre-step 在原始用户消息前插 user-role 数据消息，用 source.kind/form 明确标为插件上下文。继承 DSH signal、决策去重和错误状态；中途话题/来源/域变化刷新。数据中的任意文本不能当成宿主指令。

工具增加关系 index/resolve/get、分面 read、memory_explain 和稳定引用支持；原 memory_search/get/remember/correct/forget 保持协议及证据获取纪律。所有工具直达接口与自动 bundle 用同一可见性判定。

使用纪律由受控插件说明提供：重要变化即时保存；每个新用户回合进行有界回忆检查，已有 bundle 算一次检查，话题相同的工具 step 可复用；相关人物事实/推荐先 get 页；片段不足先精读；问来源用 explain；不确定/索引滞后查规范源；成功前不说保存。

每轮相关信息可通过 bundle 快速进入模型；需要更广的检索时可用 2—3 个相关问法。多问法是读取设计，不能作为由 Schema 证明的 Muse 内部算法。
