# 04 · V2-P1 / V2-Q1：溯源、稳定寻址与检索上下文

> 依据：[报告 02](../Muse记忆系统分析报告/02-源证据-数据库Schema.md) 的 claims/entries/embeddings，报告 01 的 memory_explain 纪律，以及 [Muse文档 04](../Muse文档/04-读取与检索管线.md) 的工具观察。
> Schema 是字段证据，不证明写入阶段、关联基数或完整查询执行顺序。

## 1. quote、speaker 与多来源

当前已经有 memory_candidates.quote、memory_evidence 的 evidence_id/UTF-8 span、evidence_events.role/content。缺口是普通 get 未返回 quote/speaker，且没有完整 explain 工具；不是“系统没存原话”。

首选新增读取模型，沿版本化引用把原文重建出来，而非直接给 memories 填单个 quote/speaker：

| 返回项 | 来源与要求 |
|---|---|
| claim | 当前改写正文；不得把 quote 当成新版正文 |
| evidence[] | 每条 evidence_id、span、逐字 quote、role/source_kind、发生时间、域与验证状态 |
| speaker | 谁表达了该证据；user/assistant/tool 是角色，具体人物身份只在来源明确时提供 |
| subject | 命题描述的主体，与 speaker 区分；用户说朋友喜好，不等于朋友本人表达 |
| versions/relations | 当前版本、纠正/替代的前后关联、有效期、状态 |
| reason | 当时的保存/准入 reason_code，若有独立记忆动机文本则单列 |
| stable_ref | 服务端生成的持久地址、当前版本引用和来源引用 |

证据会强化、同条记忆可能多来源，单个 quote 列会丢其余依据。逐字摘录按 UTF-8 字节 span 读取，不能折叠空白、拼接、由模型重写。NULL span 只可标明整事件引用，不能假装拥有精确 quote。

若以后需要 inline 缓存，必须绑定 evidence/span/source_version，禁止作为第二真相源；旧行未知值保持未知，不从 claim 推测原话。无需为兼容 Muse 字段形状强制新增重复列。

## 2. memory_explain 与当前精读缺口

拟议 API：`GET /v1/memories/{id}/explain` 与 `memory_explain(ref)` 工具。路径仅为 V2 设计，当前路由不存在。输入可为 memory_id、服务端 stable URI 或版本化导出引用，不能让模型制造 evidence ID。

普通 memory_get 提供当前 claim 和授权证据摘录；explain 提供前后替代链、已核实 speaker/quote、首次见到/强化时间及保存原因。仅在显式历史/核对请求且授权满足时返回历史；forgotten/purged 的正文不因 explain 复活。已删引用返回 withdrawn/not_found，不能从旧缓存恢复。

当前 direct get 只读 active，但源码 memories.rs:442 起没有自身 valid_until 复核；V2 把到期、retired、source stale、域权限统一为所有读接口的可见性判定，不能只依赖调度器迟后转状态。

claim_sha256 是内容指纹，不是稳定外部地址：更正正文会改变 hash；同文在不同域也不是同一实体。当前 memories.id 为独立主键。stable_ref 应由内核用 scope 内对象 ID 生成并在访问时认证，版本引用另带 version；重排文件或改写正文后可沿关系解释，不能猜 hash 即等于 Muse claim_id。

reason_text 表示“为何记录”，证据只能证明“从何得知”，两者不能等同。没有动机文本时返回 null/unknown，不能事后从 quote 编一个理由。V2 先暴露已有准入/写入原因；未来生成动机文本时注明 generator 和版本。

## 3. entry / chunk 上下文对象

Muse entries 有 title/body/line range，embedding 外键指向 entry；报告没有展示 entry↔claim 的显式关联，因此“先检索 entry 再取其所有 claims”是拟议方案。

V2 新建/扩展版本化 context_entries（ID、domain、title、body、source_type、可见策略、version、source_fingerprint）和 entry_sources（memory_id/version、证据定位）。优先从合法 active 原子记忆、人物页、派生页组织上下文；原始 L0 按独立权限精读，不能把同块里的 held、敏感或另一域正文一起注入。

条目摘要与逐字证据清楚区分；完整段落不能都称 quote。一个 entry 可支持多命题，一命题可有多 entry；关联与基数是本项目选择，需显式来源校验。

隐私分类与域规则联合判可见性：分类标签不能替代鉴权，不把 Muse 未知 privacy_class 值硬映射成 chat_id。先支持本项目明确的来源域与公开范围，其他分类待政策定义。

## 4. 当前检索基线与增量

已核实：

- migrations/0008 的 semantic_vectors 支持 memory/page 对象、model_id/dimensions、source_version/hash、ready/stale。
- memory-server 的 /v1/context/bundle 支持已配置的语义支路；未配置时 disabled，失败时降级。旧 /memories/search 和 /context/compose 仍走词法路径，不能混称全部端点已混合检索。
- 交接 17 §8.9 有真实零词法命中记录；交接 19 有无关 query 误召回。代码存在与质量通过必须分开。

V2 不废弃 claim/page 召回来盲目照搬 entry。新增 entry 召回作补充，与现有词法+语义进行同语料对照，统一合法来源后再融合；避免同源重复打分、长块压过精确命题、关联上下文混入未准入事实。

新 entry 向量绑定版本和内容 hash，模型/维度隔离；更正、过期、retire、forget、purge 同事务失效并清依赖。延迟索引期间可通过规范源直接 get 已成功保存内容；search 空不等于未保存。不能在 response 中说已保存但实际写入失败。

检索输出包含 stable ref、来源与当前版本、matched_by/semantic_status、必要上下文；相关事实回答经 get 核对，用户问依据经 explain。多问法查询及缓存按话题/域/源版本复用，预算与频率明确；不是每个工具 step 无限重复模型查询。

## 5. salience、元数据与质量

报告 claims 表明确列 salience；Riko 无此列只说明实现差异，不说明 Muse 不存在。字段取值、计算方式与排序作用均未知。V2 暂不伪造三档或权重，采用现有可解释优先级并记录行为差异；必要时以真实排序样本决定是否增加 salience 表达。

entry_attributes 作为有需求的扩展，不能用任意 KV 绕过类型、域或来源校验。Riko 已有 schema_migrations/index_state 等元数据，不应将“没有 Muse 同名 metadata 表”认定为功能缺失。

Q1 对照使用预先标注的相关/不相关、跨语言、同义、旧值、关系歧义、多来源和上下文依赖问题；测 recall/precision、答案正确性、引用正确性、无关个性化、延迟、token 与失败降级。新增 chunk 必须改善预定的上下文用例且不增加未准入事实引用；不能只用 active 数或单次 top-K 命中作质量结论。
