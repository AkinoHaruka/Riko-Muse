## 结论与目标

原稿补上了关系、会话、蒸馏三个方向，但不足以按证据接近 Muse：把建表当成关系能力，把四个 kind 查询当成蒸馏，把后台任务和宿主接线当作已经覆盖，遗漏了完整读取与溯源流程。修订版以可观察行为为目标：持续记住重要变化，回答前查阅相关关系与证据，后台整理后在下一轮实际起作用，更正与遗忘后各层一致。

这是“观察能力的复现”，不能据此宣称与 Muse 内部算法一致。报告未提供后台 prompt、排序公式、完整索引同步实现；这些空白用本项目设计补足并明确标注。证据纠偏见 [07](07-证据矩阵与推断纠偏.md)，本轮修改依据见 [09](09-本轮核实与修订记录.md)。

## 与 Muse 的明确偏离

Rust 继续是身份、准入、来源和生命周期裁决者；DB 是唯一规范源。提供人可读、带稳定引用的 Markdown 投影，而不让文件与 DB 独立双写。所有派生理解进入 user-role 数据上下文；只有用户/管理员编辑的 Soul 进入 system。后台复盘不得编辑 Soul。

人物第三方信息是实质差距：自动提取目前有 THIRD_PARTY 门，不能通过维护任务偷绕。V2 先从已合法保存的、关于用户关系的证据派生；无法合法入库的第三人细节继续 held。要覆盖 Muse 更广的人物事实，需要独立产品政策决定，见 01 §5。不得把这个差距标为已解决。

Idea/Studying/Skill review 产品面暂缓；quiet pass 和有来源的复盘已纳入核心。外部产品面缺失不是排除所有后台内化的理由。保留 salience/privacy_class 的证据与语义问题，不再标“已证伪”；不盲目照搬字段或未知算法。
