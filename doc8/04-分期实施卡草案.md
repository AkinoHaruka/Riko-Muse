# 04｜分期实施卡草案（F1—F9）

本文件把 doc8 的目标架构切成可独立验收的实施卡。切分原则：格式与协议先行、读写分离推进、每卡有明确停止条件、存储切换放在可回滚的位置、部署切换单独成卡。任一卡触发停止条件，回到规范修订，不许静默改契约（03 §7.3 的 🔴 规则）。

对应关系：03 §11 的八条设计验收不变量是全程总验收；每卡只认领其中可独立证明的条目，F7 汇总全量复验。

## F1｜文件格式与块语法基座

- 范围：`file_store_v1` 格式定义（FORMAT.toml、evidence 定界块、claim/soul/operation/receipt/fence 文件语法）、规范化规则（UTF-8/LF/NFC、字段顺序、hash 覆盖范围）、块解析器与写入器、quarantine 判定与报告格式。
- 不做：不实现 Store 读写、不接 HTTP、不碰现有 SQLite 代码路径。
- 前置：无（doc8 拍板通过即开工）。
- 验收：语法 golden 样例全过；同一内容解析→序列化→再解析逐字节稳定；证据块在正文含相同注释标记时不截断（按 content_bytes 定界）；坏块（hash 不符、ID 重复、版本倒退、悬空引用）全部进 quarantine 且给出机器可读原因。
- 停止条件：出现无法用定界块+front matter 表达的现行语义，回报规范层，不私自扩语法。

## F2｜Generation 事务引擎（硬骨头 H1）

- 范围：staging → MANIFEST → `CURRENT` 原子指针协议、scope 写锁（单写多读快照）、fsync 顺序、启动恢复（未提交 generation 的判定与隔离）、receipt 幂等落盘。
- 不做：不实现任何业务对象语义，只跑通假对象（dummy claim）的提交与读取。
- 前置：F1。
- 验收：故障注入矩阵——在写入每一步 kill -9，重启后只见旧或新 generation（不变量 3）；同幂等键并发提交只产生一个效果、异请求同键返回冲突（不变量 4）；多读请求各自固定快照不混读。
- 停止条件：任一崩溃点出现半状态且协议层无解，停工回规范，不许用「概率够低」放行。

## F3｜文件后端读路径与索引层

- 范围：以 `storage.backend` 开关接入文件后端（只读模式）；可见性谓词的文件实现；索引构建（FTS5/grams 投影、visibility/backlink 投影）与全量重建协议、index generation 原子切换、degraded 报告与刚写入对象的有界 delta scan。
- 不做：写路径仍走 SQLite；向量索引留 F5 一并处理。
- 前置：F2。
- 验收：删除全部 index 后可从规范文件重建出相同 active ID/version/status/source 集（不变量 1）；同一组 HTTP 读 fixture 在双后端返回语义等价（不变量 2 的读侧）；重建期间旧索引继续服务且 degraded 标记准确。
- 停止条件：golden 查询出现无法归因的排序/召回差异且非浮点并列问题。

## F4｜文件后端写路径：核心对象

- 范围：evidence 捕获、candidate/准入裁决落盘、remember 直写、claim 状态机与 supersede CAS、Soul 文件后端（版本/CAS/history、按 agent 隔离）、principal/scope 路径安全（H4 的路径层）。
- 不做：派生视图、后台作业、forget/purge 闭包（F6）；不接部署。
- 前置：F3。
- 验收：HTTP 写 fixture 双后端语义等价（不变量 2 全量）；span 逐字复核在文件后端成立；actor/scope 伪造用例（改 front matter 冒充、路径穿越、symlink 跳转）全部拒绝并隔离（不变量 7 的写侧）；Soul 2000 标量上限与 CAS 冲突语义与现行一致。
- 停止条件：任一现行准入/状态语义在文件形态下只能靠放宽规则实现，回规范。

## F5｜派生视图、向量与上下文包

- 范围：compact/facets 四 bank、派生页面、关系图谱与 resolve、alignment 合成、向量分片与重建复用规则、context bundle 四段组装（顺序与 8000 预算不变）、Resident pin 的文件形态。
- 不做：后台调度（F6）；派生算法本身不改（facet_v1 等冻结）。
- 前置：F4。
- 验收：bundle fixture 双后端逐段等价（顺序、预算、去重、空段、omitted/complete）；来源变更后派生即时不可见（不等待重建）；向量按 (id, version, hash, model, dim) 复用/重算规则有计数证据；pin/unpin 走 mutation 而非直接改总览文件。
- 停止条件：bundle 延迟基线明显劣化且无索引层解法，先回报再定。

## F6｜后台闭环、作业租约与遗忘闭包（硬骨头 H3/H5）

- 范围：dream/background job 的文件状态机与 lease、ledger/task_runs 的 operation log 形态、repair 授权事件、commitments、forget fence 与两阶段 purge 的文件闭包（含旧 generation、索引、归档的擦除策略与报告口径）。
- 不做：不改任何作业的触发条件与模型调用逻辑。
- 前置：F5。
- 验收：多 worker 争抢同一 job 的状态机模型检验，效果恰好一次（不变量 5 的作业侧）；forget 后源、派生、索引与未来 producer 均不可活动使用（不变量 5）；purge 报告准确区分已擦除 / 归档保留 / 外部备份限制（不变量 6）；无信号时零模型调用。
- 停止条件：lease 在故障注入下出现双跑且状态机无解；purge 闭包存在无法界定的残留面。两者任一出现，停工回规范。

## F7｜契约复验与影子读

- 范围：适配器 54 项契约测试对文件后端全跑；真实 DSH 多轮闭环（事实/偏好/指令/supersede 纠错/四段注入/Dream 工具隔离/新会话问答）；shadow-read 差异摘要工具（双读、只回旧后端、去正文差异记录）。
- 不做：不切换任何部署；适配器代码零改动是本卡的被验对象而非工作内容。
- 前置：F6。
- 验收：不变量 8 全量成立（契约 54/54、闭环全过、适配器零改动）；shadow-read 在约定语料上差异为零或全部可归因并已修。
- 停止条件：发现必须改 HTTP 契约才能等价的端点，按 03 §7.3 标 🔴 回主人拍板，不许先斩后奏。

## F8｜schema 24 转换器与核账（硬骨头 H7）

- 范围：只读转换器（专用 immutable 连接）：逐表计数、主键集合 hash、正文 hash、引用闭包、状态分布、unmapped 报告；转换产物为完整 generation；转换后引用闭包与 HTTP golden 复核。
- 不做：不打开 dana/realtest（永久禁区）；开发与验收只用临时库和**部署库的副本**，不碰线上原库。
- 前置：F7。
- 验收：任一测试库转换后 unmapped=0、active 可见集与 explain span 与源库逐项一致、幂等回放结果一致；核账报告可独立复跑得到相同结论。
- 停止条件：出现不可映射行类别且无规范定义，停工回规范。

## F9｜部署切换与旧库归档

- 范围：服务器单容器部署切换（停写 → 副本转换 → shadow → 原子切换配置 → 真实 DSH 回归）；旧库转只读归档（hash manifest、保留与 purge 策略明示）；SQLite 后端降为 import-only；运维文档（填 key 指引等）同步。
- 不做：不顺带改部署形态（仍单容器）、不动模型配置与 key 状态。
- 前置：F8；且需主人单独下令才执行本卡。
- 验收：切换后容器 healthy、3080 与默认预设正常、memoryd 冒烟（直写+召回）通过、真实会话闭环通过；回滚路径在切换窗口内实测可走（切回旧库只读响应）；归档 manifest 与保留口径落盘。
- 停止条件：切换中任一验收不过，立即走回滚，不许带病运行到「再观察」。

## 总停止规则

- 任一卡的停止条件触发，该线立即停工，先修规范再谈续工；不许用降级语义冒充等价。
- F1—F9 期间现网部署继续跑 SQLite 后端，功能迭代与本线互不阻塞；本线的任何中间产物不进生产。
