## 1. 一句话结论

**文件形态可以承接现有对外语义，但不能靠几份自由文本 Markdown 直接等价替换 SQLite；必须把版本、来源、状态、幂等、审计和作业状态也做成受约束的规范文件，并用可重建索引承接查询性能。**

这是一项“存储权威翻转”，不是导出格式调整。目标状态中：

- 规范文件是唯一事实源；
- SQLite/FTS/向量库都是可删除、可重建的投影；
- HTTP v1 的请求、响应和错误语义保持不变；
- DSH 适配器无需修改；
- schema 24 冻结为旧库最终格式，只用于导入、核账和只读归档。

## 3. 规范词汇

| 词 | 本规范中的严格含义 |
|---|---|
| 事实源 | 删除全部索引后，仅凭这些文件即可恢复对外可观察状态；冲突时文件胜出 |
| 规范文件 | 参与状态恢复的文件；包括人可读 Markdown 与机器操作日志，不包括 SQLite |
| 展示文件 | 供人查看或编辑的 Muse 形态 Markdown；是否为事实源由文件头 `authority` 声明 |
| 派生文件 | 可从规范源重建的实体页、bank、compact、alignment、页面等；不得反向覆盖源事实 |
| 索引 | FTS/CJK grams、向量、倒排、调度加速状态；允许删除后全量重建 |
| 语义等价 | 相同授权、输入和时间下，HTTP v1 的成功/失败、可见性、版本和关键返回字段一致 |
| 近似 | 用户效果相同，但排序、时间点、内部布局或诊断字段可能有可声明差异 |
| 有损 | 存在当前 schema 24 能表达、目标方案不能无损恢复的状态或行为 |

## 4. 事实分级规则

- **观察事实**：本机文件、源码或交接记录直接支持；必须附路径，源码事实优先于交接总结。
- **推断**：由多个观察事实推出，但材料没有直接声明；必须写出推断链。
- **设计决定**：F0 为目标系统规定的行为，不冒充 Muse 现状。
- **不可观察**：本机材料没有暴露 Muse 内部实现；不得补写为事实。

## 6. 拍板点

在排实施卡前，主人至少需要确认以下三点：

1. 是否接受“人可读 Markdown + 同树机器日志”共同构成文件事实源，而不是只允许自由文本 Markdown。

3. 是否接受切换期双写仅用于校验，**不允许** SQLite 与文件长期并列为双事实源。
