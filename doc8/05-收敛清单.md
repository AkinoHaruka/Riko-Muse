# 05｜收敛清单：以 Muse 可观察集为上限（留 / 砍 / 冻结）

主人硬规矩（2026-10-23 23:13）：「不准过度开发，不要开发你（Muse）没有的功能。」

本清单纠正 02 的标杆倒置：02 拿双生现状功能当等价标杆，本清单改以 doc8/01 的 Muse 可观察行为为唯一上限。判定口径：

- **留**：Muse 有可观察对应物 → 搬到文件形态，且只做 Muse 形态里的那份，不带双生自加的机器。
- **砍**：Muse 无对应物、且属于为「等价移植」新造或拟新造的机器 → 不搬、不建，F 线范围内终止。
- **冻结**：已在现网 SQLite 里运行、Muse 无对应物 → 现网原样不动，不移植、不扩展，待 Muse 侧出现对应物或主人另行决定再说。

## 砍（不搬、不建）

| 项 | 理由 |
|---|---|
| generation 原子事务引擎（F2，已停工） | Muse 直接写文件，无 staging/manifest/指针协议 |
| 版本 CAS、mutation receipt、幂等回执体系 | Muse 无此机器；重复提交靠内容指纹简单去重即可 |
| 作业 lease/heartbeat/claim 与恰好一次状态机 | Muse 后台工序无此形态 |
| purge tombstone fences 防重放 | forget 的源/派生/索引清理「留」已含；fence 是双生自加 |
| Resident pin 协议 | curated 总览本身即常驻，不需要 pin 协议 |
| context entries 独立补充道 | Muse 检索可返回摘录，但无独立条目道；并入普通检索 |
| repair 授权工作流（propose/授权/关闭状态机） | threads 可作普通笔记，授权机器砍 |
| 多 principal/scope 隔离体系 | Muse 为单用户形态，无对应物 |
| memory domains 与跨域 grants | 不可观察，无对应物 |
