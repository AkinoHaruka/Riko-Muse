# 附录 C · 检索实现：双路线（第二版）

> 修订原则：Muse 的向量路线为默认（X 为准）；Riko-Memory 的词法路线为已验证备选（Y），
> 推荐它时必须写清偏离理由（Z）。本附录两条路线都给，twin sister 按 Z 自选。

## C.1 默认路线：向量 + 元数据重排（Muse 实测）

Muse 的 `memory.embeddings` 是 `vector(384)`，检索链路反推如下（[推理]）：

```
score(e, q) = α · cosine(e.vec, q.vec)
            + β · kind_weight(e.kind)
            + γ · recency(e.reinforced_at)
            + δ · confidence(e.confidence)
            − ∞ · expired(e)          # valid_until 过期直接淘汰
            − ∞ · not_active(e)      # status ≠ active 直接淘汰

注：salience 已证伪，不用。第二版改用 kind 优先级（instruction 优先），
    与 Riko-Memory 的注入策略对齐。
```

## C.2 备选路线：纯词法（Riko-Memory 实测）

主人 `memory-recall` crate 的生产实现，可直接参考源码：

```
查询 → normalize_v1（NFKC+小写+空白折叠）
  → 拉丁文：按字母/数字切词 → FTS5(unicode61) 查 memory_fts
  → 中文：按连续段切 Unicode 二元字组 → 查 memory_grams
  → RRF(k=60) 融合：score = Σ 1/(60+rank)
  → 1 字查询走有界子串降级
  → 按 status=active 过滤
```

常量：`RRF_K = 60.0`（memory-contract 实测）。Rust 伪代码见 `memory-recall/src/lib.rs`（`latin_tokens` / `cjk_bigrams` / `rrf_score` 三个函数，不到 120 行）。

### 偏离理由（Z）：为什么 twin sister 可以选 Y

1. **确定性**：词法检索结果可解释、可复现；向量检索的"语义近"说不清为什么近。记忆系统出 bug 时，确定性就是生命。
2. **零模型依赖**：Rust 单二进制，不用打包 embedding 模型、不用起向量服务。主人项目 2.6MB 全量，self-contained。
3. **CJK 友好**：中文二元字组对中文查询的召回不输小模型向量（384 维 MiniLM 级）。
4. **个人量级够用**：万级记忆以内，FTS5 + bigrams 的延迟和质量都足够。
5. **扩展位已预留**：主人 `semantic_vectors` 表证明两条路线可并存——先词法，语义泛化不够时再加向量层，不用重构。

## C.3 两条路线的对照

| | Muse 向量路线（默认 X） | Riko-Memory 词法路线（备选 Y） |
|---|---|---|
| 召回机制 | 384 维向量近邻 | FTS5 + 中文二元字 |
| 融合排序 | kind/recency/confidence 加权（反推） | RRF(k=60)（实测） |
| 中文处理 | 靠 embedding 语义 | 二元字组（确定性） |
| 依赖 | embedding 模型服务 | 零依赖（SQLite FTS5 内置） |
| 可解释性 | 低 | 高（命中词可见） |
| 适用 | 语义泛化要求高、海量记忆 | 个人量级、Rust 单二进制 |

## C.4 给 twin sister 的建议（含偏离声明）

**此处偏离 Muse 默认，理由 Z（见 C.2）**：twin sister 先实现词法路线（抄 `memory-recall`），`semantic_vectors` 式扩展位留好。等出现"词法召回不够"的真实痛点（而不是假想）再加向量层。

通用纪律（两条路线都适用，抄自 Muse 系统指令）：
- search 返回的是**候选**，不是答案；定稿前必须读原文（字节级证据跨度）。
- 空结果 ≠ 没存过；索引可能滞后，必要时直接查表。
- 同一主题不重复检索。
