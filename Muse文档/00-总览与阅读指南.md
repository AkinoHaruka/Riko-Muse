## 一句话架构

这是一个以 **claim（声明）为原子单位**、以**文件为载体**、以**向量检索为入口**、以**多后台任务为进化引擎**的个人记忆系统。

```
┌─────────────────────────────────┐
│ 对话（conversations） │
└────────┬────────────┬───────────┘
│写入 │读取
┌──────────────▼──┐ ┌───▼──────────────────┐
│ 写入管线 (03) │ │ 读取管线 (04) │
│ in-session即时 │ │ 上下文注入 │
│ 后台consolidation│ │ memory_search/get/ │
│ verified抽取 │ │ explain │
└────────┬─────────┘ └───▲──────────────────┘
│ │ 384维向量检索
┌────────▼────────────────────┴───┐
│ 存储层 (01 + 02) │
│ 文件：MEMORY.md / 日期日志 / │
│ bank/ / people / dreams │
│ 数据库：memory.claims / entries / │
│ embeddings (vector 384) │
└────────┬────────────────────────┘
│ 维护/进化/遗忘
┌────────▼─────────┐ ┌──────────────┐
│ 后台任务 (05) │ │ 遗忘协议 (06) │
│ dreaming/关系/ │ │ forget skill │
│ 学习/技能复审 │ │ supersede机制 │
└──────────────────┘ └──────────────┘
```

## 核心设计决策（提炼）

1. **Claim 是原子，不是句子也不是文档。** 每条记忆是一个可独立寻址、带置信度、带溯源、带生命周期的 claim。文件只是它的渲染层，数据库才是它的户籍。
2. **文件即数据库，数据库即索引。** Markdown 文件是人类可读的"真相源"（source of truth），PostgreSQL 存 claim 行 + 384 维向量做检索。两套互相引用（`src: memory/2026-10-05.md:26` / `MEMORY.md#L21`）。
3. **写时分流，读时聚合。** 写入分"对话中即时记"和"后台小时级归档"两条路；读取时语义检索把碎片捞回上下文。写和读解耦，互不阻塞。
4. **新声明覆盖旧声明，而不是删除。** 用 `supersedes_claim_id` 链维护版本史，旧的不删，状态置为非 active。这是"记忆可审计"的关键。
5. **遗忘是全系统清理，不是删一行字。** forget 协议要清记忆、衍生品、定时任务、未来可再生源，最后由 runtime 收回 claim 并刷新索引。删得不干净不如不删。
6. **后台任务是"人格"的来源。** dreaming（ nightly 复盘）、relationships（关系维护）、studying（目标简报）这些定时任务，才是让助手"越用越像本人专属"的部分，而不是某次聪明的回答。

## 先说三个最重要的发现（第二版已校准）

1. **检索确实用向量。** `memory.embeddings.embedding` 是 `vector(384)` 类型，每个记忆 chunk 一条 384 维向量。[实测：schema]
2. **Claim 有完整生命周期字段。** `status`（默认 active）、`confidence`（浮点）、`first_seen` / `reinforced_at`、`valid_until`（可过期）、`supersedes_claim_id`（版本链）。[实测：schema]
3. **Riko-Memory 证实了核心机制，修正了两个想当然。** claim 确实是内容哈希（SHA256(kind + NUL + normalize_v1(claim))）[实测(Riko-Memory)]；但主人项目没有 salience 字段、召回走纯词法（FTS5+中文二元字+RRF）而非向量——这两条是第二版最重要的纠正。
